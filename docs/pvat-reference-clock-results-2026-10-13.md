# 控制器跟踪核对与 PVAT 速度参考寿命修复

日期：2026-10-13，Asia/Shanghai。基线：`526b968895d1979529d2c8014449433e8d4daf7a`。本轮只用已冻结证据做离线分析、开发和替身测试，没有连接机械臂或重新抓包。

## 横向偏移出现在哪里

在抓包的首个 PVAT 请求至停止请求之间，146 件运动学回复同时包含控制器目标 TCP 和实际 TCP。

| 本机捕获到的遥测 | 实际 X 位移 | 控制器目标 X 位移 |
| --- | ---: | ---: |
| 首个实际值超出 0.5 mm 的回复 | +0.543 mm | +0.026 mm |
| 首个目标值超出 0.5 mm 的回复 | +0.893 mm | +0.509 mm |
| 此期间的最大绝对值 | 1.542 mm | 1.456 mm |

两列分别以各自首个运动前遥测值为基线，不能直接相减当作跟踪误差。用同一回复中的实际与目标绝对坐标计算，笛卡尔误差范数中位值约 0.148 mm、最大约 0.571 mm。

最初明显偏移时，控制器报告目标仍靠近目标轴；后来报告目标也偏离。因此发送轴错误不能解释这些阶段，不能将全程问题仅归于实际跟踪误差。上述是主机收到的遥测顺序；没有控制器内部采样时间，不能由相邻回复直接确立反馈导致后续偏移的因果关系。

本轮没有将未校准的视觉 FK 用作真实运动模型，也没有修改关节零位、TCP、控制器参数或速度上限。

## 速度参考的时间边界

此前使用原 monotonic 起点间隔判断前一 PVAT 速度是否仍处于 80 ms 窗口。本次 5 个仍采用前一指令速度的点，记录的原间隔为 78/79 ms，但相邻外层 SDK await 起点的 QPC 间隔约为 80.058、80.387、80.275、82.185、87.412 ms。

外层 await 起点不是精确原生入口或控制器执行起点；这些差异是需要保留的疑点，不能声称已确定 5 次实物轨迹过期。纯替身测试独立复现了软件缺口：

- 原时钟仍显示 78 ms、独立时钟已超过 80 ms时，旧判定仍保留前一速度。
- 候选生成时参考有效，在候选返回或 `wait_for` 切入 SDK 任务时过期，旧实现仍发送原点。

## 修复范围

仅修改 `RealLebaiAdapter` 的本地 PVAT 参考寿命和实际 SDK 入口点生成。

1. 新增独立 `pvat_clock`，默认 `time.perf_counter_ns`。只有原时钟和独立时钟各自的成对间隔都小于原 horizon，才使用前一指令速度；不跨时钟相减。独立时钟缺失、异常或回退时使用观测速度。
2. SDK 任务入口再检查一次。若候选的前一速度参考过期，用同一已准入快照、IK 解和原限值重建点；没有额外读取、IK 调用、SDK 运动或重试。
3. 重建后再次检查运动权限及 pump 代次。撤销时不进入 SDK，也不推进历史。
4. lifecycle 与 `pvat_sent` 更新为实际发送点，并保存参考时钟检查记录；catch-up 保留原已接受目标。只有 SDK 正常返回且请求仍有效，才推进历史；reset 同时清理两套参考起点。

这是专用于本地 PVAT 参考寿命的时钟；没有复用声明为纯诊断用途的 clock-anchor helper。100 ms VR TTL、200 ms 停止期限、原稳定验证及停止失败锁存使用原有路径。原 PVAT 数学、horizon、目标、速度和加速度限值均保持。

## 定向回归与失败记录

新增 24 项用例：两个时钟分别有效/过期/回退、未知或异常时钟、历史清理、候选与 SDK 调度边界、普通目标和 catch-up、入口时钟未知、重建时运动权限和 pump 代次撤销。

- 首轮 18 项出现 14 个预期失败、4 通过，包含两项实际发送了旧点的替身复现。
- 首版修改后为 16 通过、2 失败：新用例将连接阶段的读取也计入动作阶段计数。改为在动作前清空替身调用记录，验证重建没有新增读取。
- 初次扩展为 22 通过、2 失败：用例误用了不存在的权限绑定方法，导致替身清理未走完并出现 pending task 警告。随后又出现 22 通过、2 失败：清理试图重新绑定权限，被原门禁拒绝。改为恢复原回调读取的布尔值并正常 disconnect，没有放宽生产权限规则。
- 最终 10 个受影响文件 **242 通过，12.22 秒**；另 4 个停止事务、时间边界、停止证据和优先级文件 **45 通过，2.26 秒**。共 287 项，JUnit 无失败、错误或跳过，最终没有 pending task 警告。

新增 24 项包含在上述统计中；中间 123 项核心回归与最终结果重叠，不叠加计数。没有后端全集、前端构建、真实 SDK 调用或新现场测试。
