# 正解只读核对入口 — 2026-10-13

## 本轮交付

新增 `scripts/real_robot_readonly_kinematics.py` 和独立采集组件 `app.commissioning.readonly_kinematics`。入口默认仅打印离线预览，不连接 SDK、不创建结果目录。真实执行须另有当前现场授权；确认文字本身不能代替人类授权。

本轮仅用替身完成开发和测试，没有连接机械臂，没有执行运动、夹爪、停止、恢复、复位或抓包，没有改变旧现场配置。上次暂停后的 PAUSED 状态可以直接只读核对，不要求用户先恢复或重新启动。

## 固定范围和单次准入

- 一次 SDK 连接；连接失败也消耗已预留的输出目录，不能在同一目录重试。
- 配置必须是 LEBAI readonly、字面量私网 IPv4；结果仅能保存在仓库 `.tmp` 下独立目录。
- 执行时核对完整预览的 SHA-256、配置及相关源码/原生 SDK 文件哈希、UTC 截止时间和精确范围。启动截止须在当前时间后 10 分钟以内；之后每次查询前后及异步子任务实际入口都重查输入与授权。哈希核对完成后再次检查 UTC 期限，不能沿用核对开始时的时间。
- 连接前两次核对本机已有机器人 RPC 连接数为零，只读取本机数字连接表。读取连接表、来源核对、SDK 导入及 init 之后重新核对授权与连接的绝对期限，最后在 native connect 前再检查。原生 SDK 仅在准入和来源核对后按需导入；不允许已提前导入或来自其它目录的 SDK。
- 固定方法：is_connected、get_robot_state、get_estop_reason、get_running_motion、get_motion_state、get_kin_data、get_tcp、kinematics_inverse、kinematics_forward。没有通用 RPC 参数或写操作入口。
- 最多 24 次调用（含连接），其中 IK 一次、FK 四次。连接等待 5 秒、单次读等待 1 秒、从连接前开始总预算 15 秒。读超时预算用于取得诊断证据，没有修改生产 100 ms VR 有效期。

## 读取、计算与证据

前后各读取一组反馈。状态只能为原始 IDLE 或 PAUSED；急停原因必须明确为零，各关节反馈速度必须全部明确为零。存在保留的 motion ID 时额外读取其状态，必须明确 FINISHED；不从零速度或 PAUSED 推断结束。关节速度、加速度、TCP 等数据必须有限且完整；TCP 设置必须符合原配置。这只收紧本次只读范围，没有改变生产停止验证的原速度阈值。

只在内存中构造保持姿态的 **+Z 0.2 mm** 目标，以当前反馈关节作为 IK 参考，检查原关节步长、奇异位姿及关节边界，使用上一轮完整零末端 PVA 构造器生成一个参考窗口。窗口不发送给机器人。

随后固定核对反馈关节、完整 IK 目标、参考中点、窗口终点四处 FK。检查反馈位置/姿态一致性（100 µm / 0.1°）、方向、横向偏差和正进展。结束后再次核对反馈没有超过限定的变化、状态没有切换，TCP 设置没有改变。**两组读不是连续静止或停止证明，四点 FK 不是完整路径或控制器插值证明。**

记录 IK、构造、四次 FK 和只读准入检查的总耗时，并以严格 `<100 ms` 标记 `chain_within_vr_lease`。这个耗时包含只读入口的哈希复查开销，没有包含生产全部状态读取、排队和分派，不能当作生产实时周期上限。超过 100 ms 时仍可保存成功的只读核对结果，但不会延长生产 TTL，也不会授权运动。

原厂说明 FK 将关节位姿转换为笛卡尔位姿，IK 结果依赖当前 TCP 与关节参考；本次据此选用反馈关节参考和 TCP 设置核对。原生安装版本的实际返回格式及真机一致性尚待只读证据。[乐白位置和姿态接口](https://help.lebai.ltd/sdk/posture.html)

## 超时与退出

读调用由单个实例持有任务。超时请求本地取消后结束查询链；没有再次连接、没有后续查询，也不把本地取消解释为远端取消。迟到结果不能改写已返回报告。报告持续标记未知远端结果和原生连接释放未验证。

CLI 用单独事件循环取得报告，退出时不等待忽略取消的 SDK 读。Ctrl+C 取消本地采集并先保存不完整报告，再退出。退出不构造 control adapter，也没有隐式 stop_move、resume、stop_sys、Home 或设置写入。

报告区分应用层连接工厂入口/等待时间与原生 SDK init、connect 的实际入口标记，不能把连接表核对和模块加载时间称为原生 connect 耗时。异步期限不能抢占同步 SDK 导入、init 或阻塞的 native 调用；本次替身验证不建立这些同步工作的实际耗时上限，也不证明原生连接已释放。
