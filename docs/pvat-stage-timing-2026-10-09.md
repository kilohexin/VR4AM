表中约 15～16 ms 的量化来自旧控制时钟。**快照读取已含快照锁等待，不能重复相加；各阶段中位数也不能相加作为单次精确耗时或占比。** 旧数据不会因增加诊断字段而获得更高精度。

TCP 配置、急停、机器人状态和关节边界参与运动安全检查；没有直接删除读取、并发发送 RPC 或复用陈旧快照。本轮也没有调整 PVAT 时域、速度、频率或共享锁策略。

## 新增代码记录

只在 `lebai_adapter.py` 添加独立 `time.perf_counter_ns` 取样：

- 快照的 requested、acquired、completed 边界，随 robot_kinematics 输出。
- PVAT handler 开始、快照返回、命令锁请求及获取、候选计算完成、SDK await 开始及 finally 完成。
- 成功发送与 SDK lifecycle 都有诊断数据，后者覆盖返回、超时、取消和错误；两份事件独立复制字典，回调修改一份不会污染另一份。

快照 completed 是锁内读取结束后的本机取样；PVAT snapshot_finished 是整个读取函数返回后的取样，包含转换及日志等待。候选计算区间包含 IK 等待和本地规划，不等于纯 IK RPC。SDK await 包含本机 asyncio 包装及调度，不是控制器执行时间。

计时不可用时保留 `None`。所有记录标记 `alignment_verified=false`；没有跨时钟减法、网络捕获点对齐或控制器时序保证。没有新增 SDK 调用、await、锁操作或日志任务；原控制时钟、新鲜度和 200 ms 停止规则保持不变。
