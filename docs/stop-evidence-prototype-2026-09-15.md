# 独立静止证据窗口：离线原型

本轮范围：仅 `backend/tests/prototypes/`。不导入SDK、不连接机器人、不注册到生产适配器，也不决定是否发送/延后 stop_sys。

原型把连续样本的静止证据与RPC结果分开。输入为采样单调时间、关节位置/速度、TCP、控制盒状态和急停/硬件故障指示。这里的 fault 输入不是应用层 `stop_unverified` 锁存：应用层未知结果须独立保留，不能用它掩盖物理读数，也不能用后来静止掩盖原故障。

验证要求：

- 连续位置相对窗口首样本稳定，速度在界内，状态在允许集合，才确认窗口。
- 位置变化、速度超限、错误状态、非有限数值撤销确认。
- 采样缺口过大使原窗口失效；重复或倒序时间不能填满窗口。
- 无RPC返回也可评价物理反馈；任何结果都不授予运动权限。

样例窗口300ms、最大采样缺口250ms、关节漂移0.001rad、TCP漂移0.0005m、关节速度0.02rad/s。部分值取现有生产判据；250ms是回放样例参数，所有组合均不是新增认证安全阈值。生产策略未修改。

## 验证

命令（仓库根目录）：

```text
python -m pytest -c backend/pyproject.toml backend/tests/prototypes/test_stop_evidence_window.py backend/tests/prototypes/test_stop_episode_model.py backend/tests/prototypes/test_stop_request_owner.py -q --tb=short
```

结果：34 passed，退出码0；其中9项为新增证据窗口测试。没有重复跑真机或要求实验室重新验收。

使用第20轮原始会话285个观察样本回放（以首次stop_move为t=0），急停字段作为硬件异常输入，应用故障单列保留：首次窗口确认位于样本14、t=3156ms，此时原记录的latched_fault仍为stop_unverified；motion_allowed始终false。

## 结论与下一步边界

此原型验证“后续物理反馈满足静止条件”和“此次停止合格/可恢复运动”是不同维度，不证明控制盒已安全停止，更不解释22mm位移原因。STOPPING阶段即使读到qd=0也不会被本模型直接算作静止。

现有原始数据的首次观察在t=453ms，缺少首次200ms内的独立连续样本，所以不能反推当时不需要系统停止升级。该缺口不通过猜测补齐。

下一步只在离线适配器集成中验证：停止请求未返回时可否连续采样、读写是否互相阻塞、超时/取消后记录能否完整收尾。先不改变200ms首轮升级行为。若后续提出改变升级策略，需要明确新的等待风险和异常处置，不能把原型通过当作真机放行。
