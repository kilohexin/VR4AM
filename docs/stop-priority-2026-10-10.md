# 停止请求的 SDK 锁优先调度

2026-10-10，Asia/Shanghai。本轮只做本机离线开发，暂不推送。

## 目标与设计

目的：减少停止请求被尚未执行的普通读取排队延后的时间。既有假 SDK 复现中，1/3 个普通读取增加 16/48 ms；一个读取正在执行且另有三个读取排队时，停止等待 56 ms，其中当前读取仅剩 8 ms。

SDK 锁权限继续互斥。当前持锁者以及已经交付的锁权限不被抢占或取消；停止 RPC 优先于还在等待的普通任务。同优先级保持 FIFO，普通任务不丢弃。普通运动/读取之间保持既有顺序，不加快运动优先级，避免绕过已排队故障观测。停止验证读取仍按普通队列执行。

实现独立内部 `SdkLock`，提供既有 acquire/release/locked 和异步上下文语义，以及仅用于停止 RPC 的 `stop_priority()`。交付时立即保留锁，防止新请求插队；若已交付的等待者在恢复前被取消，释放该权限并交给下一个等待者。排队取消只能移除自身，不能释放当前调用的锁。没有接入 Web/配置开关或新真机入口。

200 ms 从停止 RPC 创建开始计时的规则、`stop_unverified`、不自动 `stop_sys`、不重试与停止稳定验证保持。当前 SDK 调用自身及约 613 ms 停止回复不会因本轮调度变快；不能宣称物理停止或持续 VR 已验收。

## 实际结果与验证界限

红回归后 4 项初始用例通过；第一批 6 文件 49 项通过；扩大至 18 个受影响文件 **329 passed，9.56 秒**。覆盖新的 12 个锁用例和 7 个 adapter 停止优先用例，同时保持既有发送快照、夹爪撤销、PVAT 生命周期和观察取消验证。没有后端全集或真机测试。

原来验证 FIFO 停止排队的三个测试文件改为新停止优先行为的预期；其完整读取次数、200 ms 和仅 stop_move 断言保留。两个注入锁继承新的实际 SdkLock 接口，原注入时序与读取取消断言保持。普通 snapshot/IK 排队断言未放宽。

确定性的假 SDK 比较：排队 1/3 次普通读取增加的 16/48 ms 在本轮变为 0；已有一个读取执行且另外三个排队时，停止等待从 56 ms 变为当前读取剩余的 8 ms。读取随后完整完成，没有丢弃；这些是控制时钟注入的结果，并非真实线程/网络/控制器耗时，也不保证下一次真机减少相同数值。

独立静态审查未发现本轮 P0–P2，审查没有运行测试、SDK、网络或现场动作。审查明确两个保留界限：

- 当前持锁者/已交付权限不能抢占，因此停止取得锁没有新增总等待上界。200 ms 仍是停止 RPC 创建后的验证门限。
- 既有 StopRpc.wait() 对底层 await 使用 shield。超时/取消后调用者可退出锁，而底层停止调用可能仍未返回；本轮没有改变这一语义。新锁只能保证锁权限互斥，不能宣称所有尚未完成的底层 SDK 调用从不重叠。停止诊断 sampler 也沿用既有独立读取策略。

约 613 ms 停止回复、连续真机 VR 控制与真实 Trigger 抓取仍未验收。本轮不产生新的连接/动作/复位授权，不改变现场配置；源码变化使此前现场入口绑定不能复用。
