# 单窗口自然收尾候选 — 2026-10-13

## 本轮交付与边界

实现独立 `backend/app/robots/lebai_finite_pvat.py` 构造器。每个返回的点对应一个完整窗口，末端速度和加速度均为零，无需继续发送计划尾段。正常 VR adapter 尚未选择该候选；本轮没有 SDK 连接、机器人动作、网页操作、抓包或配置修改。

这里保证的是**声明的五次插值参考轨迹**的数学性质。尚未证实控制器采用相同插值、报告 PVA 与实际运动一致、笛卡尔路径正确或物理停止达标。原停止期限、稳定验证与故障锁存均保留。

## 构造方法

1. 使用给定实际位置、速度和加速度作为起点；不把速度或加速度截断为零，不借用旧指令速度替代反馈。
2. 终点为 `actual_q + fraction * (IK_q - actual_q)`，六关节共享一个 `fraction∈[0,1]`，终点速度/加速度为零。起点非零 PVA 时，整个关节曲线不一定共线；更不能据此认定笛卡尔直线。
3. 把五次位置、多项式一阶/二阶导数转为 Bernstein 控制点，在 16 个虚拟子区间上取凸包界，限制整个窗口的关节位置、速度与加速度。虚拟细分只用于计算界，仍返回一个 PVAT 点。
4. 所有控制点对 fraction 都是仿射函数。直接求约束区间的交集并取最大可行 fraction，不要求 fraction=0 先可行；因此非零速度情况下允许正的可行区间下界。
5. 固定调用者给定的 10–80 ms 时长，不自行延长。目标/实际位置越界、跟踪误差超限、初始 PVA 超限、可行区间为空或数值范围失效就拒绝。拒绝不等于停止，未来调用者仍须执行原停止处理。
6. 对实际输出的浮点终点重新计算界。数值比较容差为 1e-12，独立多项式极值检查也保留浮点误差容差；这不是机械误差允许值。

细分矩阵在模块导入时预计算，分派时只做矩阵运算；矩阵权重非负、每行和为 1、数组不可写。未加入新依赖，复用已使用的 NumPy。构造器不包含任务、SDK 方法、网络访问或调度器。

## 横向偏移核对

对每个 PVAT 输入，按请求/开始/完成时间及 actual_q 关联同一快照；62 点全部找到一致的快照。

- 原端点位移相对完整 IK 关节差的夹角：13 点中 3 个超过 5°（最大 6.655°），49 点中 5 个超过 5°（最大 14.077°）。
- 新候选只验证了共享比例的**关节端点**方向；独立计算残差夹角不超过约 0.00000171°，属于浮点量级。
- 旧 49 点在第一次夹角超过 5°前，对应快照横向偏移已达到 **0.618166 mm**；还有多份小夹角快照表现为负 Z 进展。这说明上述关节端点方向问题不足以单独解释全部横向漂移。
- 本轮没有使用网页视觉 FK 宣称真机方向正确。`robotModel.ts` 对真机肩关节另加 π/2 的显示偏置，并明确只作用于显示；仿真 FK/IK 保留自己的关节约定。视觉工具配置也不能自动代替现场 TCP 设置。

原厂说明 IK 依赖当前 TCP 设置和参考关节，提供 `kinematics_forward`；下一步需要核对控制器正解与已有反馈，再评估有限窗口笛卡尔路径。`measure_manipulation` 标注从 3.1.36 起提供，当前 RC 3.1.34，不能作为现成接口使用。[原厂位置和姿态接口](https://help.lebai.ltd/sdk/posture.html)
