# 虚拟 LM3 非真机验收流程

本文档说明如何在不连接、不启动、不移动真实乐白 LM3 的前提下，对
VR4Arm 的遥操作软件链路执行可重复验收。该流程用于确认坐标映射、虚拟
机械臂跟随、软约束处理、停止与 Home 状态机、前端抓取交互以及构建产物，
不能替代实验室真机验收。

## 运行条件

- 在仓库根目录执行命令。
- Python 依赖和 `web` 目录的 npm 依赖已经安装。
- 默认配置保持为模拟器后端。
- 不设置 `VR4ARM_REAL_ROBOT_CONFIRM`，不将真实机器人配置切换到
  `control` 模式。

## 执行软件验收

仅使用仓库中的模拟器和测试替身：

```powershell
python scripts/accept_virtual_lm3.py
```

如实验室已经填写本地真机配置，可额外比较现场配置与虚拟模型画像：

```powershell
python scripts/accept_virtual_lm3.py --real-config config/real-robot.local.yaml
```

第二条命令只读取并比较 TCP、Home、软关节限位和夹爪幅值方向等配置，
仍不会连接 Lebai SDK，也不会向机械臂发送运动命令。

脚本依次运行：

1. 后端完整 pytest；
2. 前端完整 Vitest；
3. Vite 生产构建；
4. 确定性六轴映射、伺服跟随和软约束场景；
5. 10 分钟虚拟时间的故障与停止机制 soak；
6. Git、模型、GLB 和可选现场配置的溯源记录。

任一必要检查失败时，进程以非零状态码退出。最新报告以原子写入方式保存到：

```text
artifacts/acceptance/virtual-lm3-latest.json
```

该目录是生成物并被 Git 忽略。报告中的 `passed: true` 只表示非真机软件门禁
通过；`hardware_verified: false` 始终是预期值。

## 报告判读

重点字段如下：

- `git`：执行时的提交、工作区是否干净及改动路径；
- `model`：运动学配置和 LM3 GLB 文件的 SHA-256；
- `profile`：虚拟画像及可选现场配置差异；
- `commands`：完整后端、前端和构建命令的退出码、计数与输出末尾；
- `scenarios`：坐标映射、跟随和软约束场景结果；
- `soak`：控制周期、虚拟周期、注入事件、停止验证、NaN 和错误计数；
- `hardware_pending`：必须在实验室完成的六类真机检查。

真机待验项目为：

1. `sdk_connection`：SDK、网络连接及只读状态获取；
2. `tcp_home_joint_limits`：真实 TCP、Home 和关节限位；
3. `gripper_direction_force`：夹爪开合方向、幅值和实际夹持力；
4. `pvat_tracking_latency`：PVAT 跟随、延迟、抖动和丢包表现；
5. `stop_distance_estop`：停止距离、失联停止和急停；
6. `physical_collision_load`：物理碰撞、负载、摩擦及线缆影响。

## 验收可信边界

虚拟机械臂使用与真机一致的 LM3/LMG-90 外观与配置，可支持：

- 几何尺寸、可视化和运动学链路回归；
- 关节限位与近似自碰撞检查；
- VR 手柄到 TCP 的位置、姿态映射；
- 控制状态机、消息接口、故障恢复和数据接口验证；
- 确定性抓取、释放、堆叠流程验证。

其中，确定性抓取是逻辑层和数据接口测试，并非刚体接触仿真。GLB 和软件
模型一致也不能证明真实环境中的无碰撞、摩擦、夹持力、负载能力、停止距离
或急停效果。

因此，软件门禁通过后只允许进入已有的 `LEBAI_READONLY` 现场预检阶段：
先读取状态并核对机器人型号、TCP、Home、关节限位和夹爪配置。只有这些信息
经人工确认，并完成独立的低速、空载、安全区域测试后，才能另行批准真机
运动控制。

## 推荐归档

每次阶段冻结时保留：

- 当前本地 Git 提交号；
- `virtual-lm3-latest.json`；
- 使用的本地现场配置版本或其哈希（不要提交密码、令牌等敏感信息）；
- 后续真机验收日志。

这样可将“软件已验证”和“真机已验证”作为两个独立结论追踪，避免误把
仿真通过当作硬件安全结论。
