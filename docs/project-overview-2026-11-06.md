# VR4Arm当前项目总览与接续说明

更新：2026年11月6日。开发分支`codex/vr-toggle-follow`，整理前最新实现提交`b774918`。本文是当前状态快照；旧版本的事实和失败见时间线，不能把历史参数自动当作当前入口参数。

## 1. 最新目标及用户选择

实现网页及VR手柄控制机械臂的XYZ移动、俯仰、自转和渐进夹爪，最终用于轻物体抓取搬运。当前**暂不拍视频**，先完成稳定可用的控制和Docker真人体验，再独立验收真机。

用户已明确允许不完整复刻手部运动全过程，只要目标终点可保持。因此当前优先采用“最新端点＋原厂控制器规划”，不再以完成低延迟连续PVAT为唯一交付路径。

历史抓取设想：抓取部位约20mm宽、物体较轻；前移约20cm、抓取、抬升30cm、向右搬50cm、下降30cm、同高度放下。它是保留的需求尺寸，不是已通过的路径或工作区授权。相对基座方向、实际物体布置、载荷和整条路径仍需现场核对。

## 3. 三条控制路线如何区分

| 路线 | 工作方式 | 当前用途 |
| --- | --- | --- |
| 有限位置movej/movel | 控制器执行有限目标；有些历史模式每步等到位，有些使用交融续接 | 网页/旧Docker功能与历史定位诊断；不等同于新终点跟随 |
| 连续PVAT | 后端生成P/V/A参考和收尾，控制器执行；需要稳定发送周期 | 研究和诊断保留，实时性能及真实整链仍未通过 |
| 最新端点towardj | 后端提供目标，控制器根据最新目标组织运动，不必完成旧端点 | 当前优先候选；尚未注册为完整产品体验模式 |

原厂towardj是关节跟随运动，不保证TCP直线；减少后端插值不等于免除工具、工作区、关节边界和实际路径反馈检查。[原厂运动接口](https://help.lebai.ltd/sdk/motion.html)

正常松手语义为停止接收新输入，最多提交仍新鲜的最后待发端点，完成有限目标后保持。它允许一定剩余运动，不能标作立即停止。断连/故障禁止后续发送并保留异常状态，未知命令不能自动重发；夹爪未知时不自动松开。

## 4. 为什么旧位姿模式继续封锁

11月4日旧模式转腕时，目标高度基本不变而Docker报告TCP曾下降约328mm。各关节独立限速/滤波没有保证组合后的末端路径。旧入口现返回`pose_follow_quarantined_cartesian_path`，不应去掉封锁继续体验。

方向基变换和新笛卡尔参考已有离线修复，部分小范围官方Docker反转通过；非零真实工具、完整实时输入、长时与产品链尚未闭环。新towardj是独立候选，不自动替代旧入口或解除其封锁。[问题及修复历史](vr-pose-pitch-path-2026-11-04.md)

## 5. 延迟与停止的当前结论

- 新版VR到真机的端到端延迟尚未测得，不能承诺某个毫秒值。
- 一轮主机规划任务耗时中位49.39ms、P95约69.35ms、最大95.04ms；它包括线程任务等待/调度，只是链路的一部分。
- PVAT首包返回60ms、后续尝试间隔119ms，以及休眠调度偏差均有实际Docker记录；两轮有限候选仍失败。
- 约609/631ms是部分异常stop_move调用的返回耗时，不是正常跟随延迟、实际机械刹停时间或可靠上界。
- 新终点诊断的towardj回执59/10/10ms，也不能当作真人VR到实际机械运动延迟。

当前减少计算的方式是将端点运动规划交给控制器，而不是跳过末端和实体限制。停止回执与实际停止核验分开；历史stop_unverified保留，不恢复自动stop_sys升级。[详细难点说明](project-difficulties-and-latency-2026-11-05.md)

## 6. 环境、端口和启动入口

依赖安装与无运动验证见[根README](../README.md)。前端Three.js/TypeScript/WebXR/Vite，后端Python/FastAPI/asyncio/NumPy/SciPy；可选Numba仅用于研究中的编译运动学。原厂仿真需要本地Docker Desktop及已核对镜像。

| 端口/入口 | 含义 | 当前注意事项 |
| --- | --- | --- |
| 8773 | 历史官方Docker网页后端 | 不是新towardj入口；服务是否运行要另查 |
| 8443 | 历史网页/头显HTTPS代理，代理8773 | 命令通常覆盖Vite默认5173；不能混作实体入口 |
| 8774 / 8444 | 独立位姿试验后端/HTTPS代理 | 旧位姿体验已封锁，不恢复旧服务绕过 |
| 8769 | 历史真实网页入口 | 禁止当作默认仿真启动；新实体连接需具体批准 |
| 3030 / 3031 | 原厂SDK仿真/真实端口 | Docker入口必须保持模拟标记及地址隔离 |
| 3010 / 3011 | 原厂Lua仿真/真实环境 | 不允许把诊断脚本端口替换为真机直接运行 |

`scripts/check_docker_endpoint_follow.py`只允许固定镜像、network=none、无端口映射/挂载/设备且非privileged的独立官方Docker，默认预览。`--run`会进行虚拟准备及三次towardj，不是只读。它没有真实地址选项，也没有头显体验URL。

截至最近诊断收尾，专用Docker实例均已停止。本文整理和Git上传不启动服务或连接机器人。

## 8. 后续开发顺序

1. 将towardj候选接到产品VR输入格式，保留原时间戳、代次和零位；做目标节流、静止去重及最后端点保持。
2. 加入XYZ、俯仰、自转和真实工具几何，检查切换目标时的路径与工作区；机械臂和夹爪先串行，分别隔离未知。
3. 通过产品WebSocket/HTTPS的合成输入，覆盖连续变化、松手、过期、断连、重新进入及边界退回，再开放Docker真人体验。
4. 记录实际动作响应、端点误差、松手残余和使用体验，依据证据调整倍率和速度。
5. 明确实体入口、动作范围和现场条件后，独立真机空载、夹爪及轻物体搬放验收。Docker无故障不免除这一步。

当前没有需要用户重新审阅的软件短设计；已有自主Docker开发授权继续有效。新增真实连接、运动或夹爪须在入口和完整范围准备好后单独批准。
