# VR4Arm 无真机离线实验演练设计

- **日期：** 2026-08-02
- **状态：** 已确认，待实施
- **适用运行时：** `LEBAI_FAKE` / `DIGITAL_TWIN`
- **真机验证状态：** `hardware_verified=false`

## 1. 背景与当前基线

VR4Arm 已具备乐白 LM3 的真机软件控制主链路：Meta Quest 3/网页输入经
WebSocket 进入 `RobotControl`，再通过 `RealLebaiAdapter`、IK 和 PVAT
驱动乐白 SDK 形状的客户端；系统同时具备 LMG-90 夹爪、Home、停止、失联
保护、故障锁存和诊断记录。

当前无法接触 LM3 和 Quest 3，因此本阶段不新增任何真机授权，也不宣称完成
真实方向、延迟、停止距离或抓取验证。开发重点是让 PC 独立完成一次可观察、
可重复、走真机同构软件路径的离线实验演练，并修复现有离线门禁中与机器负载
相关的 soak 墙钟时间抖动。

## 2. 目标

本阶段交付以下能力：

1. 一条命令启动 Fake Lebai 后端与 PC 前端；
2. PC 页面作为唯一控制端和唯一观察界面；
3. 一键执行确定性的 Home、零位锁定、六向平移、三轴双向旋转、夹爪、方块
   抓放和安全停止演练；
4. 所有运动继续经过现有 Arm、Grip、映射、IK、PVAT、停止及故障锁存路径；
5. 浏览器实时展示步骤、目标与实际状态、误差、诊断和根因；
6. 生成带 Git/config/model 来源信息的 JSON 与 Markdown 报告；
7. 稳定通过后端、前端、构建、Virtual、Fake Lebai 和新增离线演练门禁；
8. 所有报告永久保留 `hardware_verified=false`，不能提升真机权限。

## 3. 非目标

- 不连接、导入或调用真实乐白 SDK；
- 不自动写入真机 IP、TCP、Home、软限位或夹爪方向；
- 不替代现场只读预检和逐轴低速 commissioning；
- 不增加第二观察端或多控制端模式；
- 不开发轨迹编辑器、倍速器、用户脚本语言或数据采集；
- 不以提高时间阈值、删除测试或跳过测试的方式制造绿色门禁；
- 不使用网页故障注入接口暴露任意底层写命令。

## 4. 总体架构

离线演练保持单连接、单控制权：

```text
PC 网页（唯一 WebSocket 所有者）
  -> OfflineRehearsalController
  -> 现有 arm/home/reset/stop 消息与 VRFrame
  -> RobotControl
  -> RealLebaiAdapter
  -> FakeLebaiClient / Digital Twin
  -> robot_state + diagnostics
  -> 三维场景、步骤面板、结果汇总
```

`OfflineRehearsalController` 是浏览器侧确定性状态机。它只生成与真实手柄相同
形状的相对控制输入，不直接发送关节角、TCP 目标或 PVAT 数据。后端不为演练
添加绕过预检的运动接口。

演练只在运行时身份同时满足以下条件时启用：

- `backend == LEBAI_FAKE`；
- `runtime == DIGITAL_TWIN`；
- `digital_twin == true`；
- `hardware_verified == false`；
- 当前页面持有唯一控制连接；
- 后端未处于 readonly、FAULT、STALE 或急停状态。

任何一项不满足时，开始按钮保持禁用并显示确定原因。真实 `LEBAI`、普通
`SIM` 和未知身份都不能启动离线演练。

## 5. 组件边界

### 5.1 `OfflineRehearsalController`

职责：

- 管理演练阶段和唯一运行实例；
- 根据当前权威状态生成下一帧虚拟手柄输入；
- 等待状态确认，而非按固定延时盲目推进；
- 计算每阶段误差、超时和结果；
- 收到停止条件时立即停止发帧并请求现有安全停止；
- 将结构化结果交给报告器。

它依赖现有 Teleop WebSocket、ArmPanel 安全状态、robot state 和 diagnostics，
不依赖 Three.js 场景内部实现。

### 5.2 `OfflineRehearsalPanel`

职责：

- 显示永久的“数字孪生，不是真机”身份；
- 提供“开始完整演练”和“立即停止”；
- 显示阶段、进度、目标/实际 TCP、误差、剩余超时和首个失败根因；
- 在完成后显示报告位置和硬件待验证项。

面板只反映状态，不拥有机器人控制逻辑。普通 PC 手动控制和自动演练互斥。

### 5.3 演练报告器

报告器接收浏览器阶段结果以及后端已发布的权威状态/诊断摘要。输出至少包括：

- schema version、run id、开始/结束时间；
- Git commit、dirty 状态；
- runtime/backend/digital twin 身份；
- GLB、运动学配置和 Fake 配置 SHA-256；
- 每阶段目标、实际结果、误差、耗时、超时和失败原因；
- 故障、软约束、停止计数、迟到命令检查；
- recorder 会话路径和丢弃事件计数；
- `hardware_verified=false`；
- 固定的八项 `hardware_pending`。

JSON 用于机器判定，Markdown 用于人工查看。失败报告也必须完整写出。

报告生命周期复用当前页面的同一个 WebSocket，不增加 HTTP 控制入口或第二条
连接。协议增加三类不含运动目标的消息：

- `offline_rehearsal_begin`：后端验证 Fake 身份、当前所有者和空闲状态，返回
  唯一 run id；
- `offline_rehearsal_phase`：浏览器提交阶段名、目标、测量值和本地判定，后端
  同步附加当时的权威 robot state 与 diagnostics；
- `offline_rehearsal_finish`：后端校验 run id、阶段顺序和所有权，执行原子写入
  并返回 JSON/Markdown 路径。

后端只在 `LEBAI_FAKE` 接受这些消息。阶段消息不能 Arm、Home、停止或写运动
目标；相关动作仍必须走现有协议。浏览器提交的判定仅是报告输入，后端身份、
状态、诊断、Git 来源和硬件边界由后端重新生成，不能由客户端覆盖。

### 5.4 启动入口

新增统一入口：

```powershell
python scripts/run_offline_rehearsal.py
```

入口固定加载 `config/fake-lebai.yaml`，启动 FastAPI 与 Vite，输出 PC URL 和
进程状态，并在退出时按顺序停止前端、停止控制、断开 Fake 后端。它不接受
真实机器人配置，也不读取真机确认口令。

## 6. 演练状态机

每个阶段包含进入条件、目标、权威完成条件、超时和失败收尾。完整顺序如下：

1. **IdentityPreflight**：验证 Fake 身份、唯一所有者、配置哈希、IDLE、无故障；
2. **Home**：调用现有 Home 请求并等待 `homing -> stabilizing -> complete`；
3. **ArmAndAnchor**：松开 Grip 请求 Arm，再用当前虚拟手柄/TCP 建立相对零位；
4. **Translate**：依次执行 `+X/-X/+Y/-Y/+Z/-Z`，每次回到中心后继续；
5. **Rotate**：依次执行 `+roll/-roll/+pitch/-pitch/+yaw/-yaw`，每次回中；
6. **Gripper**：验证开、闭、重复命令抑制和方向一致性；
7. **PickPlace**：接近测试方块、闭合、抬升、横移、释放并等待稳定；
8. **SoftBoundary**：触发工作区软约束，退回有效区域并确认自动恢复；
9. **TrackingLoss**：发布无效跟踪，确认停止和锁定，不接受迟到目标；
10. **RecoveryAndHome**：按现有复位/Home 流程恢复并回到安全姿态；
11. **FinalStop**：松开 Grip、停止、解除控制权并检查命令静默；
12. **Finalize**：生成报告和结果摘要。

平移、旋转和抓放幅度由版本化演练配置定义。第一版固定为：各平移轴相对零位
`±0.020 m`，各旋转轴相对零位 `±8°`，平移完成容差 `0.003 m`，旋转完成容差
`2°`，单个运动阶段超时 `8 s`。每个轴必须回到相同容差内的零位后再测试下一
个轴。配置校验拒绝非有限数和超出这些固定第一版边界的值。真实 commissioning
的 5 mm/2° 限制不由离线演练修改。

## 7. 方块抓放判定

演练复用现有浏览器运动学抓取控制器，不引入重型物理引擎。判定条件包括：

- 抓取前 TCP/夹爪和方块进入规定邻域；
- 闭合后方块进入 attached 状态；
- 抬升与横移时方块相对夹爪位姿保持在容差内；
- 释放后方块落到桌面支撑面；
- 稳定后方块无穿桌、无穿夹爪、无持续漂移；
- 最终放置位置与目标区域相交。

视觉效果用于软件交互验收，不代表 LMG-90 接触力、摩擦或真实负载能力。

## 8. 失败与停止语义

以下事件立即中止当前演练：

- 页面隐藏、刷新、关闭或 WebSocket 断开；
- 控制权丢失或出现第二个控制连接；
- robot state/diagnostics 超时；
- FAULT、STALE、急停、停止未验证；
- 阶段超时、非有限数、误差持续越界；
- Home、Arm、Grip、IK/PVAT 或记录器拒绝。

中止顺序固定为：停止生成 VRFrame、清空本地轨迹、松开 Grip、发送现有停止
请求、等待权威停止确认、释放控制权、写失败报告。若停止无法验证，保持故障
锁存，报告不得显示“已安全复位”。刷新页面不能继续旧 run id。

网页只自动演练可由正常输入产生的跟踪丢失和软约束。PVAT 写失败、断连、
停止失败等底层故障继续由 Fake acceptance 的受控测试夹具注入，生产网页不
暴露通用故障注入能力。

## 9. soak 门禁稳定化

现有测试把安全正确性和“当前电脑上首次完整运行必须小于 15 秒”绑定在一起，
导致结果相同时仍会因系统负载跨过阈值。调整遵循以下原则：

1. 完整 10 分钟 soak 仍运行 30000 个周期和全部 7 类事件；
2. 安全断言继续覆盖步骤数、事件验证、停止次数、NaN、队列深度和最终模式；
3. 相同/不同 seed 的确定性复测使用较短但同构场景，避免重复三次完整 soak；
4. 性能回归独立检查短/长场景吞吐比例，捕获意外 sleep、阻塞和非线性退化；
5. 报告记录完整场景的 `duration_s` 与 `steps_per_second`；
6. 普通机器负载导致吞吐偏慢时标记性能警告，不伪装成安全失败；
7. 卡死、硬超时或明显非线性退化仍使门禁失败。

该调整不减少安全场景、不跳过失败，也不通过简单提高 15 秒阈值来获得绿色。

具体判定为：先执行 `0.1` 分钟预热，再分别测量 `0.5` 分钟和 `2.0` 分钟同构
场景；长场景吞吐不得低于短场景的 `70%`。完整 10 分钟场景设置 `60 s` 硬超时，
只用于捕获卡死或意外实时等待。完整吞吐低于 `2000 steps/s` 时报告性能警告，
但只要相对吞吐、硬超时和全部安全不变量通过，就不把机器负载误报为安全失败。

## 10. 测试策略

### 10.1 后端

- Fake 身份和配置拒绝测试；
- 报告 schema、哈希、原子写入和失败报告测试；
- 停止、Home、故障锁存和迟到命令静默回归；
- soak 完整安全不变量、确定性和相对吞吐测试；
- 禁止导入/调用真实 SDK 的审计。

### 10.2 前端

- 演练状态机逐阶段单元测试；
- 身份、所有权、页面隐藏、断连和超时拒绝测试；
- PC 面板状态、按钮互斥和根因显示测试；
- 六向平移、三轴双向旋转、Grip 与零位输入生成测试；
- 方块附着、移动、释放、支撑面和不穿模测试。

### 10.3 集成与验收

- WebSocket + `RobotControl` + `RealLebaiAdapter` + Fake Lebai 集成测试；
- PC 浏览器完整演练冒烟测试；该项使用本地浏览器人工/工具化执行，不新增
  Playwright 或 WebXR 模拟依赖；
- 完整 pytest、Vitest 和 Vite build；
- Virtual、Fake Lebai 和 Offline Rehearsal 三条门禁连续通过；
- 最终仓库审计确认无真实 SDK/硬件调用。

浏览器冒烟测试不模拟 WebXR；它直接运行 PC 离线演练界面，因此不依赖 Quest。

## 11. 完成标准

只有同时满足以下条件，本阶段才算完成：

- 一条命令能够启动离线演练环境；
- PC 页面能完整执行或安全失败，并始终保持单控制端；
- 演练动作经过现有真机同构上层路径；
- 方块抓放过程可观察且满足确定性几何判定；
- 任一中止条件都会停止、释放控制并写出根因；
- 完整后端、前端、构建和三条离线门禁通过；
- 报告来源、哈希和硬件待验证项完整；
- `hardware_verified` 始终为 `false`；
- 未连接真机、未调用真实 SDK、未合并、未推送。

本阶段完成后，项目仍只能进入下一次现场的 readonly 预检和逐轴低速测试，
不能自动批准真机自由遥操作。
