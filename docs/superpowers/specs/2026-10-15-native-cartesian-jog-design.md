# 有限时长原生笛卡尔平移候选设计

日期：2026-10-15，Asia/Shanghai。基线：a46d90c。

状态：用户已认可设计和实现计划；离线阶段 1、2 已实施并完成独立复核及修复，见[阶段结果](../../native-cartesian-jog-offline-2026-10-15.md)。真机及持续控制阶段仍未验收；本文不授权新机器人连接或动作。

## 1. 目标与当前证据

先实现简单可控的真机网页平移：摇杆控制平面、按钮控制升降，持续按住更新，松开撤权并停止。随后复用同一平移入口接入 VR，准备位与渐进夹爪继续使用已有独立流程。

当前 PVAT 候选通过过一次原停止验证，但回复198.817 ms，距200 ms门槛约1.2 ms，尚无可靠性结论。50 μm目标最大关节变化约0.000129565 rad；发送前实际/控制器目标最大差约0.000095874 rad。参考内目标TCP变化约4.1 μm，实际反馈未变化。因此不能把继续发送同类单点作为交付进度，也不能认定硬件有故障或IK失效。

本次选择调整底层运动方式，属于架构变更。第一交付物是隔离的单次候选和离线验证，持续网页模式须后续验收，不能直接替换现有真机入口。

## 2. 方案选择

| 路线 | 优点 | 代价/限制 |
| --- | --- | --- |
| 原生有限时长speedl（选定） | 直接表达平移速度，可减少逐帧应用层IK/FK调用；与摇杆方向输入相符 | 新接口与限时行为未验证，必须补足关节约束和停止证据 |
| 继续PVAT流 | 保留现有代码与关节目标检查 | 仍需满足连续点时序，并解释微小目标执行不足与停止波动 |
| 示教点位抓取 | 运动目标明确 | 不满足用户已选择的实时摇杆路线，不作为本次替代 |

官方SDK提供`speedl(a, v, t, frame)`，返回运动ID；`t`缺省为0，不能沿用缺省值。官方文档说明新运动命令会终止当前速度运动并执行新命令，但未给出本项目所需的停止回复时限。见[运动接口说明](https://help.lebai.ltd/en/sdk/motion.html)。

本机SDK存根`.venv/Lib/site-packages/lebai_sdk/__init__.pyi`包含该签名；这只是静态能力证据，不证明已安装原生异步桥接或控制器兼容性通过。SDK二进制身份继续按既有SHA绑定，不升级SDK来试错。

## 3. 范围和操作行为

- 首个候选只含XYZ平移，旋转三个速度分量固定为0，坐标系显式为基座。自转沿已有路线保留，候选未验收前不混合发送两种运动。
- 摇杆两轴与升降共用一个速度向量，合成速度按向量模限幅，不能让斜向速度超过设定上限。网页和VR最终共用同一后端平移意图接口。
- `a`必须为有限正数且不超过批准配置的TCP加速度上限；速度不超过批准TCP速度上限。候选不修改当前0.05 rad/s、0.2 rad/s²关节策略目标。
- `t`必须显式提供、为有限正数，初始软件支持范围10–80 ms；禁止0、None、缺省或负值。实际现场值另由单次范围批准。
- 持续控制将采用最新有效输入，不积压旧目标；松开、失焦、隐藏、断连、输入过期、撤权都禁止续发。不得用“t已经结束”替代原停止与稳定验证。
- 准备位、Home禁用策略、渐进夹爪、桌面与仿真物理均不在本次重写范围。候选不增加另一套交付界面。

## 4. 软件结构与权限

先增加独立的原生平移命令类型、规划校验和Fake执行器，再做只连接固定127.0.0.1自有模拟端的原生SDK协议核对。原有生产配置解析和真机服务不会自动选择此候选。

未来专用候选适配器复用现有运动调用所有权、代次撤权、SDK锁优先级、原停止事务、日志与未知结果隔离，不提供任意RPC透传。原生白名单只增加明确的speedl能力；不扩大旧控制路径的通用能力判定。

每个命令绑定：连接实例、会话/代次、输入序号、方向/速度、帧、时长、固定截止、实际快照来源、配置与源码身份。入队前和实际SDK入口均核对；不得在SDK入口重启输入或运动有效期。仅一个原生运动写入在途；迟到输入只替换尚未发送的意图，不能续发旧命令。

保留100 ms运动新鲜度与60 ms原生运动调用等待上限，使用隔离QPC时钟。若speedl在此时限内不能正常返回，就报告该候选不合适，不放宽时限。返回ID必须有效且属于本次请求；晚返/取消/未知结果保留原所有权与故障，晚到ID不得恢复发送。

## 5. 工作区、关节与停止约束

进入候选需要原只读预检、记录准备位、空载净空和独占控制。仍须检查关节软限位、奇异风险、工具配置、实际与目标反馈、软件工作区、遥测年龄及原未知结果锁存。

**不能把`速度×时长`当作包含启动延迟、到期减速和停止迟到的物理位移上界。** 工作区规划须显式保留经验证的启动/制动余量；缺少余量证据时，只能产生离线计划，不能据此打开持续控制。当前±5 mm框只属于以前批准的单次范围，不能自动继承为新候选的自由工作区。

**笛卡尔低速不自动证明关节低速。** 原IK/FK关节约束不能直接删除后声称已保留。持续模式的准入必须具有与当前机器人/姿态范围绑定的关节速度、加速度和奇异边界证据（控制器可核对的约束，或经过单独审查的局部模型约束）。不满足时返回明确的`native_jog_joint_bounds_unverified`并拒绝持续真机入口；遥测事后监控不是预测约束的替代。首次单次诊断所需的预检和数学查询另定范围，不能预先承诺完全免IK。

松开和撤权仍发起原唯一stop_move事务，保留200 ms RPC、300 ms稳定、500 ms验证、stop_unverified以及未知写入锁存。到期或停止回复不是物理停稳证明。不得恢复自动stop_sys、用pause_move替换、把零速度命令当停止证明或自动复位。原生速度指令可能改变停止时序，不能沿用PVAT那一次通过记录。

## 6. 分阶段验收

1. **离线命令与所有权**：参数/单位/坐标系、速度模限幅、显式正时长、输入和快照截止、工作区余量、未验证关节边界拒绝、单写入所有权、撤权与未知结果锁存通过定向测试。默认生产路径不选择新候选。
2. **固定回环协议**：使用相同SDK二进制，仅连接由脚本创建的127.0.0.1监听端；核对真实speedl序列化、时长/帧参数、运动ID、超时/晚返、取消和停止优先级。不能接受CLI任意IP，不发现机器人。回环通过不等于硬件兼容。
3. **单次真机候选**：准备具体范围与哈希预览，取得新的现场条件和明确授权后，最多一次连接、一次小幅平移及原停止/观察。读取原厂速度倍率与当前设置需要包含在批准范围；不修改倍率或控制器配置。须核对实际位移方向、速度/关节反馈、时长结束行为和原停止验证。
4. **网页长按**：只有关节/工作区约束、单次运动、独立松开与超时行为得到足够现场证据后，才提出新的有限时段网页范围。前端保留现有摇杆，后端只在授权窗口内更新，不自动重试或恢复。
5. **VR与夹取**：平移通过后再验收VR共用链、旋转和渐进夹爪，最终抓取轻物体。不能用Fake或回环录像充当真机演示。

## 7. 失败处理和交付口径

任何参数、权限或边界不满足均拒绝本次动作；不回退PVAT、不生成其它目标。原生结果未知或停止未确认立即终止本次候选，不重新连接或发送其它动作。保留原始现场材料于本机忽略目录，版本库只存代码、合成用例和不含敏感信息的结果说明。

每阶段分别报告软件实现、回环协议、单次运动、松开停止、持续控制与抓取状态，不合并为“真机已实现”。如果控制器不能提供所需关节/停止/有限时长边界证据，就报告该路线的具体阻塞项并重新选择方案，不能删掉门槛上线。
