# VR4Arm 自碰撞约束与确定性积木堆叠设计

日期：2026-07-26

## 1. 背景与已验证根因

当前 Quest 跟手体验已基本达到要求，但进入真机阶段前还存在两类必须在纯仿真中解决的问题。

### 1.1 机械臂关节与连杆穿模

仿真模型目前只使用所有关节统一的 `Home ± π` 窗口。该窗口用于防止数值 IK 绕行多圈，不是 LM3 真机机械限位，也不检查连杆自碰撞。

在当前窗口内执行固定种子的关节采样后，已找到非相邻关节中心距离约 `9.6 mm` 的姿态：

```text
q = [-2.9743, -3.6972, 2.7814, 1.3861, 2.4257, -3.7945] rad
```

因此穿模不是单纯的渲染误差：后端差分 IK、`VirtualRobot` 和前端 GLB 都允许进入缺少自碰撞约束的关节状态。

### 1.2 方块无法可靠抓取和放置

现有 `KinematicGraspController` 把配置中的 TCP 偏移直接传给：

```text
robotgrabber.localToWorld([0, -0.09, 0])
```

但 GLB 的 `robotgrabber` 节点带有约 `0.007950832` 的统一缩放。因此：

```text
期望 TCP 偏移：0.09 m
实际视觉偏移：约 0.000716 m
```

方块使用 `tool.add(cube)` 挂到该节点后还会继承同一缩放，`60 mm` 方块的视觉边长会变为约 `0.477 mm`。现有单元测试使用未缩放的普通 `Group`，没有覆盖该真实 GLB 条件，所以测试通过但实际抓取失败。

现有释放逻辑始终把单个方块放回固定桌面高度，没有多个物体、支撑面选择或重叠处理，不能实现积木堆叠。

## 2. 目标与范围

本阶段目标：

- 在后端差分 IK 与仿真积分之间增加轻量、确定性的 LM3 自碰撞约束；
- 自碰撞保持软约束语义：停在最后安全姿态，退回后自动恢复，不进入红色锁存故障；
- 修复 GLB 工具缩放导致的 TCP 抓取坐标和方块尺寸错误；
- 在桌面放置五个不同颜色的可抓取方块；
- 支持桌面放置和确定性的多层积木堆叠；
- 保证所有静止/释放后的方块 AABB 不互相穿透，也不穿入桌面；
- 使用少量主体测试和一次 Quest 人工体验验收；
- 保持 `backend: simulator`，不导入、不连接、不调用 Lebai SDK。

本阶段不包含：

- 真机连接、真机自动 Home、真机速度或安全参数；
- Cannon-es、Rapier、Ammo、MuJoCo、Isaac Sim 或其他刚体物理引擎；
- 重力、弹跳、摩擦、倾倒、抓取力和接触动力学；
- 机械臂与方块、机械臂与桌面的后端碰撞耦合；
- 携带中方块与其他方块的完整连续碰撞求解；
- 相机采集、数据集写入或方块状态进入协议；
- 用仿真碰撞代理替代未来的真机安全配置和现场验收。

## 3. 方案选择

### 3.1 推荐并采用：后端胶囊自碰撞 + 前端确定性堆叠

后端使用与共享 GLB 运动学一致的关节原点构造简化胶囊代理，在每个候选伺服步执行前检查自碰撞。前端使用后端权威 `actual_tcp` 驱动方块，并在释放时计算确定性的支撑高度。

优点：

- Quest 计算开销小；
- 行为可复现，便于后续 VLA/ACT 数据采集；
- 机器人安全约束和物体交互职责清晰；
- 不引入新依赖；
- 未来更换真机后端时不会把浏览器交互误当成真机安全控制。

### 3.2 未采用：仅缩小关节角范围

关节角盒约束实现简单，但 LM3 官方语义是关节运动范围不等同于一组固定机械止挡，且多个关节组合仍可能产生自碰撞。仅缩小角度会带来大量误限制，也不能从根本上解决连杆交叉。

### 3.3 未采用：完整网格碰撞和刚体物理

网格碰撞与刚体物理更真实，但会增加 Quest 负载、依赖、调参成本和非确定性。本阶段只要求安全可预测的仿真遥操作、抓取和堆叠，不需要掉落与倾倒。

## 4. 后端自碰撞约束

### 4.1 碰撞代理

共享运动学链继续使用：

```text
base origin
J1 origin
J2 origin
J3 origin
J4 origin
J5 origin
J6 origin
TCP
```

从 GLB 的 ARM0–ARM6 几何包围范围校准以下代理半径：

| 代理 | 半径 |
| --- | ---: |
| 底座 | `0.075 m` |
| 主要臂段 | `0.055 m` |
| 腕部 | `0.045 m` |
| 工具/TCP 段 | `0.040 m` |

额外安全间隙为 `0.008 m`。碰撞阈值为：

```text
segment_distance < radius_a + radius_b + 0.008
```

不对所有线段两两检测。相邻连杆、共享同一关节的连杆以及 GLB 中结构上必然靠近的腕部外壳组合加入忽略表。检测表只包含可能发生实际折返穿模的组合：

- 底座 vs 前臂；
- 底座 vs 腕部各段；
- 底座 vs 工具/TCP 段；
- 上臂 vs 腕部各段；
- 上臂 vs 工具/TCP 段；
- 前臂 vs 远端工具/TCP 段。

实现必须以 Home 为无碰撞基准，并用已知折叠姿态作为碰撞回归样本。若某个代理在 Home 误报，应收窄该代理有效线段或调整忽略组合，不能简单降低所有代理半径。

### 4.2 伺服集成

`cartesian_servo_step()` 保持现有位置优先的速度求解。得到受速度限制、关节窗口裁剪后的 `next_q` 后：

1. 使用共享 GLB 运动学计算 `next_q` 的代理端点；
2. 检查配置允许的碰撞组合；
3. 若安全，返回现有 `joint_velocity`；
4. 若碰撞，返回全零 `joint_velocity`、保持当前 `q`，并设置 `self_collision_limited = true`。

不把碰撞候选传给 `VirtualRobot` 后再回退，避免仿真积分和视觉状态短暂进入穿模姿态。`SimRobotAdapter.command_tcp()` 收到该结果后不更新速度目标，而是抛出 `BackendCommandError("self_collision")`；这与现有 IK/关节软约束拒绝路径保持一致。

候选碰撞属于软约束。`SimRobotAdapter.command_tcp()` 不抛出硬故障，而是把结果反馈给 `RobotControl`。控制层发布新的约束码：

```text
self_collision
```

前端中文提示：

```text
机械臂接近自碰撞边界，请将手柄退回
```

当前方向停止后，Grip 仍可保持按住；当下一目标产生安全的退回速度时自动恢复。现有 `joint_safety_window`、数值异常、失联和控制循环故障仍保持原有硬停止语义。

### 4.3 数值关节窗口

`Home ± π` 继续作为仿真会话数值窗口，防止多圈绕行。它不改名为真机限位，也不在本阶段伪造一组 LM3 硬件止挡范围。

## 5. 多方块世界空间抓取

### 5.1 方块集合

创建五个边长 `0.060 m` 的方块，颜色与初始中心坐标如下：

| ID | 颜色 | 初始位置 `(x, y, z)` |
| --- | --- | --- |
| `block-orange` | `#ff8a3d` | `(0.18, 0.025, -0.32)` |
| `block-blue` | `#39a8ff` | `(0.32, 0.025, -0.22)` |
| `block-green` | `#58d68d` | `(0.04, 0.025, -0.28)` |
| `block-yellow` | `#ffd84d` | `(0.28, 0.025, -0.38)` |
| `block-purple` | `#a77bff` | `(0.10, 0.025, -0.18)` |

桌面顶面为 `-0.005 m`，所以方块静止中心高度为：

```text
-0.005 + 0.060 / 2 = 0.025 m
```

所有方块始终是 `robotVisualRoot` 的直接子对象，绝不挂到带缩放的 `robotgrabber`。

### 5.2 权威 TCP

抓取控制器改为消费后端 `RobotStateMessage.actual_tcp`：

```ts
update(actualTcp: Pose, gripper: number): void
```

`actual_tcp` 与方块坐标都位于机器人视觉根的局部场景坐标。左手工作台位移统一作用于 `robotVisualRoot`，因此不会改变二者的相对关系。

携带中，控制器直接写入方块在 `robotVisualRoot` 下的位置和姿态，不经过工具节点局部缩放。方块跟随 TCP 旋转；释放时为稳定堆叠恢复为世界竖直、绕 Y 轴零旋转。

### 5.3 抓取体积与状态机

抓取区域是以 `actual_tcp` 为中心、随 TCP 姿态旋转的有向盒，中心容差为：

```text
half_extents = (0.055, 0.045, 0.055) m
```

状态机：

```text
FREE
  -> gripper >= 0.65 且存在候选
  -> CARRIED(block_id)

CARRIED(block_id)
  -> gripper <= 0.35
  -> PLACE
  -> FREE
```

候选必须：

- 未被携带；
- 中心在抓取有向盒内；
- 在所有候选中到 TCP 中心距离最近。

一次只能携带一个方块。`0.65 / 0.35` 迟滞避免模拟夹爪值在阈值附近抖动。闭合状态下移动到新方块附近不会再次抓取；必须先释放到 `<= 0.35`，再重新闭合。

## 6. 确定性无穿模放置与堆叠

### 6.1 桌面范围

释放的 X/Z 先限制到桌面内，并保留半个方块边长：

```text
x ∈ [-tableHalfWidth + 0.030, tableHalfWidth - 0.030]
z ∈ [-tableHalfDepth + 0.030, tableHalfDepth - 0.030]
```

### 6.2 支撑面选择

对每个非携带方块计算水平 AABB 重叠。如果释放方块与支撑方块在 X/Z 上的中心差都不超过 `0.039 m`，视为具有足够支撑重叠。

候选支撑面包括：

- 桌面顶面 `-0.005 m`；
- 每个满足水平重叠的方块顶面 `block.center.y + 0.030 m`。

选择最高支撑面。若选择方块支撑，释放方块的 X/Z 对齐到该支撑方块中心；否则保留桌面范围内的释放 X/Z。

最终中心高度：

```text
placed_center_y = support_top_y + 0.030
```

### 6.3 重叠校验

写入最终位置前，对所有静止方块执行 AABB 重叠检查：

```text
overlap_x = abs(dx) < 0.060 - epsilon
overlap_y = abs(dy) < 0.060 - epsilon
overlap_z = abs(dz) < 0.060 - epsilon
```

三轴同时重叠才判定穿模。若候选仍重叠，继续把方块提升到所有水平重叠方块中的最高顶面，直到无重叠。五个方块的有限集合保证该过程终止，最坏结果是形成五层竖直堆叠。

本阶段保证桌面和每次释放后的静态堆叠不穿模。携带中方块仍以跟随夹爪为优先，不实现与其他方块或机械臂的连续碰撞动力学；这是确定性运动学方案与完整刚体物理方案的明确边界。

## 8. 数据流

```text
Quest 手柄目标
  -> RobotControl
  -> 位置优先差分 IK 候选速度
  -> 预测 next_q
  -> 胶囊自碰撞检查
     -> 安全：VirtualRobot 积分
     -> 碰撞：零速度 + self_collision 琥珀提示
  -> RobotStateMessage.actual_q / actual_tcp / gripper
  -> Three.js GLB 渲染
  -> actual_tcp + gripper 驱动多方块抓取
  -> 释放时确定支撑面并消除 AABB 重叠
```

相机、时间同步和未来记录扩展点保持不变。

## 9. 错误处理与安全语义

- 自碰撞候选：软约束，不锁存故障，不自动 Home；
- 无抓取候选时闭合 Trigger：夹爪正常闭合，方块状态不变；
- 多个候选：抓取最近方块；
- 释放位置超出桌面：限制到桌面安全边界；
- 释放位置与多个方块重叠：放到最高合法支撑面；
- 非有限 TCP/夹爪值：忽略该次方块更新，保留上一个稳定状态；
- 连接中断或页面重载：机械臂沿用现有安全锁定；新建场景时方块回到初始位置；
- 自碰撞计算异常或非有限关节值：沿用现有数值安全故障路径，不能按“无碰撞”放行。

## 10. 聚焦测试与人工验收

### 10.1 后端

1. Home 姿态与现有小幅跟手路径必须无碰撞；
2. 已知折叠姿态必须被判为自碰撞；
3. 一个会进入自碰撞的伺服候选必须返回零速度并保持当前关节角；
4. 从相同状态向外退回的安全候选必须恢复非零速度；
5. `self_collision` 只形成软约束，不进入红色故障。

### 10.2 前端

1. 使用带 `0.007950832` 缩放的工具节点复现旧错误，并证明新控制器不继承工具缩放；
2. 五个方块具有唯一 ID、不同颜色和无重叠初始位置；
3. 抓取有向盒只选择最近合法方块；
4. 携带方块随 `actual_tcp` 平移和旋转；
5. Trigger 释放可放回桌面；
6. 两层和五层堆叠的中心高度分别正确；
7. 所有释放后的方块 AABB 均不重叠；
8. 运行一次前端生产构建。

不运行长时间 soak、全量随机 IK 或完整物理仿真测试。

### 10.3 Quest 人工验收

1. 普通小幅跟手仍保持当前响应速度；
2. 向折叠方向运动时停在穿模之前，显示琥珀提示；
3. 手柄退回后无需复位即可继续；
4. 五个方块都能用 Trigger 抓取、携带和释放；
5. 方块抓取后尺寸不变化、不消失；
6. 可完成至少两层和五层堆叠；
7. 放置后的方块不进入桌面或其他方块。

## 11. 真机接入门槛

完成本设计并通过 Quest 人工验收后，项目才进入“准备真机接入”阶段。真机阶段必须重新设计并确认：

- 乐白 SDK 的权威关节状态、TCP 状态和笛卡尔控制接口；
- 真机控制计算机、网络和急停链路；
- 乐白设备中实际配置的安全角度、速度和加速度；
- 真机自碰撞/奇异/工作空间能力由 SDK、控制器还是上位机负责；
- 仿真关节角与真机零位、方向、单位的标定；
- 仿真碰撞代理只用于可视化预检，不能替代真机控制器安全功能；
- 首次真机测试使用低速、空载、有人值守和物理急停。

真机后端在上述规格另行批准前继续保持硬禁用。

## 12. 设计自审

- 无 `TBD`、`TODO` 或未定义接口；
- 自碰撞与积木交互职责分离；
- 明确区分数值关节窗口、仿真碰撞代理和真机安全限位；
- 明确静态堆叠无穿模，不夸大为完整连续碰撞或物理仿真；
- 不增加依赖、不修改相机/记录协议、不启用真机；
- 每项用户需求都有对应实现组件、错误语义和验收项。
