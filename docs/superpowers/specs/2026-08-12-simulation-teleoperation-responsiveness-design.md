# 仿真遥操作稳定性与跟手体验设计

## 背景

当前仿真遥操作存在两个相互放大的问题：

1. 手柄连续移动时很容易进入 `workspace_boundary` 或 `joint_boundary`，工作空间边界会冻结整个位姿，导致即使用户只在一个方向越界，其他平移方向和夹爪旋转也全部停止。
2. Fake 乐白后端连续五次 IK/关节连续性拒绝后会抛出 `ik_failure_persistent`。该异常会永久停止 PVAT Pump，之后 `get_state()` 持续抛错，使唯一控制 WebSocket 在“已连接/正在重连”之间循环。

这不是局域网或浏览器带宽故障。最新运行证据中，WebSocket 在故障前保持连接，ACTIVE 状态下 347 个状态样本中出现 78 次工作空间边界、3 次关节边界，随后后端日志明确记录 `BackendCommandError: ik_failure_persistent`。

## 目标

- 仿真中的可恢复 IK、关节连续性和工作空间越界不得杀死 PVAT Pump，也不得导致 WebSocket 重连。
- 工作空间到边界时只限制越界轴；未越界轴和姿态继续跟随手柄。
- 用户反向移动时，从下一批有效控制样本开始退出限制，不自动改变零位或重新锚定。
- 适度提高仿真的平移、旋转和关节响应速度，使手柄动作与机械臂末端之间的延迟和“慢动作感”明显降低。
- 真机继续使用保守限速、整姿态保持和异常停机策略；仿真优化不得放宽真机安全行为。
- HUD 明确把软约束描述为可恢复状态，并提示“保持 Grip，向反方向退回”。

## 非目标

- 本阶段不修改真机 LM3 的速度、安全空间、IK 错误升级和失联停止策略。
- 不增加自动零位漂移、自动重锚定或绕过 Home 的隐藏恢复动作。
- 不引入完整物理引擎，不改变现有积木抓取物理模型。
- 不处理数据采集、VLA/ACT/Diffusion Policy 数据格式。

## 方案比较

### 方案 A：仿真专用的稳定控制通道（采用）

在保留单一 WebSocket、现有普通 VRFrame 协议和现有 RobotControl 状态机的前提下，增加显式的仿真控制策略：逐轴软限位、Fake-only IK 回退、Fake-only 速度配置和可恢复 PVAT 约束。真机路径维持原行为。

优点是同时解决重连根因和操作不灵活问题，仿真与真机边界清楚，已有遥操作协议无需分叉。代价是需要修改安全投影、Fake 适配器和配置，并补充跨层回归测试。

### 方案 B：只调大速度和工作空间

实现最快，但 IK 不连续仍会杀死 PVAT Pump，边界仍会冻结整个位姿。它只能推迟故障，无法解决重连和卡死根因，因此不采用。

### 方案 C：越界后自动重设零位

短时感觉自由，但机械臂与手柄的空间对应会在用户不知情时漂移，反向移动也无法回到原来的映射位置，不适合后续数据采集，因此不采用。

## 总体架构

控制数据流保持不变：

`Quest/鼠标 -> SimulationScene -> 普通 VRFrame -> TeleopSocket -> RobotControl -> SafetyLimiter -> RealLebaiAdapter(LEBAI_FAKE) -> FakeLebaiClient -> RobotState -> 场景/HUD`

优化发生在三个独立边界：

1. `SafetyLimiter` 负责把请求位姿投影为安全位姿，不处理 IK。
2. `RealLebaiAdapter` 的 Fake 运行模式负责将 IK/连续性失败转换为可恢复约束，不让 PVAT Pump 退出。
3. `config/fake-lebai.yaml` 只调整仿真响应参数；真机配置不变。

不创建第二条控制连接，不新增观察端，不绕过 RobotControl，也不把前端的虚拟关节状态直接写入后端。

## 详细设计

### 1. 逐轴软限位

`SafetyLimiter` 增加显式工作空间策略：

- `hold`：当前真机默认。任一轴越界时保持最后安全位姿。
- `axis_clamp`：仿真使用。将每个越界的平移分量分别夹到 `anchor ± half_extent`；未越界分量保持请求值，四元数姿态不因平移越界而冻结。

旋转范围也采用边界投影而不是整姿态冻结：将相对锚点的旋转角限制到最大角度，保留旋转轴。球形总工作空间限制继续做径向投影。投影后的位姿仍必须经过速度、加速度、单步长度、IK、软关节限位和自碰撞检查。

`axis_clamp` 返回 `constrained=true, hold=false`。RobotControl 因此继续向后端发送安全投影后的目标，同时发布 `workspace_boundary`。当用户反向移动到边界内时，现有约束清除窗口负责去抖；坐标映射锚点和手柄零位均不改变。

### 2. Fake IK 连续性回退

Fake 运行模式下，如果完整目标产生以下可恢复错误：

- `ik_unreachable`
- `ik_invalid`
- `ik_joint_limit`
- `ik_joint_jump`
- `joint_speed_limit`

适配器保存上一次已发送的安全末端位姿，并在它与本次请求位姿之间执行最多四级、从接近请求目标到接近安全目标的有界回退。平移线性插值，旋转采用四元数球面插值；接受最接近请求目标且通过 IK、软关节限位、关节单步限制、自碰撞和 PVAT 构造的候选位姿。停止、断线、Home 或控制代际变化时清除该缓存，禁止跨控制会话复用安全目标。

如果没有候选可行，则保持最后安全目标并发布 `ik_boundary` 或 `joint_boundary`，等待用户反向移动。该结果属于一次成功处理的可恢复约束，不增加 PVAT Pump 的永久 fault，也不关闭 WebSocket。一次完整可行的目标成功发送后清除连续失败计数和约束。

真实 `LEBAI` 运行模式不执行该回退；其 SDK 超时、调用失败、连续 IK 失败和未知异常仍按现有策略停止 Pump 并触发故障处理。

### 3. 仿真响应参数

`config/fake-lebai.yaml` 采用以下首版参数，所有数值只影响 `LEBAI_FAKE`：

| 参数 | 当前值 | 新值 |
|---|---:|---:|
| `max_tcp_speed_mps` | 0.03 | 0.06 |
| `max_tcp_rotation_radps` | 0.25 | 0.50 |
| `max_tcp_acceleration_mps2` | 0.10 | 0.20 |
| `max_tcp_angular_acceleration_radps2` | 0.50 | 1.00 |
| `max_joint_speed_radps` | 0.15 | 0.30 |
| `max_joint_acceleration_radps2` | 0.50 | 1.00 |
| `max_joint_step_rad` | 0.01 | 0.015 |
| `max_tcp_step_m` | 0.002 | 0.003 |
| `max_tcp_rotation_step_deg` | 1.0 | 1.5 |
| `max_relative_translation_m` | 0.10 | 0.16 |
| `max_relative_rotation_deg` | 30 | 45 |
| `translation_scale` | 0.50 | 0.70 |

控制环仍为 50 Hz，状态和 PVAT 仍为 25 Hz，WebSocket 协议与时间戳语义不变。速度提升不通过降低 stale、失联停止或自碰撞检查实现。

### 4. 状态与 HUD

现有 `constraint` 枚举保持兼容，不把软约束升级为 `fault`：

- `workspace_boundary`：`已到达操作边界，保持 Grip 向反方向退回`
- `ik_boundary`：`当前姿态暂不可达，保持 Grip 退回上一个位置`
- `joint_boundary`：`已到达关节操作边界，保持 Grip 反向退回`
- `self_collision`：沿用现有自碰撞提示

连接状态只反映真实 WebSocket 生命周期。软约束出现时仍显示“已连接”，禁止用断线重连来恢复软约束。诊断事件记录约束原因、请求目标、采用的回退级别和最终安全目标，便于下一轮调参；首版不扩展 RobotState 消息协议来传输逐轴明细。

### 5. 错误处理

| 情况 | 仿真 | 真机 |
|---|---|---|
| 工作空间单轴越界 | 夹紧该轴，其他自由度继续 | 保持最后安全位姿 |
| IK/关节连续性失败 | 有界回退；失败则软约束保持 | 现有错误升级策略 |
| 自碰撞 | 保持并提示反向退回 | 现有安全策略 |
| SDK 超时/未知异常 | 故障并停止，不伪装成软约束 | 故障并停止 |
| tracking stale/断线 | 沿用失联停止 | 沿用失联停止 |

只有明确列出的 Fake IK/连续性错误可以恢复；录制失败、SDK 调用失败、控制循环异常和停止未确认仍必须 fail closed。

## 测试与验收

实施使用测试驱动方式，最少覆盖：

1. **SafetyLimiter 单元测试**：X 轴越界时 X 被夹紧，Y/Z 和旋转继续变化；反向回到范围后约束清除；真机 `hold` 模式保持旧行为。
2. **Fake 适配器测试**：连续十次不可行目标不会设置 `pump.fault` 或停止 Pump；回退候选可行时发送最接近请求的安全目标；完整可行目标恢复正常状态。
3. **真机隔离测试**：相同连续错误在 `LEBAI` 标签下保持现有升级行为，真机配置哈希和关键限速值不变。
4. **RobotControl 测试**：软约束期间保持 ACTIVE/HOLD 且连接不关闭，其他轴的 `target_tcp` 持续更新，反向动作可恢复。
5. **前端测试**：HUD 显示可恢复说明；软约束不会呈现为重连或 FAULT。
6. **集成耐久测试**：Fake 栈持续至少 15 秒并发送不少于 200 帧包含工作空间越界、IK 不可达和反向恢复的普通 VRFrame；整个过程只有一个控制 WebSocket，重连次数为 0，PVAT Pump fault 为空。
7. **渲染验收**：桌面鼠标控制与可用时的 Quest 3 手柄分别验证平移、旋转、单轴触边和反向恢复；不得出现页面自动刷新或“已连接/正在重连”闪烁。

首版性能验收目标：

- 50 mm 可行平移命令在 2 秒内进入 3 mm 位置误差范围。
- 20° 可行旋转命令在 2 秒内进入 2° 姿态误差范围。
- 单轴越界时，另一个未受限平移轴在后续 3 个状态样本内持续产生同向位移。
- 反向退回后，在现有约束清除去抖窗口内恢复无约束状态。
- 全部自动测试通过；Vite 现有大包警告可以保留，但不得新增构建错误。

## 发布与回滚

改动分成独立提交：

1. 安全投影策略与测试。
2. Fake IK/PVAT 可恢复路径与真机隔离测试。
3. Fake 参数与 HUD 文案。
4. 集成耐久与渲染验收修正。

任何阶段出现真机路径行为变化时停止合并。回滚 Fake 参数不会改变协议；回滚 `axis_clamp` 可恢复原来的整姿态保持；Fake IK 回退可通过运行标签独立关闭。

## 已确认的产品决策

- 仿真到达边界时采用单轴软限幅，其他方向继续跟手。
- 用户反向移动时立即恢复，不自动改变零位。
- 仿真和真机使用明确隔离的安全/响应策略。
- 仿真控制是正式功能，不作为只供展示的次要路径。
