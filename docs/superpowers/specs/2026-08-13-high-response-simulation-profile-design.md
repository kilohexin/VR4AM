# 高响应仿真控制参数设计

日期：2026-08-13

## 目标

为 PC 和 Quest 3 的交互仿真提供接近手柄直觉的末端跟随体验，同时继续通过与真机相同的坐标映射、IK、PVAT、停止和状态回传链路验证集成逻辑。仿真体验参数与真机现场参数必须完全隔离。

本次目标不是取消安全机制，也不是修改任何真机速度。真实六轴软关节限位、自碰撞检测、Grip 松开停止、失联停止、单控制端和故障锁定继续有效。

## 运行模式边界

项目对用户仍只显示两种模式：

- **仿真**：运行时身份为 `LEBAI_FAKE`，使用高响应仿真参数。
- **真机**：运行时身份为 `LEBAI`，使用现场本地 YAML 中的保守参数。

网页不能自行把仿真后端切换成真机后端。运行模式由服务器启动配置决定。仿真启动器仍强制加载 Fake 配置；真机必须经过独立的只读预检、确认口令和现场配置启动。

## 仿真参数组

`config/fake-lebai.yaml` 使用以下相互匹配的参数，不只修改单个 TCP 速度：

| 参数 | 新值 | 目的 |
|---|---:|---|
| 控制循环 | `50 Hz` | 保持低延迟控制 |
| 状态回传 | `50 Hz` | 提高画面与权威状态更新频率 |
| PVAT 发送 | `50 Hz` | 减少目标等待和慢动作感 |
| PVAT horizon | `0.04 s` | 保持两个发送周期的前视 |
| 平移映射默认值 | `1.5` | 手柄移动 `10 cm` 时 TCP 目标移动 `15 cm` |
| TCP 最大线速度 | `0.30 m/s` | 恢复高响应仿真体验 |
| TCP 最大线加速度 | `1.2 m/s²` | 与速度上限匹配 |
| TCP 最大角速度 | `1.5 rad/s` | 提升姿态跟随 |
| TCP 最大角加速度 | `4.0 rad/s²` | 与角速度匹配 |
| TCP 单控制周期步长 | `0.006 m` | 等于 `0.30 / 50` |
| TCP 单周期旋转步长 | `2.0°` | 略高于 `1.5 rad/s / 50`，避免数值边界误报 |
| 关节最大速度 | `1.5 rad/s` | 避免 IK 输出被旧真机级限速持续卡住 |
| 关节最大加速度 | `4.0 rad/s²` | 与仿真伺服能力匹配 |
| 关节单步上限 | `0.06 rad` | 等于 `1.5 × 0.04` |

相对工作空间保持现有逐轴 `±0.16 m`，相对姿态保持 `45°`。本次不扩大可操作空间，只提升空间内部的响应速度。

`config/real-robot.example.yaml` 不得随本次改动变化，继续保持 `0.03 m/s`、`0.5` 平移比例以及现有现场保守限制。自动测试必须直接断言仿真与真机模板的速度隔离。

## 前端平移倍率

PC 页面增加“平移倍率”控件，显示为 `倍率值 : 1`：

- 范围固定为 `0.5–2.0`，步进 `0.1`，默认值 `1.5`；
- 仅运行时身份为 `LEBAI_FAKE` 的仿真允许修改；
- 真机 `LEBAI` 只显示现场 YAML 的倍率，控件禁用，网页不能覆盖真机配置；
- 只有 Grip 松开且权威状态已经停止时才允许修改；ACTIVE、停止确认中、故障恢复中和离线演练期间均禁用；
- 修改后由后端校验范围、应用到下一次 Grip 锚定并返回实际生效值；当前已经建立的 Grip 锚点不允许中途改变倍率；
- 仿真值保存到当前浏览器的 `localStorage`，下次连接同一仿真运行时恢复；越界、非有限值或协议拒绝时回退到后端权威值；
- 日志记录倍率变更、请求来源和实际生效值。未来采集数据时原始手柄位姿与生效倍率分字段保存，不能只保存放大后的 TCP 目标。

倍率是工作空间覆盖参数，不是速度上限。即使使用 `2.0:1`，TCP 仍受 `0.30 m/s`、加速度、工作空间、IK、关节和自碰撞限制。

## 边界与恢复语义

界面不得把所有连续性保护都称为“关节操作边界”。约束按根因分类：

- `joint_boundary`：IK 解确实越过配置的软关节上下限。
- `ik_boundary`：姿态/位置在当前关节构型下暂时不可达或 IK 无有效解。
- `motion_continuity_boundary`：IK 解存在，但单步、关节速度或加速度连续性暂时超过仿真伺服能力。
- `workspace_boundary`：末端超过 Grip 锚点的相对工作空间或姿态包络。
- `self_collision`：模型进入自碰撞保护范围。

前三类均为可恢复软约束，不锁定、不要求 Home。保持 Grip 并向反方向退回即可恢复。只有真实硬故障才进入红色故障锁定。

工作空间继续使用 Fake-only 逐轴夹紧：某一轴达到边界时，其余未越界轴仍可运动。真机保持原有整体保持策略，不继承仿真夹紧行为。

## 数据流

```text
PC/Quest 手柄（50 Hz）
  → 相对零位映射（仿真平移 0.5–2.0、姿态 1:1）
  → 仿真 TCP 速度/加速度限制
  → IK 与真实软关节/自碰撞检查
  → 50 Hz PVAT 仿真执行
  → 50 Hz 权威状态与三维画面
```

Grip 每次重新按下仍从当前手柄位姿与当前实际 TCP 重新锚定。松开 Grip 必须先确认仿真停止；再次按下时重新预检并继续，不沿用停止前未执行的旧目标。

## PC 三维视角

PC 页面保留现有左键拖动虚拟手柄、滚轮控制手柄前后的操作，同时增加独立观察相机：

- 按住右键拖动时，以机械臂工作区中心为观察目标做水平/俯仰环绕；
- 右键操作禁止触发 Grip、Trigger 或任何机器人目标帧；
- 右键拖动过程中阻止浏览器上下文菜单，并正确处理 pointer capture、窗口失焦和页面隐藏；
- 页面增加“复位视角”按钮，恢复当前默认相机位置和观察目标；
- 进入 WebXR 后仍由头显视角控制，不应用 PC 环绕相机；退出 WebXR 后保留 PC 最近视角，除非用户主动复位；
- 仿真自动演练期间允许观察相机环绕，但不允许左键或滚轮产生人工机器人输入。

相机变化只影响渲染，不进入 WebSocket 控制协议，也不改变机械臂、方块或工作台坐标。

## 真机画面边界

当前真机运行时在 PC/Quest 中仍显示由真机权威关节状态驱动的三维 LM3 模型，不读取 Quest 摄像头，也没有实现 MR 透视。首次现场验收必须由操作者和独立安全观察员直接观察真实机械臂，保持急停可达。

推荐的后续真机体验是 Quest 3 MR 透视：用户通过头显直接观察真实机械臂，应用只叠加 HUD、目标末端、边界和状态。该能力作为独立后续阶段处理，先验证 Quest Browser 的 `immersive-ar`；若浏览器支持或权限不稳定，则保留 FastAPI/控制协议，改用轻量原生 Quest 前端。外部 Gemini 330 用于远程视角、遮挡补充和未来标定/数据采集，不是本次高响应仿真的依赖。

## 测试与验收

### 自动测试

1. 配置测试断言 Fake 参数为本设计的完整值，并断言真机模板仍为 `0.03 m/s`、前端不可覆盖。
2. 速度测试在 `50 Hz` 下验证 TCP 可达到 `0.30 m/s`，且单周期位移不超过 `0.006 m`。
3. PVAT 测试验证 `0.04 s` horizon、`1.5 rad/s` 关节速度和 `0.06 rad` 单步相互一致。
4. 约束分类测试验证软关节越界、IK 不可达和运动连续性分别产生不同消息。
5. 协议测试覆盖仿真倍率范围、步进、停止门禁、权威回执、持久化恢复和真机拒绝。
6. PC 输入测试覆盖左键机器人控制、右键相机环绕、右键不产生 Grip、复位视角和生命周期清理。
7. 单连接集成测试覆盖持续运动、Grip 松开、修改倍率、再次 Grip、反向退出软边界，全程无重连和硬故障。
8. 完整后端、完整前端和前端构建必须通过。

### 人工体验验收

1. 默认 `1.5:1` 下，手柄约 `10 cm` 位移对应约 `15 cm` TCP 目标位移；松开 Grip 后可按 `0.1` 步进调整并在下一次 Grip 生效。
2. 中等幅度快速移动时，机械臂不再呈现旧 `0.06 m/s` 的慢动作感。
3. 在普通工作区内连续前后、左右、上下以及姿态旋转，软约束不会无原因高频闪烁。
4. 真实越界时提示与根因一致；反向退回后自动恢复，无需复位。
5. 松开并再次按住 Grip 后继续从当前 TCP 跟随，不发生跳变或 `preflight_not_ready`。
6. PC 右键拖动可稳定环绕观察；右键操作不改变 Grip、手柄目标或机械臂状态，“复位视角”恢复默认观察点。

## 非目标

- 不修改真机现场速度或安全限制。
- 不通过网页按钮动态切换真机与仿真后端。
- 不关闭真实软关节限位、自碰撞、停止或失联保护。
- 不在本次实现 Quest 摄像头读取、WebXR MR 透视或原生 Quest 应用。
- 不在本次实现相机采集、时间同步落盘或训练数据集写入。
