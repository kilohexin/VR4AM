# VR4Arm 统一 GLB 运动学、笛卡尔跟手与方块抓取设计

日期：2026-07-22

## 1. 背景与根因

当前版本的后端 FK/IK 使用手写 MDH 模型，前端则把后端关节角直接应用到 `Lebai_LM3.glb` 的 `Joint1` 到 `Joint6` 节点。两者不是同一条运动学链。

诊断结果显示：后端从 Home 求解一个 TCP `+X` 方向 `0.05 m` 的目标时，数值 IK 可以在四次迭代内收敛，但相同关节角应用到 GLB 后，视觉 TCP 主要沿场景 `-Y` 方向移动约 `0.05 m`。两套位置雅可比不能通过单个刚体坐标变换对齐。因此当前问题不是简单的 IK 不收敛，而是后端认为已经到达的笛卡尔目标与用户在 VR 中看到的末端运动不是同一个运动。

本阶段必须先建立唯一运动学真源，再实现跟手控制和简单抓取。禁止继续通过交换坐标轴、增加 IK 迭代次数或扩大工作空间掩盖模型不一致。

## 2. 目标与范围

本阶段目标：

- 前端 GLB 渲染、后端 FK、后端雅可比和后端 IK 使用同一条 LM3 关节链；
- 右 Grip 锁定零位后，手柄前后、左右、上下与视觉 TCP 同方向连续运动；
- 末端位置优先，姿态在可行范围内跟随俯仰、偏航和滚转；
- 接近奇异位形或姿态不可完全满足时，保持位置跟手并柔和限制姿态，不进入锁存故障；
- 桌面上显示一个可由夹爪吸附、携带和释放的方块；
- 使用少量主体测试验证一次完整链路。

本阶段不包含：

- 乐白真机连接、真机自动回 Home 或真机速度参数；
- 重力、接触、摩擦、碰撞、刚体动力学或 Cannon-es；
- 抓取力、夹爪碰撞体或方块翻滚；
- 方块状态进入后端协议、相机数据或 VLA/ACT 数据集；
- Pinocchio、MoveIt、MuJoCo、Isaac Sim 或新的机器人学依赖。

## 3. 唯一运动学真源

新增版本化 JSON `config/lm3_visual_kinematics_v1.json` 作为仿真运动学真源。Python 后端读取该文件；TypeScript 机械臂加载器使用同一文件中的节点名称和关节轴。

配置固定包含：

- 六个关节节点 `Joint1` 到 `Joint6`；
- GLB 关节轴 `y, z, z, z, y, z`；
- GLB 节点的六组局部平移；
- 用户确认的 Home 关节角 `[0°, -45°, 90°, -45°, 90°, 0°]`；
- 每个关节相对 Home 的仿真安全窗口；
- `robotgrabber` 的局部平移和 GLB 中现有的固定旋转四元数；
- TCP 在夹爪坐标系中的固定偏移 `[0, -0.09, 0] m`；
- 工具前向为夹爪/双目摄像头坐标系的局部 `-Y`。

后端删除 `LM3Model` 对 MDH 参数 `a_prev_m`、`alpha_prev_rad` 和 `d_m` 的运行时依赖。新的 FK 按 GLB 层级顺序计算：先应用节点局部平移，再绕该节点局部关节轴旋转，最后应用夹爪固定变换和 TCP 偏移。

FK 输出的场景坐标约定与 WebXR/Three.js 一致：

```text
+X：用户右侧
+Y：竖直向上
-Z：用户/工作台前方
```

`RobotStateMessage.actual_tcp` 从本阶段起使用该场景坐标定义。协议字段不变，避免破坏未来相机和时间同步接口。

## 4. Grip 相对零位映射

Grip 上升沿同时记录：

```text
P_hand_0, R_hand_0
P_tcp_0,  R_tcp_0
q_actual_0
```

平移不再经过旧的机器人轴重排矩阵。WebXR 手柄位移直接进入与 GLB 相同的场景轴：

```text
P_tcp_target = P_tcp_0 + translation_scale * (P_hand - P_hand_0)
```

`translation_scale` 保持配置化，默认 `0.5`。因此手柄向前 `10 cm`，TCP 目标向场景 `-Z` 前进 `5 cm`；手柄向下对应 TCP `-Y`；手柄向右对应 TCP `+X`。

姿态使用手柄局部相对旋转：

```text
delta_hand_local = inverse(R_hand_0) * R_hand
delta_tool_local = C_hand_to_tool * delta_hand_local * inverse(C_hand_to_tool)
R_tcp_target = R_tcp_0 * scaled(delta_tool_local)
```

默认 `C_hand_to_tool` 把 Touch Plus 局部前向 `-Z` 映射到工具/摄像头前向 `-Y`，把手柄局部上方 `+Y` 映射到工具局部 `+Z`。矩阵为：

```text
[[-1, 0, 0],
 [ 0, 0, 1],
 [ 0, 1, 0]]
```

保留 `2°` 旋转死区和默认 `0.5` 旋转比例。Grip 松开立即停止并保持；再次按下时以当前实际 TCP 和实际关节角重新锁定，不产生目标跳变。

## 5. 位置优先的差分 IK 伺服

### 5.1 控制方式

移除仿真遥操作路径中“每帧从目标位姿求完整全局关节解”的做法。`command_tcp` 接口继续保留，但内部改为从当前实际关节角计算一个受限关节增量。

每个约 `20 ms` 控制周期：

1. 用共享 GLB FK 计算当前 TCP 位姿；
2. 计算位置误差 `e_p = P_target - P_current`；
3. 计算姿态误差旋转向量 `e_r`；
4. 从关节世界轴和关节原点构造几何雅可比 `J_p`、`J_r`；
5. 先求位置阻尼最小二乘解；
6. 再在位置任务零空间内求姿态修正；
7. 对单关节速度、整步关节增量和关节窗口进行限制；
8. 把下一步关节目标交给 `VirtualRobot`。

位置任务：

```text
qdot_position = damped_pseudoinverse(J_p) * clamp(Kp * e_p)
N = I - pseudoinverse(J_p) * J_p
```

姿态任务：

```text
A = J_r * N
qdot_rotation = N * damped_pseudoinverse(A)
                * (clamp(Kr * e_r) - J_r * qdot_position)
qdot = qdot_position + qdot_rotation
```

默认位置增益高于姿态增益。位置误差优先消除；姿态任务只能使用不明显破坏位置跟随的剩余关节能力。

### 5.2 连续性与奇异处理

- 每帧只积分一个小关节步，不使用多起点全局解，不允许跨解分支跳变；
- 阻尼根据 `J_p` 或 `A` 的最小奇异值增加，接近奇异位形时自动减慢；
- 姿态任务不可满足时降低姿态修正，不把普通姿态误差升级为红色故障；
- 位置超出软工作空间时保持最后有效目标并显示现有琥珀色提示；
- 实际关节已经越过硬安全窗口、输入存在 NaN/Infinity、连接失联或控制循环异常时，仍执行硬停止；
- 仿真关节速度和加速度保持配置化。本阶段可以为跟手体验使用比当前 `0.5 rad/s` 更响应的仿真值，但不代表真机参数。

### 5.3 跟手验收指标

在仿真 Home 附近：

- 手柄单轴移动时，视觉 TCP 主运动方向必须与手柄一致；
- 连续保持一个 `5 cm` 以内的位置目标时，TCP 位置误差应收敛到 `1 cm` 以内；
- 连续保持一个 `10°` 的姿态目标时，在位置仍满足 `1 cm` 的前提下把姿态误差收敛到 `4°` 以内；
- Grip 松开再按下，第一帧目标等于重新锁定时的实际 TCP；
- 普通小幅移动不得触发红色故障，也不得持续卡在错误的关节边界提示。

## 6. 方块抓取交互

方块完全位于前端场景，使用确定性的运动学吸附，不依赖物理引擎。

新增独立 `KinematicGraspController`，只依赖：

- GLB 的 `robotgrabber` 工具节点；
- 方块 `Object3D`；
- 后端返回的权威夹爪开合量；
- 桌面高度和抓取阈值。

方块初始边长为 `0.06 m`，放置在 LM3 可达的桌面前方区域。控制规则：

- 未吸附且夹爪与方块中心距离不超过 `0.07 m`；
- 夹爪闭合量从低值上升并达到 `0.65` 时吸附；
- 吸附后方块位于共享配置定义的 TCP/夹爪中心偏移，并随 `robotgrabber` 运动；
- 夹爪开合量降低到 `0.35` 以下时释放，使用迟滞避免阈值抖动；
- 释放时把方块重新挂回 `robotVisualRoot`，保留水平位置并把中心高度放到桌面顶面加半个方块高度；
- 方块水平位置限制在桌面范围内，避免落地后丢失；
- 页面重载或新建场景时恢复初始方块位置。

第一版不验证手指碰撞和接近方向；“靠近 + 闭合”就是可预测的抓取条件。后续数据采集阶段再把方块位姿和抓取状态加入后端时序记录。

## 7. 数据流

```text
Quest Touch Plus 位姿
  -> WebXR 原始 VRFrame
  -> FastAPI newest-only 输入
  -> Grip 相对零位目标
  -> 位置优先差分 IK（共享 GLB 运动学）
  -> VirtualRobot 关节状态
  -> RobotStateMessage.actual_q / actual_tcp / gripper
  -> Three.js 将 actual_q 应用到同一 GLB 关节链
  -> robotgrabber 世界位姿驱动方块吸附或释放
```

相机帧、时间戳和未来记录接口保持不变。

## 8. 简化测试与验证

按用户要求，只增加少量主体测试，不扩展复杂测试体系：

1. **共享 GLB 运动学测试**：读取同一 JSON，验证 Home FK 有限、已知单关节扰动方向与 GLB 关节链一致；
2. **笛卡尔伺服烟雾测试**：从 Home 连续执行有限次差分 IK 步骤，确认一个小位置加姿态目标的位置误差下降并达到阈值；
3. **方块抓取测试**：使用 Three.js 纯对象层级验证靠近闭合时吸附、工具移动时跟随、张开时释放并回到桌面高度。

实现完成后只运行上述定向 Python/Vitest 测试和一次 `npm run build`。不运行长时间 soak、不增加大规模随机 IK 测试，也不以测试结果代替 Quest 人工体验。

## 9. 实施顺序

1. 建立共享 GLB 运动学 JSON，并让 Python FK 与 TypeScript 关节映射读取它；
2. 以失败测试证明现有 MDH FK 与 GLB 目标不一致；
3. 实现共享 GLB FK、几何雅可比和位置优先差分 IK；
4. 把仿真 `command_tcp` 切换到差分 IK 伺服；
5. 简化 Grip 坐标映射到 Three.js/WebXR 场景轴；
6. 实现方块和 `KinematicGraspController`；
7. 运行三项主体测试和一次前端构建；
8. 重启服务，交用户在 Quest 中验收跟手和抓取体验。

## 10. 后续真机边界

本设计保证当前 GLB 仿真的 FK、IK 和显示一致，不声称该 GLB 链已经等同于 LM3 真机标定模型。接入真机时，应优先调用乐白 SDK 的权威正逆解或笛卡尔伺服，并建立“真机关节角到 GLB 节点角”的零位、符号和单位标定。仿真控制参数不能直接复制到真机。
