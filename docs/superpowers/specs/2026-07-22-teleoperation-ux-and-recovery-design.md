# VR4Arm 遥操作体验与故障恢复改进设计

日期：2026-07-22

## 1. 背景与目标

当前版本已经能够通过桌面输入和 Quest 3 原厂手柄驱动 LM3 运动学仿真，但人工体验暴露出四个相互关联的问题：

1. 右手柄与末端运动方向不符合用户直觉；
2. “目标超出工作空间”会因普通操作进入锁存故障；
3. 故障复位只清状态，不把仿真机械臂恢复到稳定初始姿态；
4. 左手摇杆只能调节工作台高度，无法在三维空间中摆放工作台。

本次改进首先服务于纯 VR/桌面运动学仿真，不连接真机。目标是让用户感觉自己在“直接握持机械臂末端”，并将普通操作边界与真正系统故障分开。

## 2. 本次范围

本次包含：

- 右手柄相对零位的六自由度末端控制；
- 用户直觉方向的前、后、左、右、上、下映射；
- 左手摇杆对虚拟工作台的三维摆放；
- 工作空间软边界与不可达目标的非锁存处理；
- 仿真故障复位后低速返回 Home；
- 控制参数从 YAML 配置真正传入控制组件；
- VR 内必要的状态提示和可用时的手柄振动反馈。

本次不包含：

- Cannon-es 或其他浏览器物理引擎；
- 重力、摩擦、碰撞、接触或真实抓取动力学；
- 真机自动回 Home；
- 乐白真机使能；
- 相机采集和数据集落盘实现。

相机帧、时间戳和未来数据记录接口继续保留，不因本次改动删除。

## 3. 右手相对零位控制

### 3.1 零位锁定

右手 Grip 是控制离合器，也是零位锁定动作。Grip 从松开变为按下时，系统同时记录：

- 当前右手柄位置 `P_hand_0`；
- 当前右手柄姿态 `R_hand_0`；
- 当前实际 TCP 位置 `P_tcp_0`；
- 当前实际 TCP 姿态 `R_tcp_0`；
- 本次操作使用的用户方向基准。

锁定瞬间不得产生目标跳变。Grip 松开时机械臂停止并保持当前位置；再次按下时，以当前手柄和当前实际 TCP 建立一组新零位。

### 3.2 平移语义

目标位置不是速度积分，而是相对零位的绝对映射：

```text
P_tcp_target = P_tcp_0 + scale_translation * map(P_hand - P_hand_0)
```

映射必须满足人工可感知的语义：

- 手柄从零位向用户所见前方移动，TCP 从锁定位置向相同视觉方向移动；
- 手柄向右，TCP 向右；
- 手柄向下，TCP 向下；
- 反方向运动完全对称；
- 手柄回到零位，TCP 回到锁定时的 TCP 位置。

竖直方向始终采用世界竖直轴，不随用户低头或抬头倾斜。Grip 锁定时，把头显本地 `-Z` 轴投影到水平面作为 `user_forward`，以 `cross(user_forward, world_up)` 作为 `user_right`。手柄位移先分别投影到 `user_forward`、`user_right`、`world_up`，然后确定性映射为机器人语义轴 `base +X`、`base -Y`、`base +Z`。GLB 默认摆放必须使这三个机器人语义轴在用户视野中分别表现为前、右、上；若模型资产存在差异，只允许通过配置中的离散轴置换/符号校准修正，不能在控制过程中动态猜测方向。

默认平移比例改为 `0.5`。该值必须来自配置，不能继续只写在 YAML 而不进入运行时。

### 3.3 旋转语义

末端姿态采用相对旋转：

```text
R_tcp_target = map(R_hand * inverse(R_hand_0)) * R_tcp_0
```

手柄俯仰、左右偏航和绕自身前向轴旋转，应分别表现为夹爪同方向俯仰、偏航和腕部滚转。旋转采用约 `2°` 的输入死区和默认 `0.5` 比例，降低自然手部抖动对完整六自由度 IK 的影响。

## 4. 左手三维工作台摆放

左手输入只操作 VR 中的 `robotVisualRoot`，不得改变后端坐标、机器人关节状态、IK 目标或发往未来真机的命令。

采用已确认的方案 1：

- 未按左 Grip：
  - 摇杆左右控制工作台左右；
  - 摇杆前后控制工作台前后；
- 按住左 Grip：
  - 摇杆左右继续控制工作台左右；
  - 摇杆前后改为控制工作台上下；
- 按下左摇杆：恢复工作台默认三维位置。

工作台摆放只在系统处于锁定、停止或故障且右 Grip 已松开时启用。ACTIVE、HOLD、正在解锁和正在复位期间忽略该输入。

实现需要读取左摇杆 X/Y、左 Grip 和摇杆按压。三轴位移使用 `0.2` 摇杆死区、时间步进和 `0.1 s` 最大时间步。水平速度默认 `0.6 m/s`，竖直速度保持 `0.35 m/s`；人工左右和前后偏移分别限制在默认位置的 `±1.2 m`，人工高度偏移限制在 `±0.6 m`，最终工作台高度继续限制为 `0.30–1.40 m`。三轴人工偏移保存到浏览器本地存储。进入新 VR 会话时恢复偏移，离开 VR 时恢复桌面页面的默认视觉位置。

## 5. 工作空间软边界

### 5.1 当前问题

现有 `SafetyLimiter` 把每次 Grip 锁定的 TCP 位置作为中心，并对每个机器人轴应用 `±0.25 m` 立方体限制。以当前 `0.8` 平移比例计算，VR 手柄单轴移动约 `31.25 cm` 即会触发 `workspace_violation`。桌面鼠标约 260 像素拖动或数次滚轮操作也可能触发。

这个立方体不是真实 LM3 工作空间：它会拒绝仍然可达的目标，也不能保证立方体内目标一定可达。更严重的是，任何单帧越界都会进入锁存故障。

### 5.2 新行为

“目标超出工作空间”从锁存故障降级为软约束。

- 单次零位操作范围使用各向同性的相对位移半径，默认目标半径为 `0.45 m`；
- 超过半径的请求投影到边界，不抛出 `SafetyViolation`；
- TCP 停留在边界或最后一个有效目标；
- 用户将手柄移回有效区域后自动继续，无需复位；
- VR HUD 显示“已到达操作边界”；
- Quest 支持振动时以不高于每 `300 ms` 一次的频率提供约 `40 ms`、强度约 `0.35` 的短振动，不能每帧连续振动。

如果目标在相对范围内但 IK 返回 `ik_unreachable`、`ik_singular` 或命令目标会超过仿真关节窗口，本帧同样保持最后一个有效目标，并发布软约束状态。单帧或持续普通不可达不得清除解锁状态，不得要求用户复位。

软约束状态至少区分：

- `workspace_boundary`：相对操作范围达到边界；
- `ik_boundary`：目标暂时不可达或 IK 未收敛；
- `joint_boundary`：请求目标将超过仿真关节范围。

软约束在目标连续有效 `100 ms` 后自动清除；控制命令本身不等待该稳定窗口，只有提示状态延迟清除，以避免闪烁。

### 5.3 仍然保留的硬安全机制

以下情况仍然立即停止并进入锁存故障或失联停止：

- WebXR 跟踪无效、页面隐藏或输入超时；
- WebSocket 断开；
- NaN、Infinity、无效四元数等非法数值；
- 控制循环异常或后端不可用；
- 机器人后端报告真实故障；
- 实际状态已经越过硬关节限制。

现有线速度、角速度、线加速度和角加速度限制继续保留。它们用于让运动平滑，不应因工作空间改造而被删除。

## 6. IK 连续性

仿真 IK 优先使用上一次成功的目标关节解作为下一帧种子，而不是仅使用仍在追赶目标的实际关节位置。这样可以提高连续手柄轨迹中的解分支稳定性。

IK 失败的处理顺序为：

1. 不向虚拟机器人提交失败目标；
2. 保持上一次有效关节目标；
3. 发布对应软约束；
4. 用户返回有效区域后继续。

IK 数值异常与普通不可达必须分开。由非法输入导致的数值异常属于硬故障；有限且合法目标的未收敛属于软约束。

## 7. 真正的仿真复位过程

当前复位只停止、清故障、清映射和解除使能，因此通常在一次 WebSocket 往返内完成，没有可见运动过程，也没有改变机械臂姿态。

新复位流程为：

```text
FAULT/DISARMED
  -> STOPPING
  -> HOMING
  -> HOME_STABLE
  -> 清除故障和软约束
  -> DISARMED/等待重新解锁
```

复位要求右 Grip 已松开。仿真后端使用关节空间低速运动到 LM3 Home：

```text
[0°, -45°, 90°, -45°, 90°, 0°]
```

该姿态对应用户确认的收拢、末端水平初始姿态。回程不经过笛卡尔 IK，仿真最大关节速度设为 `0.25 rad/s`，单次回程超时为 `15 s`。只有当最大关节误差小于约 `1°`、最大关节速度小于 `0.02 rad/s`，并持续稳定约 `300 ms` 后，才接受复位完成并清除故障。

界面按阶段显示“停止中”“正在回到初始姿态”“复位完成”。如果回 Home 超时或仿真后端异常，保持锁定并显示复位失败，不得部分清除故障。

真机后端本次仍然禁用自动回 Home。未来真机实现必须将“清故障”和“自动回安全姿态”拆分，并经过无负载、低速和碰撞风险评估。

## 8. 协议与状态兼容

现有原始右手柄位姿继续保留，避免破坏未来 VLA/ACT 数据采集价值。`VRFrame` 在兼容 v1 消息的前提下增加可选原始头显四元数 `head_q`；Quest 每帧发送该字段，Grip 锁定时由后端计算并保存水平用户基准。桌面输入省略 `head_q`，后端使用与桌面相机默认方向一致的单位头显姿态。该字段只新增为可选字段，不改变现有右手柄原始位姿的语义。

`robot_state` 可增加可选软约束字段。它与 `fault` 分离：

- `fault != null` 表示要求停止/复位的硬故障；
- `constraint != null` 表示仍可保持解锁、退回后自动恢复的软边界。

新增字段采用可选默认值，避免现有 v1 消息和录制接口立即失效。

## 9. 物理仿真取舍

Cannon-es 从近期路线图移除。当前只保留：

- LM3 FK/IK；
- 虚拟关节运动；
- 夹爪视觉动画；
- 工作台、目标标记和控制提示。

如未来只需要演示抓取流程，可以单独增加轻量“靠近后附着”逻辑；如需要有研究价值的接触或合成数据，应评估 MuJoCo 或 Isaac Sim，而不是把浏览器游戏物理作为真实抓取依据。

## 10. 人工验收标准

按用户要求，本次实现不新增、不运行自动化测试，由用户启动程序进行体验验收。建议按以下顺序检查：

1. 锁定零位后，右手向前、后、左、右、上、下移动，TCP 视觉方向完全一致；
2. 手柄回到零位时，TCP 回到锁定时位置；
3. 松开 Grip 后保持，再次按下时无目标跳变；
4. 手柄俯仰、偏航和滚转时，夹爪方向符合直觉；
5. 左摇杆能摆放工作台的前后左右，左 Grip 修饰后能调节上下；
6. 到达相对工作边界时机械臂停在边界，只提示和振动，不进入故障；
7. 手柄退回后立即恢复，不需要点击复位；
8. 真正硬故障仍会停止并锁定；
9. 点击复位后可看到机械臂低速回到 Home，完成后再允许重新解锁；
10. 不出现 Cannon-es、物体动力学或浏览器物理依赖。

## 11. 实施顺序

1. 接通配置参数并建立软约束状态；
2. 改造工作空间和 IK 失败处理；
3. 实现右手相对零位和可校准方向映射；
4. 扩展左手输入并实现三维工作台摆放；
5. 实现仿真关节空间回 Home 与复位阶段反馈；
6. 更新 HUD、VR 提示和使用文档；
7. 交由用户运行程序并提供体验反馈。
