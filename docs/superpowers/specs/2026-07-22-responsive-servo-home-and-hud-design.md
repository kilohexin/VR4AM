# 快速跟手伺服、标准 Home 与 VR HUD 设计

## 1. 目标

本阶段解决当前 Quest 遥操作的三个直接体验问题：

- 消除微分 IK 与虚拟关节位置控制串联造成的“慢动作”，让 TCP 以 1:1 位移和姿态跟随右手柄；
- 将启动和复位后的标准 Home 定义为两指左右排列、双目摄像头在上，并允许用户在没有故障时主动返回 Home；
- 将 VR HUD 上移到操作区外，并在 HUD 中完整显示 A、B、Grip 和 Trigger 的按键语义。

本阶段继续只运行浏览器仿真。不得启用 `LebaiRobotAdapter`、导入乐白 SDK 或向真机发送命令。

## 2. 已确认根因

当前 `cartesian_servo_step()` 从实际关节角计算一个 20 ms 的下一步关节目标。最大关节速度为 `1 rad/s` 时，这个目标通常只比实际关节角超前约 `0.02 rad`。

`SimRobotAdapter` 又把这个单步目标传给 `VirtualRobot.set_target_q()`。`VirtualRobot.step()` 使用 `desired_qd = 2 * (target_q - q)` 再做一次位置伺服，因此 `0.02 rad` 的目标误差只产生约 `0.04 rad/s` 的关节速度，即原本 `1 rad/s` 速度命令的约 4%。这层重复积分是主要慢动作来源。

此外，当前默认 `translation_scale=0.5`、`rotation_scale=0.5`、旋转死区 `2°`，以及 `0.15 m/s`、`0.6 rad/s` 的保守笛卡尔限速进一步降低了主观跟手性。

## 3. 单层关节速度伺服

### 3.1 控制结构

微分 IK 负责根据当前实际关节角和目标 TCP 位姿计算期望关节速度 `qd_command`。`SimRobotAdapter.command_tcp()` 将该速度交给 `VirtualRobot` 的速度模式，而不是把一个 20 ms 单步结果再次当作长期位置目标。

```text
Quest 手柄位姿
  -> Grip 锚定的 1:1 TCP 目标
  -> 工作空间投影、笛卡尔限速与滤波
  -> 位置优先微分 IK
  -> qd_command
  -> VirtualRobot 单次加速度限制与积分
  -> actual_q / actual_tcp
```

`VirtualRobot` 有两个互斥模式：

- `velocity`：遥操作时跟踪 `qd_command`，在自身 50 Hz 更新中只积分一次；
- `position`：Home 时继续使用受限关节位置控制。

`stop()` 清除两种目标并减速到零。进入 Home 时先停止，再切换到 `position`；Home 完成后保持停止状态，不能自动重新解锁。

### 3.2 限制与仿真参数

仿真专用默认值调整为：

| 参数 | 数值 |
|---|---:|
| 控制频率 | `50 Hz` |
| 状态回传频率 | `50 Hz` |
| 平移比例 | `1.0` |
| 旋转比例 | `1.0` |
| 旋转死区 | `0.5°` |
| TCP 最大线速度 | `0.30 m/s` |
| TCP 最大线加速度 | `1.2 m/s²` |
| TCP 最大角速度 | `1.5 rad/s` |
| TCP 最大角加速度 | `4.0 rad/s²` |
| 最大关节速度 | `1.5 rad/s` |
| 最大关节加速度 | `4.0 rad/s²` |

这些值仅属于模拟器体验配置。未来真机接入必须使用独立且更保守的参数，不得直接复用。

状态回传从 `20 Hz` 提高到 `50 Hz`，使浏览器每个控制周期都能获得新的实际关节状态，减少 Quest 画面的阶梯感。单控制端下该 JSON 状态流量很小，不引入多观察端广播。

关节速度、关节加速度和关节窗口继续为硬限制；工作空间边界、普通姿态受限和接近奇异位形继续作为软约束。位置优先于姿态，姿态暂时无法完全满足时不得让平移失去响应，也不得仅因姿态误差进入硬故障。

## 4. Grip 锚定的 1:1 位姿映射

按下右 Grip 的瞬间记录：

- 手柄锚点位置 `p_hand_0` 和姿态 `R_hand_0`；
- 实际 TCP 锚点位置 `p_tcp_0` 和姿态 `R_tcp_0`；
- 姿态偏置 `R_offset = inverse(R_hand_0) * R_tcp_0`。

持续按住 Grip 时：

```text
p_tcp_target = p_tcp_0 + (p_hand_now - p_hand_0)
R_tcp_target = R_hand_now * R_offset
```

该映射把手柄视为刚性连接在夹爪上的控制把手：手柄平移 10 cm，TCP 目标平移 10 cm；手柄滚转、俯仰或偏航多少，夹爪目标就旋转多少。按下 Grip 时使用实际 TCP 建立偏置，因此不会发生目标跳变。松开 Grip 后停止，再次按下时从新的实际位姿重新锚定。

保留 `0.5°` 小死区以抑制静止手抖，但死区之外不再缩小旋转角度。

平移增益继续由单一配置项 `translation_scale` 控制，默认值为 `1.0`；需要精细操作或快速覆盖时可以在启动前显式配置为其他固定正数，但本阶段不增加 VR 内动态切换。姿态比例固定为 `1.0`，不允许放大或缩小。不得使用随位移变化的非线性增益，以保持人体动作、机械臂动作和未来采集数据之间的对应关系可解释。用户通过松开并重新按下 Grip 多次锚定，在舒适的手臂活动范围内覆盖更大的机械臂工作空间。未来启用数据记录器时，必须把本次会话实际使用的固定 `translation_scale` 写入会话元数据；本阶段继续使用 `NoopRecorder`，不新增数据集写入。

## 5. 标准 Home 姿态

GLB 中工具局部轴的实际含义为：

- TCP/摄像头光轴前向：工具局部 `-Y`；
- 两指开合方向：工具局部 `+Z/-Z`；
- 摄像头相对夹爪的上方：工具局部 `-X`。

现有 Home 下，工具局部 `+Z` 映射到世界竖直方向，表现为两个夹爪上下排列。保持 TCP 位置和摄像头光轴不变，将第六关节 Home 角减少 `π/2`：

```text
home_q = [0, -π/4, π/2, -π/4, π/2, -π/2]
```

这样工具局部 `-X` 映射到世界 `+Y`，摄像头位于正上方；工具局部 `Z` 位于水平面内，两个夹爪左右排列。由于旋转轴与工具前向共线，修改第六关节不会改变标准 Home 的 TCP 位置和夹爪指向。

启动和任何 Home 流程都使用该关节姿态。普通 Grip 重新锚定不得自动回到 Home。

## 6. 主动返回 Home

### 6.1 B 键状态语义

保留 B 键作为最高优先级停止输入，并增加停止后的 Home 语义：

| 当前状态 | B 键行为 |
|---|---|
| `ACTIVE`、`ARMED` 或 `HOLD` | 立即停止并进入锁定/停止状态 |
| 已停止或未解锁，Grip 已松开 | 请求主动返回 Home |
| 可恢复故障，Grip 已松开 | 执行故障复位并返回 Home |
| Home/故障复位进行中 | 忽略重复请求 |
| Grip 按住 | 禁止 Home，只允许先停止 |

因此，从运动状态主动回 Home 的操作是：按 B 停止，松开 Grip，再按 B 回 Home。

### 6.2 协议和后端

协议 v1 增加向后兼容的 `home_request` 与 `home_result` 消息，不改变现有 VR 帧、相机和时间同步接口。主动 Home 与故障复位共享后端的“确认停止—返回 Home—确认稳定”执行器，但语义分离：

- `home_request` 只在无故障、控制循环可用且逻辑状态已停止时接受；执行器随后再次发送停止命令并等待实际关节速度稳定到零，再开始 Home；
- `reset_fault` 继续只处理允许在线复位的硬故障；
- 两者都更新已有 `recovery_phase`；
- Home 成功后清除 mapper、滤波器、动态限速器和旧目标，保持 `DISARMED`；
- Home 失败则保持停止和锁定，返回明确拒绝原因，不自动解锁。

## 7. VR HUD

状态牌仍为世界固定、始终朝向相机的 Sprite，但从当前 `(-0.82, 1.18, -0.58)` 上移并稍向后放置到：

```text
position = (-0.82, 1.52, -0.72)
scale = (1.15, 0.2875, 1)
```

该位置位于用户视野左上方，避开夹爪、方块和主要工作空间。HUD 底部固定显示：

```text
A 解锁 · B 停止/回 Home · Grip 移动 · Trigger 夹爪
```

主提示根据状态补充：

- 运动中：`松开 Grip 停止 · B 紧急停止`；
- 已停止：`保持 Grip 松开：A 解锁，B 回 Home`；
- Home 中：`正在返回 Home，请保持 Grip 松开`；
- 可恢复故障：`松开 Grip，按 B 复位并回 Home`；
- 操作边界：保持现有琥珀色软约束提示。

桌面网页按钮在已停止状态显示“回到 Home”，运动或已解锁状态仍显示“停止”。

## 8. 安全和并发

- B 键第一次操作在所有已解锁状态下必须仍然只执行停止，不能直接启动 Home；
- Home 前必须确认 Grip 松开、无并发解锁请求；后端负责等待实际运动完全停止，用户快速按第二次 B 时不因短暂减速过程直接拒绝请求；
- Home 过程中禁止解锁、Grip 运动和重复 Home；
- 新会话、断线、数据过期或隐藏页面仍优先停止；
- 所有速度和姿态体验更改仅在 `backend: simulator` 生效；
- 真机适配器继续拒绝全部运动命令。

## 9. 聚焦验证

按用户要求只做主体功能的简短验证：

1. 速度单元用例：速度模式在 50 Hz 下只积分一次，并遵守关节速度/加速度限制；
2. 坐标映射用例：Grip 锚点无跳变，10 cm 平移和 30°旋转均为 1:1；
3. Home 用例：第六关节为 `-π/2`，TCP 位置与旧 Home 一致，摄像头向上且夹爪开合轴水平；
4. 主动 Home 用例：运动中第一次 B 只停止，停止且 Grip 松开后的第二次 B 才进入 Home；
5. HUD 用例：状态提示包含完整按键说明，Sprite 使用新位置；
6. 运行后端上述聚焦测试、前端对应聚焦测试和一次生产构建。

最终由用户在 Quest 中体验跟手速度、1:1 姿态、标准 Home、主动 Home 和 HUD 遮挡情况。

## 10. 不在本阶段范围

- 真机控制或真机速度参数；
- Cannon-es、碰撞、重力或刚体动力学；
- 相机采集和数据集写入；
- MR 透视、手势识别或新增控制器型号；
- 自动避障或全局轨迹规划。
