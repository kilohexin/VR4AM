# VR4Arm 工具坐标系与 IK 连续性修正设计

日期：2026-07-22

## 目标

让右手柄的姿态控制遵循夹爪双目摄像头的工具坐标系，并消除 Grip 重新锁零位后由陈旧 IK 种子造成的持续“已到达关节操作边界”。本次仍只修改仿真遥操作，不启用真机，不增加物理仿真。

## 坐标语义

- 平移继续使用 Grip 锁定时的水平头显基准：手柄前后、左右、上下对应用户看到的前后、左右、上下。
- 姿态不再使用手柄世界坐标旋转增量，而使用锁定姿态下的手柄局部旋转增量 `R_hand_0^-1 * R_hand`。
- WebXR 手柄的局部前向为 `-Z`，LM3 仿真 TCP/摄像头光轴前向为 `+Z`。默认手柄到工具的固定校准是绕局部 `Y` 轴旋转 `180°`，即 `diag(-1, 1, -1)`。
- 工具目标姿态为 `R_tcp_0 * R_hand_to_tool * delta_hand_local * R_hand_to_tool^-1`。因此手柄前伸只影响平移；手柄绕自身前向翻滚时，夹爪绕摄像头光轴翻滚。

## IK 连续性

- 正常连续跟随仍使用上一条成功关节目标作为下一帧 IK 种子，保持解分支稳定。
- 后端已停止、Grip 松开或会话重新开始后，下一条 TCP 命令必须从仿真机械臂的实际关节角起算，不能沿用停止前尚未执行到的关节目标。
- `stop()` 同步保存实际关节角；当虚拟机器人没有活动关节目标时，`command_tcp()` 再次从当前实际关节角同步一次，覆盖快速松开/重新按下期间的减速位移。

## 关节边界分类

- IK 种子本身已经在安全窗口外仍报告 `joint_safety_window`。
- IK 的单次中间迭代越过安全窗口时，将候选关节角投影到窗口内并继续求解，不立即报告边界。
- 迭代结束仍未收敛且最终解确实停在关节窗口边缘时，报告 `joint_safety_window`；否则报告 `ik_unreachable`。
- 两者都保持现有琥珀色软约束行为，用户把手柄移回可达区域即可恢复，不需要复位。

## 人工验收

按用户要求，不新增、不修改、不运行自动测试，也不运行构建或程序。用户在 Quest 中重点验证：Grip 锁零位无跳变、前后左右上下方向、摄像头光轴翻滚、快速松开再按下、普通小幅移动不再持续出现关节边界，以及真实边界仍显示琥珀色软提示。
