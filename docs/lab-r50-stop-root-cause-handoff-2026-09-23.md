# R50：停止位移根因核对（仅离线，不接真机）

目标是尽快给 R51 真机 VR 动作做可判定的准入决策；**本文件不授权真机运动、系统停止、复位或修改保护策略**。实验室 AI 只处理既有 R37/R41 原件，不重新触发已复现的位移。

## 已知事实与待验证假设

- R37：`stop_move` 在 200 ms 等待窗超时，约 625 ms 才迟到返回；约 204 ms 启动 `stop_sys`，约 1797 ms 才返回。主要反向位移出现在其后，停止前目标基本冻结。先后时序**不等于因果证明**。
- R41：静止 `IDLE` 基线单独调用一次 `stop_sys`，未先发运动，仍记录最大约 5.804 mm、末值约 5.485 mm 的偏离，主要在 J3。该结果使“必须先有 PVAT 运动才会位移”的解释不成立。
- 乐白官方 [系统控制说明](https://help.lebai.ltd/sdk/system.html) 将 `stop_sys` 描述为“先停止手臂运动，再禁用关节运动”；[运动接口说明](https://help.lebai.ltd/sdk/motion.html) 将 `stop_move` 描述为停止已有运动，但不能取消之后新发指令。**推断**：系统停止/关节使能切换可能与位移相关；目前不能判断是否为重力、制动、负载/安装参数或固件行为。
- R49 只覆盖假 SDK 断连后空闲 `control_overrun`；不覆盖上述真机停止链。

## 实验室 AI 本轮任务

1. 从既有 R37 和 R41 归档原件各自复算：请求/完成时间、`raw_robot_state`、逐轴 `actual_q`/`target_q`、`actual_qd`、TCP、可用的关节力矩与目标力矩，特别标出首次位移相对 `stop_sys` **请求**和**返回**的时间。列清“读取开始/读取完成”的时间口径与采样间隔，不能把两个非原子快照拼成同一时刻。
2. 对照两轮：R37 的 `stop_move` 迟到 + 自动 `stop_sys`，与 R41 的单独 `stop_sys`。给出共同点、不同点、仍无法区分的因果解释；不得写成“已证实停使能导致下坠”。
3. 整理一份可直接提交乐白技术支持的问题：在 SDK 0.3.13、连续 PVAT 控制场景下，`stop_move` 200 ms 无应答但后来返回时，厂商推荐的**受控停止与超时处置**是什么？`stop_sys` 禁用关节运动时是否可能产生实测的 J3/TCP 位移？需核查哪些安装、负载、重力、制动或固件信息？可否提供有界、可验证且不禁用关节的保护路径？
4. 回传原始件哈希、复算脚本/输出、厂商问题稿。缺少控制器固件或安装参数时标“未知”，不要为凑字段连接设备、调用 SDK 或猜值。既有只读 `get_payload=0.65 kg`、`cog=(0,0,0.05)m`、`get_gravity=(0,0,-9.8)` 可并列记录，但其坐标系/有效性未经独立核实。

## R51 条件

R50 不是一次新的动作额度。只有保护方案的行为和失败分支明确、离线回归通过，并取得真机停止效果的**独立验证**后，才能另发 R51 真机 VR 小幅动作授权；若缺任一项，R51 不自动变成运动轮。不得通过增大 200 ms 截止时间、删除 `stop_sys` 升级或跳过 Grip 松开停止来换取演示视频。
