# 网页与 VR 操作流程修复（2026-10-27）

## 范围与结论

按用户最新要求，仅离线开发。此前网页现场授权已撤回，未生成执行材料、未启动真机服务器、未初始化 SDK。本轮修复解锁与停止收尾之间的前端状态冲突，不改变运动、停止验证或故障锁存判据。历史 stop_unverified 及夹爪未知结果没有被清除或重新判定。

## 已定位的问题

后端原本会在 disarm 事务返回后发送带 request_id 的 disarm_ack，前端却没有消费它。停止尚在收尾时，READY 状态与释放输入就可能重新开放解锁；进入 VR 时的本地锁重置也会掩盖尚未完成的停止。新解锁请求还可能被旧 ACTIVE 状态误认为已经成功。这使页面按钮与后端实际可接受的操作不一致。

现改为明确流程：

1. 任何网页、VR 或有限输入异常发起的停止，立即记录请求身份，撤销本地准备及操纵权限。
2. 等待期间显示“等待停止确认”，不允许解锁或准备；第二次停止不会被解释为 Home。
3. 仅匹配最新请求的 disarm_ack 可以结束等待；旧请求、非法报文和旧连接回执不能解除等待。
4. 回执本身不授予控制权。随后必须收到新的 READY 状态和释放输入，才能重新解锁，再独立进入准备姿态。
5. VR 本地锁重置保留尚未完成的停止；新的连接生命周期仍清理旧请求身份。

正常有限小步松手完成当前目标，不走上述显式停止流程；同一输入端正常移动、开合后保留已准备状态。VR 面板同步显示停止确认、小步规划/执行/自然收尾，并说明 Grip 松开完成当前步、B 请求停止。故障与数据陈旧提示保持优先。

disarm_ack 仅表示软件停止事务已返回，不等于物理静止证明。故障锁存仍阻止解锁，未新增自动恢复、复位或重试。

## 本轮验证

- 前端 33 个文件、502 项测试通过；新增回归先观察失败再修复，覆盖回执匹配、重复停止、本地 VR 重置、故障保留、过早解锁及界面提示。
- TypeScript 检查与 Vite 构建通过，保留既有超过 500 kB 的包体警告。
- 后端操作事务定向测试 12 项通过，包括准备期间接收停止及回执；没有运行后端全集。pytest 提示本机缓存目录无写权限，不影响断言结果。
- 实际 Edge 页面连接实际 WebSocket/生产后端，后端仅注入内存 Fake：解锁、准备、停止后立即尝试解锁、等待回执、再次解锁/准备、升降松开、夹爪按压松开，全流程通过。停止等待时即使程序化触发点击，也不发送提前解锁请求。夹爪回执人为延迟 120 ms，停止调用延迟 100 ms。
- 合成 Quest 输入经过实际 XRSessionController、ArmPanel、有限输入模块与 TeleopSocket：进入 XR 后由产品界面等待停止确认，再按 A 解锁/准备；两次相反平移各自松手自然到位，Trigger 开合取得两次回执，B 后未准备不能产生新目标。测试驱动不再额外等待停止回执来绕过界面缺口。
- 两组整链均没有控制故障、运动未知结果或原生 SDK 加载。它们不验证真实控制器、物理停止或头显呈现。

本机证据目录为 `.tmp/ui-unlock-logic-20261027/`，最终页面记录 `browser-2026-10-26T16-24-31-825Z.json`，最终 XR 记录 `result-2026-10-26T16-25-13-453Z.json`（文件名时间为 UTC）。原始输出保持本机，不提交。
