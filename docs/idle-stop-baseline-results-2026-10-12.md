# 仅限 IDLE 的单次停止基线入口

日期：2026-10-12，Asia/Shanghai。基线：`ed03d7085a188fb1383f5f04bf5fa5cadba87a37`。

## 完成的软件

新增 `backend/app/commissioning/idle_stop_baseline.py` 和 `scripts/real_robot_idle_stop.py`，用于现有 Wi-Fi 下的静止基线，不要求有线或原厂材料。默认只输出离线预览；没有任意动作、夹爪、Home 或目标 IP 的命令行选项。

专用入口直接复用生产 `RealLebaiAdapter.stop`、`StopTransaction`、SDK 锁与稳定验证，不构造 RobotControl，也不沿通用 smoke 的清理路径发首次停止。

连接后的完整 preflight 和两份只读观察必须符合原始 IDLE、健康与几何条件。诊断额外要求报告的六个关节速度均为零，完整样本年龄小于 100 ms，时间顺序有效，位置变化不超过原停止验证的关节/TCP 漂移容差。该零速度要求只决定诊断准入，没有改动生产停止速度容差；零报告速度仍不是物理静止证明，现场目视确认必须独立提供。

## 写入与清理边界

客户端代理只委托固定读取方法，仅允许一次 `stop_move` SDK 入口，其余调用禁止。即使 SDK 方法存在，也不能借能力检测授权运动或夹爪写入。

在 StopRpc 创建的异步任务内部、进入 native SDK 前，再次检查绑定材料、有效期、owner 取消状态、记录器健康、最新缓存 preflight 和样本年龄。因此记录失败、状态改变、锁等待、取消或授权过期不能靠清理补发首次写入。

取消发生在本地停止任务已创建但尚未进入 SDK 时，仍保持零 SDK 写入；若已进入 SDK，沿原未确认停止锁存处理，没有重试。代理在清理前撤销权限，不会以断开/异常收尾发第二次独立 SDK 停止。

复用 adapter 的私有快照/preflight 和本地资源字段进行同步检查，这是仓库内诊断的明确依赖；相关源码纳入预览散列并由回归保护。本地 pump/引用释放不代表 native SDK 网络连接已经关闭，报告保留 `native_connection_release_verified=false` 和独立 CLI 进程退出要求。原始停止理由沿用 `grip_released` 枚举，workflow 明确标为静止诊断，不能解释为真实 VR Grip 操作。

## 原停止验证与尾段

原 200 ms RPC 等待、300 ms 稳定窗口、500 ms 验证预算，以及 `stop_unverified` / `stop_incomplete` 保持。没有增大期限、自动 `stop_sys`、复位、Home 或恢复控制权限。

代理另记录权限/文件核对结束后的 native 调用开始与结束 QPC，最终结果给出 `native_sdk_await_qpc_ms`。原 StopRpc 期限仍包含准入检查开销，没有据此延长。该值在取消时表示本地 await 退出，不代表收到控制器回复；没有调用时保留未知。

一次 SDK 停止进入后，正常或失败都沿原只读观察采集 2 秒尾段；取消时优先退出，不强行延长为尾段采集。专用尾段包装器额外核对原始 IDLE、零报告速度、样本时序与位置连续性。任何异常样本保存到 `idle_stop_tail_rejected`，永久令本次基线失败，不追加停止。

`stop_confirmed` 是原事务完成当时的验证结果；之后尾段异常仍会令 `complete=false` / `tail_rejected=true`。没有改写生产锁存来伪造诊断故障或清除既有故障。记录器关闭失败也使最终返回结果失败；命令行的 `result.json` 是关闭记录器后的最终结果，日志中的结果事件发生在记录器关闭前。

## 材料绑定与默认预览

预览绑定固定目标、配置字节、运行源码、SDK 二进制、输出目录、唯一允许写入、原期限和固定 UTC 截止。执行要求确认串、预览文件散列和精确一致的有效期；独立修改 CLI 时间不能延长旧批准。有效期必须当前未过期且距当前不超过 10 分钟。

配置解析前后再次比较字节，避免把旧解析出的目标绑定到新文件散列。批准材料一次读出并同时用于散列与 JSON 校验。输出目录以独占方式创建；连接失败也消耗该次目录，不自动重试。同一目标可使用 Wi-Fi，没有进行网络模式切换。

静止入口不是其它动作的启动器。原 SDK/配置仍需已安装并合法；CLI 执行要求仓库虚拟环境。预览可以没有有效期，此时只是不可执行的准备材料；本轮实际生成的是这种未获批准的预览，未创建执行目录。

注入假客户端的完整入口测试明确记录 `runtime=SIMULATION`、`hardware_verified=false`，不会作为真实 LEBAI 现场证据。

## 失败与最终验证

- 新增 **67 项**用例（核心 49、命令行 18），覆盖拒绝、缺失/未知字段、时间边界、前后状态与配置变化、源码变更、目录一次性、不同取消阶段、禁止其它写入、三种停止失败、尾段运动/漂移及日志关闭失败。
- 首轮红测试中的取消夹具无等待上限，功能未实现时挂起；仅结束该测试进程并增加 1 秒等待与任务清理。随后完成有效的 17 项红回归，再实现核心。
- 命令行配置解析期间变化及缺失批准材料复现 2 个失败；健康字段/最后 preflight/记录器变化复现 6 个失败；尾段异常、批准延期和错误授权回调复现 4 个失败；零速度下位置漂移复现 2 个失败；未知连接健康及独立 native 计时各复现 1 个失败。全部针对性修正，未放宽旧断言。
- 独立静态复核发现尾段异常未令基线失败，以及有效期未进入批准散列，两处已关闭；最终复审未发现剩余 P0–P2。审查者未运行测试、SDK 或网络操作。
- 最终 11 个定向文件 **243 通过**，JUnit 无失败、错误或跳过。包括原停止事务、证据、优先级、adapter、诊断与输入时钟回归；没有后端全集、前端构建或原生 SDK 实验。
