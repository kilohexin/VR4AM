# IK 方向保持与连续可达性核对

日期：2026-10-13，Asia/Shanghai。基线：`caac5978ef2eda8457123cc96b5b6056a2988392`。本轮仅离线开发、数学分析和定向测试，没有连接机械臂，未修改生产控制代码、限值或现场配置。

## 方向偏差的数学来源

记限速后的期望速度为 `d`，选用的速度参考为 `r`，原加速度约束缩放比例为 `b`。现有生成器得到：

`v = b*d + (1-b)*r`。

`d` 平行于“当前 IK 解减实际关节位置”；`r` 不一定平行。因而发送速度的垂直分量为 `(1-b)*r_perpendicular`。本次冻结输入逐件核对该分解，与生产输出一致；原参考组的最大垂直速度范数约为 0.005779 rad/s。

这是关节空间端点方向改变的数学解释，不证明现场 TCP 横向偏移全部由它导致，也不提供未校准 FK 的实物预测。

## 测试目录中的候选

新增 `backend/tests/robots/pvat_direction_candidate.py`，只供离线实验，生产 adapter 和动作入口不导入它。

候选限制 `v = fraction*(IK-actual)/T`，将六关节各自的速度和加速度条件转为同一 fraction 的区间，取交集中的最大值。fraction 保持在 0～1；区间为空时抛出 `direction_acceleration_infeasible`，不能将反复拒绝当作静止保持或停止确认。负方向、零方向、目标已到达但参考仍在运动，以及无法在原加速度预算内消除的横向参考速度，都单独验证。

49 个冻结输入在原参考、五件时间疑点独立替换、全部观测速度参考三组条件下，均存在满足上述**端点约束**的方向保持解。共 147 次比较，固定原 IK 和实际状态，没有形成新反馈闭环。五件时间疑点依然来自外层 QPC，不能当作新版精确 SDK 入口时间。

## 关键限制：端点约束并不保证连续轨迹

从零速度开始，若实际加速度始终不超过 0.2 rad/s²，80 ms 内位移最多为：

`0.5 * 0.2 * 0.08² = 0.00064 rad`。

但原端点构造及这个方向候选都可能给出 `v=0.016 rad/s`、`q-actual=0.00128 rad`，同时端点速度和速度差检查通过。位置要求已经超过上述必要范围。测试显式保留这个反例，防止把端点通过误称为完整运动可行。

用原记录的位置和两种不同初速度假设核对，结果如下。必要条件分别检查在速度、加速度上限下可积分到的位置范围，以及末速度变化；即使通过，也不是充分条件。

| 固定输入实验 | 原算法端点不通过：以观测速度起算 | 候选端点不通过：以观测速度起算 | 原/候选端点不通过：以所选参考速度起算 |
| --- | ---: | ---: | ---: |
| 原参考 | 48/49 | 48/49 | 两者均 15/49 |
| 五件疑点独立切换观测参考 | 48/49 | 48/49 | 两者均 18/49 |
| 全部观测速度参考 | 48/49 | 48/49 | 两者均 48/49 |

观测速度来自先前快照，前一指令速度也不是已证明的实际速度；两者都不是控制器执行入口的精确初速度。此表说明给定假设下的端点要求与连续限值不相容，**不能宣称真实机械臂发生了 48 次超加速度**。没有假定乐白采用五次插值，也没有从这个结论推断约 621 ms 停止延迟的原因。

因此本轮候选保留为数学比较工具，尚不能接入真机。下一步需用完整 P/V/A 状态检验连续段的速度、加速度和位置可达性，再处理不断变化的 IK 目标与重定向；只改 endpoint fraction 不足以解决问题。
