# VR 分段控制首版候选 — 2026-10-14

## 交付范围

本轮按用户加速交付要求，把开发集中到显式选择的 `segmented_experimental` 模式。代码已接入配置解析、后端创建、RobotControl 的策略及生命周期入口；默认仍为 legacy，现场配置没有更改。当前用户要求继续离线，所有连接和写入验证均使用显式假客户端，未连接机器人或推送。

首版只处理平移，保持捕获时的工具方向；沿用 Grip 控制运动权限、Trigger 控制夹爪。Home 和准备位姿在该专用适配器中暂不支持；不要把该候选描述为完整真机功能已验收。

## 分段规则

- 每次只有一个短段请求。等待完成和新反馈期间，手部输入继续经过原映射/滤波，只保存最新目标，不排队、追赶或恢复旧轨迹。
- 每段沿用有限参考构造、关节界限、反馈/目标/中点/终点四个 FK 审计和 100 ms 请求租约。参考时长不超过 80 ms，段末六关节速度及加速度为零。首版平移上限保留为 **0.2 mm**，限速和加速度还可能进一步缩小请求。
- 有限参考必须完整到达 IK 解；部分关节终点不能宣称完整 TCP 接受。不自动补发、插值尝试或发送 catch-up。
- 原 SDK 回执必须与请求身份、接受缓存和 TCP 一致才能推进 owner 目标。再次提交前，owner 必须先收集上一段接受结果。
- 下一段须在回执收集后的完整参考时长之后，收到至少三个不同、时间严格递增、当前代次的状态/运动反馈；位置接近本段解、速度低于配置阈值、加速度绝对值不超过 `1e-6 rad/s²`。位置容差还限制为本段最大关节位移的 10%，防止小目标被宽容差吞掉。
- 新段计算前再次检查起始速度及加速度。无效、回退或缺失加速度的反馈不会累计或继续保留 ready；反馈超期、接受变化或权限撤销结束候选控制。
- Grip 松开走原停止流程；原 60 ms PVAT、200 ms stop RPC、300 ms 稳定验证与 stop_unverified 锁存保留。模拟 621 ms 回复仍失败，不增加超时或使用 stop_sys。

上述参考、SDK 回执和反馈检查不是控制器插值、Cartesian 全路径、碰撞或物理停止证明。反馈放行是下一段的软件准入，不能称为真机已停止。

## 明确选择方式

未来经过单独现场授权和验证后，可在原完整 control 配置增加下列片段。此片段本身不能启动应用，不能替代原真机确认环境变量和现场授权，也不是已标定的交付参数；本轮没有生成或应用现场配置。

```yaml
target_strategy:
  kind: segmented_experimental
  settling:
    budget_ms: 500
    max_observation_age_ms: 40
    max_observation_gap_ms: 40
    position_tolerance_rad: 0.001
    velocity_tolerance_radps: 0.002
    settle_samples: 3
```

配置与直接注入同时限制至少三帧、位置容差不超过 0.001 rad、速度容差不超过 0.002 rad/s、反馈 age/gap 不超过 100 ms、预算不超过 1000 ms。readonly、缺字段、额外字段和弱化门槛配置被拒绝。两种实验策略不能同时选择；日志标明分段策略及未验收状态。

## 验证记录

首批 11 项因模块未实现失败；初步实现有一项夹具误用不存在的 `robot_data`，修正为真实假客户端的 `kin_data` 后 11 项通过。随后有效失败覆盖 prepare 故障未传播、未收集接受便计算新段、无效反馈保留 ready、三帧门槛与参数上限、回退帧、旧关节位置误判到达和非零初始加速度；现均修复。

部分终点失败原先被原 solver 包装为普通候选错误，未进入锁外停止。新适配器只把自己的 `segment_` 硬错误恢复为运动故障，复用原锁外停止。迟到 stop 用例的 disconnect 会重新抛出原停止事务错误；用例显式记录该失败及本地连接引用释放，不将异常算作确认停止，也没有第二条 stop 写入。

首轮四相关文件出现一项旧有限诊断失败：其 `asyncio.wait_for` 注入钩子已不能触及当前 OwnedMotionCalls 的实际入口，未真的消耗审计租约。该原生产诊断模块和普通适配器未改；测试改为在实际 `_await_motion_call` 边界消耗租约，保留 `not_started`、四次 FK 和唯一原 stop 的断言。原失败 XML 保存在本机证据目录，没有放宽准入。

新增 **31 项用例**，覆盖完整 RobotControl 的两段反向输入及 Trigger、Grip 撤权、停止迟到、接受变化、忙时公开提交、不可变缓存、新旧草案、部分终点、配置和实际应用启动。补充 40 ms 段的有效失败后，限速计划改为使用配置的实际参考时长，避免按 80 ms 计算较短段。SDK 数学是 X 方向的一维仿射替身，反馈到达由测试显式模拟，不能预测 LM3 的响应或抓取能力。

最终十一相关文件 **305 passed，11.02 秒**，无失败、错误或跳过；结果见本机 `.tmp/segmented-delivery-20261014/final-verified.xml`。未例行运行后端全集。独立静态审查指出的门槛及回退时间戳问题已修复；最终复审没有剩余 P0/P1/P2。审查未运行代码、连接设备或联网。
