# 正常 VR 原生调用阻塞修复 — 2026-10-14

## 本批范围与根因

用户仍选择继续离线。本批所有连接工厂均为显式假客户端，没有导入原生 SDK、连接机器人、网页或系统操作，也未改现场配置或推送。

正常 `RealLebaiAdapter` 的 IK / PVAT 使用 `asyncio.wait_for`。它在超时或取消时会等待子调用确认取消；如果原生 SDK 忽略取消，控制层仍持有 SDK 锁，原停止事务和断连会被阻塞。另一个问题是首次 PVAT 原生调用已经进入、但尚未完成接受记账时，旧 disconnect 只检查 `_motion_accepted`，可能不执行停止。

先用六个假客户端用例复现：IK/PVAT 本地等待无法按原预算结束、停止在等 SDK 锁，以及首次 PVAT 断连漏停止/迟到结果后允许重连。初次红测试因替身重复取消时没有置 finished 而中断；修正替身 finally 后六个有效失败留在本机。

这些是正常 VR 软件路径的可复现问题，不证明过去现场 SDK 曾忽略取消，也不构成约 621 ms 停止回复的原因定位。

## 修复

新增 `OwnedMotionCalls`，由适配器持有 IK / PVAT 子任务，保留 IK 200 ms、PVAT 60 ms。等待阶段最多每 5 ms 检查一次停止、代次、断连和 VR 权限撤销；不等待原生取消确认释放锁。这个调度间隔不是实时保证，事件循环被阻塞时仍可能延迟；完整快照读取、Home、夹爪和连接调用没有在本批全面改成这种所有权模型。

原生任务被放弃后，此适配器永久保留未知方法，禁止再准入、写入或重连。晚到结果不能提交接受目标或改写原回执；任务仍归原适配器持有，不声明远端取消或原生连接已释放。IK 未知是数学回复未知，不直接解释为机器人运动；PVAT 未知则保留 `stop_unverified`，原停止观测满足稳定条件也不得把停止事务设为 confirmed。

PVAT 原生入口立即记下当前连接的一次停止义务。首次 PVAT 尚未接受时断连也走原停止事务；在停止原生入口消费该义务，复用原停止事务而不补发。释放旧 client 时清除属于该连接的义务，保留未知结果和停止锁存，避免将义务带到新的连接形成隐式重试。

正常目标计算、平移倍率、关节约束、catch_up / 恢复候选和 PVAT 内容公式未改变。保留原状态新鲜度、停止 RPC 200 ms、稳定 300 ms / 验证 500 ms，不增加 stop_sys、恢复、Home 或自动重试。

## 审查发现的边界

- Home / 准备位姿在旧预检通过后等待锁，期间可能新增 IK 未知。两个有效失败复现后，在 `_begin_motion_epoch` 再检查未知门禁；夹爪锁后和实际子任务也显式重查。
- 专用有限窗口的代理可能在真正原生入口前本地拒绝。一个有效失败复现外层误判未知后，新增可信代理原生进入计数，比较本次前后计数；进入代理方法不等于进入原生 SDK。计数缺失/损坏不能证明未进入。
- 主动撤权和期限到期的兼容错误码保留，所有权记录另存 `authority_revoked` / `deadline` / `owner_cancelled` / `rpc_error` 及同一事件循环 monotonic 起止时间，不能把 Grip 释放主动放弃归因为 SDK 等待预算耗尽。

## 验证

新增 **18 项**定向用例：正常适配器 17 项，专用代理 1 项。包含实际 `RobotControl.tick` 与假 SDK 的 Grip 释放、不可取消 IK/PVAT、调用者取消、迟到结果冻结、Home/准备位姿锁交错、Future 返回、原生子任务进入前撤权以及失败停止后重连不增加停止次数。

初版相关回归 **12 失败 / 246 通过**。逐项处理：异步用例改为等待明确的处理完成、接受编号或事件，SDK 入口的参考寿命注入迁移到新调用边界；原生 PVAT 已进入但未确认结果的停止用例现要求 `stop_unverified`。没有删除关节限制、新鲜度或停止门限断言。VR 集成追加用例曾因夹具漏掉 adapter.connect 而两项失败，补齐显式假连接后通过。

最终九个相关文件 **270 passed，16.77 s**，无失败、错误或跳过；未重跑后端全集。配置、用户已有总结、原 SDK 文件与旧冻结证据保持。派生证据保存在 `.tmp/normal-motion-ownership-20261014/`。

独立最终静态复审无剩余 P0/P1/P2，确认上述四项修复及回归断言没有放宽门限；审查未运行测试或访问 SDK、网络、机器人、系统。原生取消、连接释放与物理停止尚未验收。

## 当前进度

这次修复进入正常 VR 适配器，补齐了 Grip 释放停止路径的一项软件阻塞风险。它没有解决或验收真实 FK/IK 超时、621 ms 停止回复、横向偏移、连续 VR 平移响应或真实 Trigger 抓取。

代码变化使上一批单窗口待审核材料中的运行哈希失效；旧预览保留作历史证据，不可沿用执行。当前没有有效现场授权，也未重新生成带有效期的执行范围。现场恢复后仍需先确认状态与只读 FK/IK 一致性，再单独授权微窗口。
