## 当前结果

网页实际操作已完成：解锁 → 独立准备 → 摇杆平面正反向各两个小步 → 渐进夹爪开/关 → 工具俯仰两个小步 → 升降两个小步 → 页面关闭。每个平移目标为 2 mm，每个俯仰目标为 0.5°；正常松开只结束续发，当前目标自然到位。混合操作保持同一准备代次，不需要每次重新解锁。8 个普通位置目标均通过自然到位检查，夹爪共 12 次本地目标调用，关闭后控制权释放且无故障或未知调用。

合成 XR 输入通过产品前端 `FinitePositionInput / FiniteXRInput` 和产品 WebSocket 接入官方控制器：准备、平移约 1.99986 mm、俯仰约 0.4998°、模拟扳机开/关；运动期间注入跟踪丢失，走原停止与锁定，再解锁和准备通过。最后断连 `DISCONNECTED`，`session_owned=false`，`control_fault=null`，读写未知列表均为空。跟踪丢失的那个已进入目标被中止，日志保留其失败结果，不能计为自然到位成功。

这是合成 XR 软件整链验收，不是佩戴真实头显的验证。自转按钮尚未在此有限位置模式开放。

## 实现与修复

- 独立 `LEBAI_DOCKER / finite_position_docker` 模式，固定 SDK `127.0.0.1:3030`；核对本机 Docker 上下文、官方镜像、入口、端口及无设备/挂载。拒绝远程上下文、真实端口和失败回退。普通启动及真机配置不变。
- 启动以持久调用所有权包住连接、虚拟 STOP→start_sys→IDLE 和模型验证。取消/超时后未知结果继续隔离，晚到结果不能追加查询/动作或挂接客户；禁止并发初始化。
- 启动进行三组原厂 FK 比对，再使用已验证理论模型作纯本地 FK；IK、机械臂运动、关节/TCP/状态读取仍来自原厂控制器。每步模型/路径核验继续执行。文件身份包含本地模型实现。渲染端同步使用原厂编码器零位约定，包括 J2 的呈现偏置。
- 连续本地 FK 之间显式让出事件循环，恢复后重查授权、期限、连接和模型；没有续写输入或反馈时间戳。修复连续计算令摇杆消息得不到处理的饥饿问题。
- 固定三维向量叉积不再经过通用广播/轴规范化；100 组随机新旧 FK/J/Jdot 对照的最大数组差为 0，单次分析中位时间约 4.488→1.022 ms。数值/有限差分回归保留，数学与限制不变；源码模型身份随修改更新。
- Docker 规划预计耗时预算对齐既有 5 秒粗抓取到位窗口，设为 4.8 秒，保留 200 ms 余量。原真机、Fake 和直接调用仍默认 1.8 秒；位移、速度、加速度、工作区与到位标准没有随之放宽。
- Docker 页面状态轮询在“规划→实际 SDK 发送入口”期间短暂让行，最多等待 1 秒，然后执行新读取。规划/进展/停止读取不受此等待影响。不用缓存替代新读、不改时间戳。规划失败、取消、实际进入、执行退出、断连均解除该等待。修复新反馈读完后，页面轮询抢先占 SDK 锁导致写前反馈过期的问题。
- 同一步 FINISHED 仅作绑定在连接、读取所有者、代次、准备绑定及任务编号上的终态证据复用；关节、速度、TCP 持续新读，仍需稳定观察。新步骤、停止、未知调用使复用失效。
- 桌面输入独立于 WebGL 绘制，每 20 ms 采样当前控件；XR 接管时停止桌面采样。Docker 方向显示窗口为 500 ms，但输入帧间隔与后端写前反馈仍为 100 ms。每个新夹爪目标仍需 100 ms 界面反馈；显示延迟不会积攒目标或回放 Trigger。
- 动作完成后的断连可在原期限内等待正在读取的调用结束，再执行原断连停止。故障锁存或未知调用后拒绝新会话，网页停止自动重连，避免重复 SDK 访问和日志风暴。

## 夹爪与物理边界

官方容器夹爪返回 `ClawUninit`。一次仅虚拟环境的 `init_claw(False)` 尝试在 5 秒内未完成，未重试、未作为成功。Docker 模式明确使用本地虚拟夹爪，长按渐变、松开保持选定目标，不调用原厂夹爪初始化/控制，没有接触、力或抓取物理。页面及状态入口均明确标注。

网页实测长按打开至约 5%，松开保持，再长按闭合至约 3%；速度受有界预检和回执影响，不承诺固定开合速率。力请求上限 30% 仅是模拟设置，不证明真实夹持力。

自研机械臂仿真作为独立模块保留；物理引擎、真实负载、接触抓取和制动效果尚未验收。

## 本机运行

确认用户已安装的官方 Docker 容器正在运行，再执行：

```powershell
.venv/Scripts/python.exe scripts/run_lmaster_docker.py
.venv/Scripts/python.exe scripts/run_lmaster_docker.py --run
```

第一条只预览；第二条启动 `http://127.0.0.1:8773/`。操作顺序为“解锁仿真 → 进入准备姿态 → 持按摇杆/升降/俯仰或夹爪 → 松开”。发生故障时保留锁存与记录，不在页面自动重试。真实头显使用已支持的 `--host 0.0.0.0 --cert <证书> --key <私钥>` 模式，需另行准备可信 HTTPS 访问条件，私钥不入库。
