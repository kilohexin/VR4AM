# 待发送 PVAT 在 SDK 入口核对 VR 授权

日期：2026-10-11。基线：`83c36e94264e56b845195747509885ba7827ec4f`。

## 已复现的问题

上一轮验证了控制 tick 接管停止后可以撤销 pending IK。这一轮进一步阻塞假 SDK 的 IK，接受新的 VR 输入，然后**不运行下一次控制 tick**，直接放行旧 IK。

在原策略和 transactional 实验策略下，以下输入变化都不能在适配器内部直接撤销旧目标：Grip 释放后重新握住、输入过期、追踪失效、页面隐藏、会话替换。10 个新增用例全部失败。待发送运动仅检查 pump generation；它在控制器接管停止时才失效，与最新 VR 授权之间有一个异步窗口。

这项离线复现与现场约 613 ms 的停止回复是两个已分别记录的问题。本轮不能将前者认定为后者的原因。

## 修正

- RobotControl 向支持该接口的适配器绑定纯同步运动授权检查，复用现有 ACTIVE、Grip、追踪、可见性、100 ms 输入年龄、会话、释放计数、故障和生命周期条件。
- RealLebaiAdapter 在异步处理开始、读取状态后、获得 SDK 锁后、IK 返回后检查授权；未授权的本地 admission 标记 `invalidated/not_started`，不进入 `move_pvat`。
- `asyncio.wait_for` 安排单独的发送任务，因此在该任务内部、进入 SDK 前再检查一次，中间没有 `await`。此处拒绝时不开始新的运动事务。
- 保留 pump 串行处理和原停止流程。未绑定 teleop owner 的独立适配器调用保持原有契约；Home、夹爪和停止接口没有通过本轮 PVAT gate 改变语义。
- SDK 入口窗口拒绝时，诊断同时记录 `rpc_outcome=not_started`、`invalidated=true` 和撤销原因，与 admission completion 一致。

这不是远程取消接口：已经进入 SDK 的 RPC 不能由本检查撤回。它也不会自行发送 stop、Home、复位或任何新命令；操作者释放后的原停止流程仍需运行。

## 验证

新增 14 个回归用例，均使用内存报文和注入的假 SDK：

| 场景 | 原策略 | transactional 实验策略 |
| --- | --- | --- |
| 五类授权失效，不等待 tick，拒绝旧 IK 发送 | 5 | 5 |
| 更新为健康的新 held 帧，允许原合法 admission | 1 | 1 |
| 最后发送任务安排窗口接受释放，拒绝 SDK entry 且诊断一致 | 1 | 1 |

有效初始红回归为 **10 失败 / 8 通过**；修正后 18 通过。增加健康输入和最后发送窗口覆盖后，独立审查指出诊断 `invalidated` 仅按 pump generation 计算，两个诊断回归先失败，再修正。

最终定向回归：12 个文件 **457 通过**，补充 5 个文件 **120 通过**，合计 **577 通过**；JUnit 无失败、错误或跳过。覆盖 WebSocket、控制状态机、Grip/Trigger、适配器、admission、catch-up、停止优先级、状态边界、停止事务及两种策略。未运行后端全集；前端源码未改，本轮不重复运行前端测试或构建。

曾有日志输出目录写错、测试插入处缩进错误、一个测试文件名写错；均在有效回归前修正，失败输出与说明保留本机，不当作功能红回归。最终独立静态复审结果随本机证据保留。

## 当前真机进度

本轮补上了“接受失效 VR 输入后，待发送 IK 不必等下次控制 tick 才拒绝”的软件边界。真实 SDK 内部发送时刻、后台调度、网络与机器人运动没有在本轮测试中验证，不能据此宣称软件停止实时性或真机验收通过。

现场约 **613 ms** 的 `stop_move` 回复原因仍未知；200 ms RPC 回复期限、`stop_unverified` / `stop_incomplete` 锁存和不自动 `stop_sys` / 重试 / 复位的要求均保持。持续真机 VR、Grip 释放停止、Trigger 夹爪仍待验收。

本轮没有连接机械臂、访问 L Master、修改现场配置、改变抓包状态、发送原厂消息或推送。新的现场访问和动作仍须另行明确范围与现场条件。
