# speedl 写入前核验调整（离线）

## 已批准的范围

用户已认可：代码和 SDK 加载后、进入运动租约前完成全量 SHA；实际 SDK 写入前核对同一文件身份和元数据、配置/批准材料、工具/关节/模型及原 100 ms 期限。实际入口不再逐字节重算运行文件 SHA，不能检测刻意保留全部元数据及文件身份的内容篡改。此次只进行离线实现、真实代码规模 Fake 和自有本机原生 SDK 回环，不授权真机连接或动作。

前序记录：[预检性能修复](native-jog-preflight-fix-2026-10-16.md)。以下结论仅适用于本轮软件候选。

## 实现

1. 全量核验仍在加载后及 FK/运动快照租约前完成。只有完整核验成功才能进入实际写入检查；之后的完整核验若失败，会作废先前验证状态。
2. 实际写入比较运行文件的设备号、文件号、长度、`mtime_ns` 和 `ctime_ns`。保留原路径名进行查询，避免路径链接替换后仍只查询旧目标；小集合直接扫描，真实规模集合使用四个线程扫描纯文件元数据，所有线程结束后才比较，线程不操作 SDK。
3. 快照组、提交、实际原生写入及返回边界仍检查运行文件元数据。内部所有权轮询继续核对配置、批准材料、绝对有效期及原权限，避免同一检查嵌套两次读文件。锁等待后仍必须经过原生写入检查，没有跨锁沿用旧结论。
4. 固定配置绑定预先捕获独立的字段值及类型，每次权限检查仍逐项比对，减少反复 JSON 序列化和 SHA。嵌套配置、可变列表、浮点符号零、类型和非有限值变化仍拒绝；工具/关节/几何校核保留。
5. 单次运动观察只产生读请求，其多层所有权检查使用配置/批准材料/有效期的轻量路径。它仍不能占用停止启动权；已进入速度命令后的原停止权不依赖代码文件或运动租约有效性。
6. 新预览明确写出核验策略和元数据局限；旧版“实际写前全量 SHA”的批准预览不能授权本候选。元数据拒绝也消耗一次提交，不允许恢复文件后重用同一次提交。

不变：一次连接、唯一基座 +Z speedl，5 mm/s、10 mm/s²、80 ms；FK/快照及输入 100 ms、SDK 速度等待 60 ms、停止 RPC 200 ms、稳定 300 ms、停止验证 500 ms、总预算 20 秒及最多两秒只读尾段。没有新增动作、重试、Home、恢复、夹爪或自动 stop_sys。

## 开发中实际失败

最初仅移走写前全量 SHA，真实规模 Fake 仍因 FK/快照过期而拒绝。计时又定位到重复文件元数据扫描、重复输入核验及观察检查的开销；并非据此认定机械臂或网络故障。

本机元数据扫描基准中，串行中位约 6.04 ms，四线程含创建和回收中位约 3.45 ms；这只是采样，不是调度上限。源码 SHA 并行化仍未采用。

`.tmp/native-jog-preflight-20261016/source-bound-fake-04` 至 `13` 保留实际结果，包括零写过期拒绝、一次速度/一次停止后的 stop_unverified，以及观察未通过。部分测试在开发阶段也出现时序失败。所有这些失败均未改写为通过，没有放宽原截止。

作者复核及首轮大回归发现：将元数据检查前移到提交边界后，拒绝时可能未消耗提交，也遗漏详细授权拒绝字段。已有回归与新复现用例共同覆盖修复，恢复文件不允许再次提交。
