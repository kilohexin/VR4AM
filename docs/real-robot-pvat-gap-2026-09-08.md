# +x 过冲：过期 PVAT 速度历史修复

## 已核实的证据

来源：`20260908T105538Z-5a4675df/session.jsonl`，指令 20。

- TCP 目标没有超过 +5 mm；实测最终位移为 +5.792 mm，日志峰值约 +5.905 mm。
- 该指令使用的实测 J2 为 -1.5843145324881387 rad，IK 目标为 -1.591424341099449 rad。
- 上一条指令 J2 速度为 -0.1499921353971312 rad/s，但当前实测速度已降到 -0.019174759848570515 rad/s。
- 旧计算仍基于上一条速度做加速度限幅，生成 J2 位置 -1.593113903319909 rad，比 IK 目标多走约 0.001690 rad。用现场快照可精确复现，不是仅凭 TCP 结果推测。
- 轨迹时长 80 ms，而日志下发完成事件间隔约 125～172 ms。发送完成时间并不等于控制盒接收时间；后续新增发送调用起点间隔日志，便于进一步区分。

乐白官方文档说明，相邻点发送间隔必须小于轨迹时长，超出会自动减速停止：
https://help.lebai.ltd/sdk/python/motion.html#伺服运动-pvat

## 修改范围

- 保存最近一次成功 PVAT 的调用起点时间。
- 只有距离该起点尚未达到轨迹时长时，继续使用上一条指令速度；否则使用当前快照中的实测关节速度重新计算。
- 同时覆盖 advance 与 catch_up 计算路径；停止、断开等既有历史清理会清掉时间戳。
- `pvat_sent.previous_pvat_gap_ms` 记录相邻成功调用起点间隔，首条为 null。
- 不修改 IK、轨迹时长、速度/加速度限值、奇异保护、停止确认或 0.5 mm 平移验收容差。

## 证据边界

本次消除了已复现的“轨迹间隔超时后沿用过期指令速度”问题，不构成任意位形、任意轨迹无过冲的保证。
短间隔下的终点减速与整体发送节奏仍须评估。未通过简单增加 t 使报表看起来连续，也未宣称实际频率已修复。

## 下一轮实验室验证

本机验证：现场快照在旧代码下复现越过 IK 目标；修复后 80/125/172 ms 边界与长间隔通过，40 ms 连续历史仍保留。完整后端 **664 项通过，85.20 秒**。
