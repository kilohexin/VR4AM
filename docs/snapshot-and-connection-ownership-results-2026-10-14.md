# 快照与连接取消边界、实现进度 — 2026-10-14

## 本轮交付

用户要求继续推进；此前“现场条件不满足，继续离线”仍有效。本轮仅显式假客户端、源代码及冻结文件检查，没有导入原生 SDK、连接机器人、网页/系统操作、现场配置修改或推送。

正常快照读取原有 300 ms 整组预算，但 `wait_for` 等待原生取消确认可能一直持有 SDK 锁。八种读取方法的不可取消替身、等待停止和调用者取消共十个有效失败复现了这个路径。新 `OwnedSnapshotCalls` 持有读取任务；预算结束或调用者取消即退出软件等待，不等待原生取消确认。

放弃的原生读取结果保持未知，禁止该实例继续读取、预检、写入或重连；晚到数据不回填缓存。原停止 RPC 仍可尝试一次，缺少新鲜反馈就保留 `stop_unverified`、不得报告 confirmed。显式终态读取异常继续走原故障屏障；它没有悬空的晚到任务，不与取消/超时导致的未知结果混淆，也不能靠后续健康样本擦除原故障来源。

## 连接和整个快照流程的隔离

- 连接工厂使用原 3 秒预算，连接后的首次 is_connected 增加 200 ms 有界等待；两者均归当前 owner 持有。这里记录的是注入工厂/SDK 方法进入，不等于已向机器人建立连接的证明。
- 断连闭合 owner，未完成连接及时退出；迟到的客户端或 True 不得重新赋值 `_client`、启动 pump 或恢复权限。没有原生取消/连接释放确认，不自动重连。
- active 覆盖整条连接与快照流程，包括 SDK 锁等待、数据解码及日志 await。记录器等待期间也不允许替换 owner 后接受旧预检；最后返回再次核对 owner、client 和闭合状态。
- 已收到完整回复后代理本地验证/期限拒绝，与尚未收到回复分开记录。可信代理传递本次原生进入计数和结果状态；内层已经冻结的 unknown 优先保留，不能被外层观察到的迟到 task.done 清除。

保留原快照时间戳、300 ms 读取预算、新鲜度、SDK 锁停止优先级、停止 RPC 200 ms、稳定 300 ms / 验证 500 ms。停止的 200 ms 是 RPC 预算，不能当作包含锁等待的整体停止时长。5 ms 分片检查也不是实时保证；事件循环阻塞、Home/夹爪原生调用及日志回调仍有其他限制。
