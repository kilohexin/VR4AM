# PVAT SDK 子任务入口与返回后的失效检查

日期：2026-10-13，Asia/Shanghai。基线：`a5e230a1718b0c505e8e7116d30abd419729c970`。本轮修改现有 adapter 控制路径，并只用替身客户端和时钟验证；没有导入或调用原生 SDK、连接机械臂或执行新现场测试。

## 两处已复现的软件缺口

1. 原路径在候选完成后检查快照新鲜度，然后用 `asyncio.wait_for` 切入另一个发送任务。任务调度或同步速度参考重建可以使快照过期，子任务仍会调用 `move_pvat`。新增替身用例分别跨越原快照期限 1 ns、1 ms，以及在参考重建时跨过期限，旧实现三项均失败。
2. SDK 已正常返回，但 VR 权限在等待期间过期；原路径返回后只检查 pump 代次，仍更新前一速度参考和已接受目标。替身独立复现旧路径的历史由空值推进到新指令；这不说明真机实际发生了该时序。

## 修复范围

修改 `RealLebaiAdapter._send_target_impl`，并为原权限判定 helper 补充调用结果参数，其余 adapter 方法保持。

- 发送子任务内检查已知快照故障、原运动读取及候选使用快照的新鲜度。同步重建旧速度参考后，再检查一次，随后进入原 SDK 调用；没有新增读取、IK、重试或额外运动。
- 保留原快照年龄规则和边界：最大年龄仍是 300 ms 加状态周期，等于边界允许，超过拒绝。没有将它改成 VR 的 100 ms TTL，也没有用更新缓存延长原运动读取寿命。
- 用本地标记区分 SDK 调用前的准入异常与 SDK 调用本身的异常。入口拒绝记录 `not_started` 及原原因；已知快照故障保留异常身份，释放 SDK 锁后由原 wrapper 走停止路径。真正调用 SDK 后抛出的 `BackendCommandError` 仍按原 `sdk_call_failed:move_pvat` 报告。
- SDK 返回后，重新使用原运动权限及 pump 代次判定。权限已撤销时，保留 `returned` 事实并标记 `invalidated`，不更新速度历史、已接受目标或 `pvat_sent`。该返回不撤回已发送运动，也不代表停止确认。
- 返回后检查需要保留调用事实：原权限 helper 的完成回执写死 `not_started`。本轮增强正常目标和 catch-up 用例，先复现两项失败，再由返回后调用显式传入 `returned` 和请求编号；调用前路径仍默认 `not_started`，不伪造 SDK 未调用或已成功执行机械动作。

上述“SDK 入口”是本地 Python 客户端调用边界，不是已证明的控制器开始执行时刻。没有将此前的五次插值、连续到达或窗口编码候选接入生产，也没有新增它们的控制器时钟假设。
