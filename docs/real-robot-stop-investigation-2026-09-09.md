# 9 月 9 日停止异常：修复范围与复测限制

后续已补充可选停止后只读观察，见[连续观察交接与静止复测清单](lab-stop-observation-2026-09-09.md)。

## 结论与证据边界

实验室 `6cf4e46` 会话 `20260909T045653Z-9e477bc5` 的首次停止失败是
`sdk_timeout:stop_move`，不是等待 IDLE 的 smoke 超时。
程序随后会尝试 `stop_sys`。原会话缺少该调用的完成/超时记录，不能根据
`stop_confirmed=true` 倒推该次兜底调用成功。

退出阶段的原始状态仍为 STOPPING，旧逻辑仅按关节速度连续 300 ms 不超过
0.02 rad/s 就确认停止。下一份探针读到 HOLD，关节 J2 与会话末值相差约
1.5°，TCP x 相差约 18.1 mm。现场已确认中间没有人工移动、xLab 操作或
手动启停系统。这是必须调查的异常；两份离散记录仍不足以确定实际运动时刻、
反馈延迟及系统停止过程各自的影响。

官方接口区分：

- [stop_move](https://help.lebai.ltd/sdk/motion.html)：停止所有运动，不能取消以后新发的命令。
- [stop_sys](https://help.lebai.ltd/sdk/system.html)：先停止运动，再禁用关节运动。

两者不是同义接口。不要自动 start_sys，也不要移除安全兜底、提高运动限位，
或把映射后的 HOLD 一律算成功。

## 本次代码修复

停止确认在原有速度窗口之外增加：

1. 原始控制器状态只能是 IDLE、PAUSED、STOP（兼容 SDK 数字状态 5/6/12）。
   STOPPING、MOVING、TEACHING、故障等不能仅凭速度为零确认停止。
2. 不能有急停原因或尚未结束的运动 ID。
3. 同一个连续 300 ms 窗口内，相对窗口起点的最大逐轴关节变化不超过
   0.001 rad，TCP 平移距离不超过 0.0005 m。超出后重新计时，不能通过
   相邻两帧都很小的变化掩盖累计漂移。
4. 保留原 500 ms 验证期限、200 ms SDK 调用期限和失败锁定/stop_sys 兜底。
   没有放宽门槛。PAUSED/STOP 即使确认静止，仍不能通过运动就绪预检。
   500 ms 是验证循环的检查期限，不是包括 SDK 锁等待、网络调用和兜底在内
   的硬实时端到端停止保证。

这修复的是“错误确认停止”的软件漏洞，不证明 18 mm 异常位移或 SDK 超时
的根因已经消失；有限观察窗口也不能保证后续永久不动。

## 新增 stop_diagnostics 事件

每次 stop 单独记录一份事件：

- reason、initial_fault、started_ns、completed_ns、outcome、error/error_type、latched_fault；
- rpc_calls：stop_move、兜底连接查询、stop_sys 的起止单调时间、200 ms 期限，
  returned/timeout/cancelled/error 结果。returned 仅表示 RPC 返回，不等于机械臂已稳定；
- samples：验证窗口内的原始状态、急停原因、运动 ID、关节位置/速度、TCP、
  采集/观察时间、相对窗口起点的漂移、stationary 判定。

诊断数据先放在内存中，安全处理结束后再写入日志，不持有 SDK 锁，诊断写入
使用 50 ms 的协作式超时（记录器必须正常响应取消）。停止验证期间不调用
常规 kinematics 记录回调，避免它在速度未收敛时阻塞安全兜底。
记录器不可用时可能缺少此事件，但不因此取消或延后已执行的停止/兜底动作。
stop_move 超时直接进入兜底的情况下，没有进入验证窗口，samples 可以为空；
不能将空 samples 当作位置稳定的证据。

## 回归测试口径

本地验证：`backend` 目录执行 `python -m pytest -q --tb=short`，696 项通过，
84.39 秒。只读代码复核提出的日志阻塞和取消信号问题已修正后重跑。
这是离线软件回归，不是本次现场停止/位移异常的真机验收。

新增测试先在旧实现中确认失败，再实施修复：STOPPING/MOVING/TEACHING
零速度误判、关节/TCP 零速度读数下的累计漂移、停止超时诊断缺失。
补充验证正常 IDLE/STOP/PAUSED 的完整窗口、STOPPING 到 IDLE 后重新计时、
日志阻塞不延迟安全兜底。

额外覆盖：所有日志回调阻塞时仍执行 stop_sys；诊断写入期间收到的取消信号
不被吞掉。单纯记录器错误不再把已验证的停止转成自动系统关闭；状态读取
错误仍锁定并执行兜底，普通运动路径的记录保护不变。

原有两个运行故障测试过去允许“故障或急停 + 零速度”确认停止；现在要求
stop_incomplete，同时断言最初的故障原因保存在诊断事件中且执行了兜底。
不修改模型、限位、仿真运动夹具来迎合测试。
