# 运动发送前的完整快照校验

2026-10-10，Asia/Shanghai。目标是修复离线复现的发送边界：运动快照与发送之间插入的新故障观察不能被旧快照或随后健康样本覆盖。

## 设计与实施范围

沿用用户对自主离线开发和定向测试的授权，当前检出继续开发；现场原始材料、配置和用户总结文件保留，暂不推送。不新增真机连接、运动或测试入口。

选择在第二段 SDK 锁取得后校验已经完成的完整读取。没有把整个读取和发送合并成一个长临界区：那会延后普通观察、让故障处理可能递归等待同一把锁。也不扩大观察等待预算；上一轮未证明其收益。

为完整读取保存私有记录：单调序号、client 身份、pump generation、完整解析后的 snapshot。记录在 SDK 锁内取得读取权限时开始，解析完成后填入 snapshot；失败/取消不能伪装为完整读取。运动开始保存读取序号下界。

发送锁内先检查请求仍有效，再检查 client/generation、最近读取已完整成功及既有新鲜度。健康的新完整快照可供 IK/PVAT 使用，不增加 SDK 读取；原运动快照在取得发送锁和 IK 后发送前都必须仍新鲜，新观察不能延长原请求寿命。

pump 已运行的同 client/generation 首个 runtime 故障、TCP 配置不一致或读取/记录错误保留到发送边界；之后健康样本和日志异常不能取消或覆盖该来源。故障校验不按“已开始的读取序号”过滤，涵盖运动开始时仍进行中的读取及入队至 handler 开始的空窗。连接/预飞且 pump 未运行时不建立此记录；旧连接或旧 generation 不能冒充本次故障。读取序号下界只用于成功快照，防止拿运动开始前的缓存冒充本次读取。

已知故障在原快照 TTL 检查前处理，在读后、发送锁内和 IK 后发送前复查。边界拒绝在锁外沿既有故障停止路径处理，保留来源故障、invalidate、历史清理、`stop_unverified` 和仅 `stop_move` 策略。停止自身的读取直接执行，不能调用这个运动拒绝入口。200 ms、新鲜度阈值、PVAT 参数、速度/关节限制和默认关闭的等待窗口保持。

client 身份在原运动读取前保存；读取过程中连接对象被替换时，以 `robot_disconnected` 拒绝旧任务，不根据旧连接证据向新连接发故障停止。

原运动读取诊断与实际采用的 dispatch snapshot 分开记录，PVAT point_inputs 必须匹配真正采用的快照。取消与晚返回不应留下跨 generation 的可用证据。

- [x] 定向补充读取失败、过期、取消、stop/generation 与日志异常观察；验证无额外 SDK 读取和 no post-stop PVAT。

## 实际修复与验证

修改 `backend/app/robots/lebai_adapter.py`，新增 `backend/tests/robots/test_motion_snapshot_boundary.py`；`test_snapshot_contention.py` 中只调整诊断年龄断言，同时校验原 motion 年龄与实际 dispatch 输入年龄。原“新观察不能刷新过期 motion”用例保持不变。

新增 **27 个假 SDK 边界用例**：

- 状态 ERROR、急停、TCP 不一致后又读到健康样本，均在 IK/PVAT 前拒绝；原 motion 同时过期时仍保留故障来源并调用一次 `stop_move`。
- 运动进入时已有读取进行中；prepared generation 在 handler 之前已读到故障；正常初始化且 pump 未运行的故障不会错误污染后续合法预飞。
- 新健康完整读取更新 IK seed 和 PVAT point_inputs；即便控制时钟捕获值相同，也按读取身份/顺序正确选择。
- SDK 读取失败、执行中的观察取消、随后健康读取；记录失败不覆盖同一次读取先发现的 runtime 故障。
- 原请求在排队或 IK 期间过期仍拒绝；陈旧、不完整、旧 generation 和错误 client 的快照不作为发送依据。
- 停止发生在快照与发送之间，旧请求不产生晚 PVAT；旧 generation 读取的故障不冒充新 generation。
- 实际 production pump 与 SDK 锁 FIFO 交错，已读到故障时 completion 为 failed、SDK motion 为 not_started；故障停止失败保留 `stop_unverified`，只一次 `stop_move`，没有 `stop_sys`。
- 观察仅在队列里取消、尚未取得 SDK 锁时，不伪造读取错误；完整读取后的记录回调在 IK 期间晚失败时，发送前再次拒绝。
- 运动读取期间 client 身份被替换，不向新 client 发故障停止。

### 失败与审查记录

首次 4 项红回归确认旧任务继续进入 IK/PVAT及使用旧关节输入。独立静态审查发现 P1：读取已开始但未完成，不能用其开始序号当作故障下界；P2：原 motion 与 dispatch 诊断来源混用。补交错/诊断/日志异常断言后 3 项失败，修正为同 prepared generation 首故障保留与独立来源诊断。

扩大至 11 文件时出现 **3 failed / 227 passed**：两个旧诊断年龄断言与新实际输入来源不同；另一个原有过期保护用例暴露最新快照可能延长旧请求寿命。保留原过期用例和 TTL，补 IK 期间原 motion 已过期而新观察仍新鲜的红回归，再在发送锁内和发送前校验原 motion。没有放宽阈值或删除原安全用例。

复审还发现 P2 组合边界：原 motion 过期可能先于已知故障退出，掩盖来源并绕过即时故障停止。状态/急停/TCP 三个组合用例先失败，再统一为已知故障先处理；TTL 继续阻止无已知故障的过期请求。最终静态复审未发现剩余 P0–P2，审查未运行测试、SDK 或现场操作。

最终 **12 个定向文件，244 passed，9.24 秒，退出 0**：新边界、adapter control/readonly、snapshot contention、停止事务及计时边界、PVAT 生命周期、延迟注入、观察窗口单元/集成、command admission、离线负载 probe。没有后端全集或真机测试。

## 验证界限

本改动不保证发点间隔缩短，也不解决既有约 613 ms 的 `stop_move` 回复。离线停止返回、IDLE 或测试通过均不证明物理停止。持续真机 VR 与 Trigger 抓取仍未验收，新现场测试仍需单独范围和现场条件。

锁仍使用原 FIFO 策略：已有排队观察仍可能延迟运动或停止取得 SDK 锁。本轮修复该交错的发送安全和证据一致性，没有把锁竞争或控制器等待宣称为已解决。源码已改变，旧现场入口的 runtime 绑定不能复用；本轮没有新增 live 启用入口，暂不推送。
