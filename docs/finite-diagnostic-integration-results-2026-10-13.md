# 有限窗口独立诊断接入 — 2026-10-13

## 已完成

新增 `app.commissioning.finite_diagnostic.FiniteWindowDiagnosticAdapter`，把上一轮有限窗口构造器接入原 adapter 的队列、分派、回执、权限检查和停止事务。正常 VR、普通 smoke、配置均未选择它；原 adapter 源码没有修改。构造实例必须显式提供客户端工厂，未来实机工厂仍须由单独批准的入口约束。

当前组件仅允许一次平移请求，目标距离不超过 0.2 mm，姿态保持不变。只入队一次，失败也不能重新提交；不做 IK 自动恢复或 catch-up。Home、准备位姿和夹爪接口明确拒绝。它不是连续 VR 实现，也没有可直接执行的真机 CLI。

## 正解审计与分派

- IK 和原关节约束通过后，以实际 PVA 构造完整零末端速度/加速度窗口。
- 最多进行四次 `kinematics_forward`：反馈关节、完整 IK 目标、声明参考的中点、窗口终点。
- 反馈正解与读取 TCP 的位置/角度差要求在 100 µm / 0.1° 内；目标正解与目标也检查一致性。
- 正解位移相对反馈正解检查方向和进展。完整目标的进展差不超过目标距离的 5% 或 1 µm；中点/终点限制反向、过度推进、横向偏离和姿态变化。终点必须有正进展。这些是独立诊断检查值，没有放松原运动/停止阈值。
- 每次异步调用前后、读查询子任务入口、原 PVAT 子任务入口检查同一次请求的权限、generation 和有效期。100 ms 从队列提交前开始，排队和查询都消耗它，不从处理器启动或查询完成重新计时。
- 在查询前捕获快照输入签名，之后检查同一份位置、速度、加速度、TCP 及读取时间信息；不能把查询中途改变的位姿重绑定为合法输入。
- 审计通过的票据只适用于该请求及其快照。原 SDK 子任务最后的同步边界再次核对票据，保留原入口/返回后的权限检查与如实回执。

**正解采样不是完整笛卡尔路径证明。**当前测试使用人为定义的线性 FK，不是已标定的 LM3 模型。控制器插值、原生 SDK FK 返回格式及实机正解/反馈一致性仍待现场证据；不根据替身审计放行运动。

## 失败与退出

几何不一致、不可行窗口、坏数据或诊断过期进入原运动故障处理，释放运动 SDK 锁后执行原停止事务。仍用 `stop_move`、200 ms RPC 期限、300 ms 稳定窗口及 500 ms 验证预算；停止失败保留 `stop_unverified` / `stop_incomplete`，不自动切换 stop_sys、恢复或重试。

每次正解读等待为 50 ms。使用一个被实例持有的查询任务，超时只请求本地取消；不等待忽略取消的任务完成，不认为远端查询已取消，也不使用迟到结果生成运动票据。未结束的读阻止重新连接，没有第二个查询任务。正常协程和返回 Future 的方法均通过测试；未导入原生 SDK 确认该安装版本的具体返回对象。

PVAT 原生入口一旦被尝试，退出必须处理原停止事务，不能因为 SDK 返回后权限撤销、原接受状态未推进而省略停止。同一退出不反复重发停止；原事务继续负责复用和未知结果。只读迟到结果不能改写已记录的审计快照。

## 定向验证

新增 **37 个用例**。先观察缺少模块的失败，初始 28 项通过；补充验证发现并修复三组有效失败：

1. 忽略取消的读阻塞超时退出；可变位姿导致输入证据在查询中途被重绑定。
2. 直接 create_task 不接受返回 Future 的方法；读查询子任务入口未重查有效期。
3. SDK 返回后权限撤销使退出跳过停止；迟到查询修改了已发布审计记录。

最终七个相关文件 **195 passed，20.73 s**，无失败/跳过。覆盖原真实 adapter/pump/completion/stop 路径配合替身的完整分派与清理，并覆盖坏正解、缺能力、初始加速度超限、queued expiry、各查询阶段 100 ms 边界、权限和 generation 撤销、Future 返回、无法取消的读及停止回复迟到。正常 adapter 不调用新增 FK，也不采用零末端策略的用例通过。
