## 已确认的问题

`RealLebaiAdapter.set_gripper` 完整读取状态后会释放 SDK 锁，再等待发送锁。原实现只复查停止、预飞和夹爪撤销权限；等待期间已读到的故障及原快照过期，没有在 `set_claw` 前再次检查。

假 SDK 的四项初始回归均失败：状态故障、急停、TCP 配置不符分别被随后健康样本覆盖；另一项原请求已过期但新健康读取仍新鲜。四项都错误发送了 `set_claw(30, 50)`。这是离线代码竞态证据，不是现场出现过夹爪误动作的证明。

## 修改与边界

在原完整读取前保存 client、pump generation 和读取序号下界。取得最终 SDK 锁后执行：

1. 保留既有停止、预飞、故障锁存和夹爪撤销检查的优先级。
2. 校验准备代次及 client 身份，拒绝旧连接或旧准备代次的请求。
3. 复用运动路径的同 client/generation 首个已知 runtime、TCP 或读取/记录失败证据；先处理已知故障，再检查原请求新鲜度，随后健康读取不能取消故障。
4. 原夹爪快照仍须满足既有有效期。新健康读取不能延长该请求寿命。
5. 选用同 client/generation、序号超过下界、完整成功且新鲜的最新读取；复查既有关节软限、TCP 工作空间和 SDK capabilities。

边界拒绝会撤销预飞权限，不发送夹爪命令。保留原 gripper 的拒绝方式，没有新增 adapter 直接停止、复位、Home、重试或额外 SDK 读取。Trigger 所在的 RobotControl 错误处理和现场停止策略未改；200 ms、`stop_unverified` 和禁止自动 `stop_sys` 保持。

已完成且随后恢复的关节/工作空间越界没有在本轮新增跨读取锁存政策；其最新完整读取仍接受原全量边界检查。继承的首故障保留范围是 runtime、TCP 和读取/记录错误。本轮未修改运动规划、力限、夹爪开合幅度或观察窗口默认值。
