# 夹爪 SDK 入口授权与首次 Trigger 意图撤销

日期：2026-10-12，Asia/Shanghai。基线提交：`801a98364d4ccede2ec997ff5d2fec156ad8448a`。

## 本轮复现与修正

使用实际 WebSocket 接收逻辑、RobotControl、RealLebaiAdapter 和注入的假 SDK，暂停夹爪请求的状态读取。在读取等待期间接受新的 VR 输入，再恢复读取；没有启动后台控制循环或下一次控制 tick。

原版本在 Grip 释放后重新握住、输入过期、追踪失效、页面隐藏、会话替换五种情况下，都可能继续调用 `set_claw`。两种目标策略下的 10 个用例均先失败，修正后通过。

适配器新增可选的同步夹爪授权检查。RobotControl 绑定检查，复用原有控制代次、释放计数、状态、输入年龄、会话、追踪和可见性条件。在状态读取前后、取得 SDK 锁后，以及 `wait_for` 安排的发送任务内部、进入 SDK 前重新检查。

本地撤销使用专门的 `GripperCommandRevoked` 异常，表示夹爪请求尚未进入 SDK。VR tick 跳过该请求，不更新 `_last_gripper_sent` 和时间；直接 `command_gripper` 调用返回已有的 `gripper_command_authority_changed` 错误。SDK 超时与其它错误仍走原故障路径，不能当作本地撤销吞掉。

ARMED 状态下，Grip 松开仍允许有效 Trigger 操作。未绑定 teleop owner 的独立适配器调用保持原有契约；力、幅度、方向、10 Hz 限流和 200 ms 夹爪 RPC 等待期限保持。

## 首次意图记录

独立审查发现，首次 Trigger 按压在发送前已设置意图标记；本地撤销后该标记仍保留。若健康的松开帧先于 stale/HOLD 处理到达，可能发出夹爪松开指令，虽然首次按压从未进入 SDK。

补充非零初始夹爪遥测的合成用例：ARMED 首次按压因输入过期、追踪丢失或页面隐藏被撤销；恢复后的松开不应发送夹爪，新按压才允许发送。两种策略下 6 个用例先失败，再修正。

撤销现在只清除本次新建立的意图，保留先前已建立的意图；不会恢复 HOLD 已经清除的标记。已进入 SDK 的请求不通过这个路径撤回或重新标记结果。

## 真机主线与限制

本轮进一步保证失效 VR 输入不能在应用可控的 SDK 入口前继续发送夹爪请求，且被拒绝的请求不会被记为成功发送。该保证仅覆盖本地待发送请求，不能取消已经进入 SDK 的调用，也不能证明实际夹爪动作或物理抓取成功。

测试使用内存报文、假 SDK 和可控时钟；真实后台调度、SDK 内部发送、Wi-Fi、头显、夹爪与运动硬件未验证。此前约 **613 ms** 的 `stop_move` 回复原因仍未知，持续真机 VR、真实 Grip 释放停止和 Trigger 操作仍未验收。

200 ms 停止 RPC 等待期限、`stop_unverified` / `stop_incomplete` 锁存，以及不自动 `stop_sys`、重试、复位或 Home 的要求保持。本轮没有机器人连接、现场配置修改、网页访问、抓包改动、原厂消息或推送；新的现场访问和动作仍须明确范围与现场条件。
