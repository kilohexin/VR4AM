# speedl 分阶段核验（离线）

## 用户已认可的修复范围

[本次现场记录](native-jog-site-result-2026-10-16.md)中，SDK 停止回复约 1.9 ms，但速度发送后因旧 FK 自然过期撤权，停止验证未通过。用户已确认现场完全静止、无异常、未用急停；失败记录与锁存保留。

用户随后认可本轮局部软件设计：将发送前准入与已发送 RPC 收尾分开。实际原生入口仍要求 FK/快照小于 100 ms；已进入后继续监控原输入期限、用户撤权、配置/代次和原 60 ms 回复上限，不以同一份已使用反馈自然老化单独撤权。**只批准离线实现和本机回环，不授权新的真机连接或动作。**

## 代码行为

1. 阶段只由受限代理的可信实际 `speedl_entries`、原生开始记录及所属任务确定，没有调用者可设置的 phase 或放行开关。进入前保留原完整模型/几何、快照所有权、配置、文件身份和 100 ms 校核，锁等待后及实际 SDK 入口仍检查。
2. 创建命令时独立保存带类型的包字段与反馈字段，包括原始输入/有效期、代次、方向、速度、时长、关节/速度/加速度、工具及实际/目标 TCP、原反馈时间戳。等待期间逐项核对同一数据及当前配置/模型绑定；修改嵌套 Pose、工具、反馈时间戳或输入期限都不能沿用原权限。
3. `validate_inflight_input` 只检查已经进入的同一个 RPC 的原输入和身份，不检查旧反馈年龄，也不能准入新写入。没有把快照时间戳换成 now，没有创建新输入或延长任何期限。已经核验且逐项未变的几何数据无需在等待期间重复计算；这些冻结值不能代表当前物理姿态。
4. 原 60 ms 所有权截止及其起算点未改，仍监控等待期间和完成发布前的撤权。输入过期、配置/代次改变、显式撤权、取消、迟到或未知结果继续隔离，晚到 ID 不恢复权限。
5. 固定一次 +Z、5 mm/s、10 mm/s²、80 ms，段末仍锚定实际原生进入时间。异常或撤权仍调用唯一原停止；200 ms RPC、300 ms 稳定、500 ms 验证、最多两秒只读尾段及 stop_unverified 不变。没有第二次停止、重试、Home、恢复、复位或夹爪。
6. CLI 预览新增明确的 `motion_authorization_policy`，旧单阶段预览不能授权新候选。原公开回环候选、生产配置选择器、网页和 VR 路由不改。
7. 模型 guard 每实例最多缓存四组纯 MDH 位姿计算，键包含完整规范化关节、工具平移和工具旋转，值为不可变元组。当前实际/目标位姿比较、关节/速度/加速度约束及配置绑定仍逐次执行；没有缓存准入结果、时间、权限或 SDK 结果。

## 复现与实际失败

回归先复现旧行为：FK 已有 70 ms、进入后回复又用 40 ms，即使输入本身仍新鲜，旧实现仍报告 authority_revoked。修复后该用例完整通过，进入前 100/101 ms 则仍零写拒绝。输入过期、真实撤权、配置/代次变化、反馈/工具/时间戳修改及试图续租均保留失败。

原生回环新增三案：反馈在等待 35 ms 回复期间跨过 100 ms；在途明确撤权后收到晚 ID；停止先回复而模拟运动随后才生效。后两案必须保留未知结果和停止失败，不能用一般失败掩盖未实际触发的情形。旧迟到停止案还补充“速度本身必须正常返回”的断言，避免两个调用都失败却算该案通过。

真实代码规模的首次 25 ms 延迟 Fake 未通过：进入前检查和等待期间重复几何计算消耗了原 60 ms 所有权窗口，原生结果已返回但不允许发布成功。改为等待期间逐项核对独立绑定数据、保留输入/配置/撤权检查后，第二次完整通过；第三次复测仍在 60.0676 ms 超出原所有权截止。第三次实际原生进入前约占用 24.47 ms，原生等待约 35.43 ms，不能仅因原生已返回就发布成功。两次失败均保留，未延长或重设原 60 ms 起算点。

随后以 TDD 加入上述有界纯数学缓存，减少进入前对相同关节/工具的重复 FK。真实 106 文件绑定规模的普通 Fake 第三次和 25 ms 延迟第四、五次均完整通过；这三次为独立串行运行。失败材料仍在 `.tmp/native-jog-preflight-20261016/source-bound-phases-delay25-01/` 与 `source-bound-phases-delay25-03/`。较早第三次失败在汇总输出后进程仍收尾时启动了另一个回环，因此不将其描述为严格隔离测量；失败本身仍有效且不删除。
