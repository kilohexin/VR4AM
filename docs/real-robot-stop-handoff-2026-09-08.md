# 真机停止闭环修复与复测交接（2026-09-08）

## 本次范围

- 不修改 IK、PVAT、运动速度、关节步长或奇异保护阈值。
- 不把 HOLD 自动恢复为 IDLE，不自动启动系统或解除急停。
- 修复已知停止故障被稳定等待掩盖的问题；补全停止失败和原始 SDK 状态日志。
- 现场偶发 HOLD 的控制盒侧原因尚未确定，不能宣称已经消除。

## 行为变化

1. 稳定等待发现后端故障，立即报告 `smoke_stop_failed:<原因>`，不再等到通用稳定超时。
2. `stop` 不再受“允许运动”的预检结果阻拦；仍要求 control 配置、确认词、成功连接及有效状态读取。停止仍由适配器验证连续 300 ms 关节速度收敛，失败不能报告成功。它不是硬件急停的替代品。
3. stop 成功后可以仍然是 HOLD；仅代表已确认停止，不代表可以发运动指令。平移、旋转、夹爪及恢复动作仍保留原有预检。
4. 新增 `stop_failed`，记录停止原因、原始异常类型与信息。
5. `robot_kinematics` 新增 `raw_robot_state`、归一化 `robot_state`、`estop`、`running_motion`。HOLD 是程序分类，PAUSED、STOPPING 等多个 SDK 状态都可能映射为 HOLD。
6. 有控制会话的演练在退出停止后追加 `smoke_final_state`，分别记录停止确认和下一动作预检结果。`smoke_result` 是动作阶段结果，必须结合最终事件判断下一步是否就绪；断开后的现场状态仍需另跑只读预检。

## 实验室复测顺序

现场需保留急停可操作、观察员就位、作业区清空等既有条件；不扩大旋转幅度。

1. 更新程序后保存 `git rev-parse HEAD`、`git status --short` 和 `git diff HEAD --`。不要通过修改 `.git/refs` 伪造版本一致。
2. 先运行既有只读预检。若已经 HOLD，保留原始状态日志，不自动恢复运动。
3. 执行既有 `stop` 命令，检查 `stop_confirmed` 与 `smoke_final_state`。HOLD 下停止成功不要求变成 IDLE，且不能据此继续运动。
4. 仅在现场确认恢复就绪、预检允许且位形合适后，按既有流程 prepare，再单次复测 +roll 1°；不要追加幅度或连续试探。
5. 保存整个 session（含失败会话），随后另跑只读预检。若停止失败或仍不可运动，停止后续动作，回传日志。

## 回传内容

- 完整 session.jsonl、summary.json、终端退出码与错误。
