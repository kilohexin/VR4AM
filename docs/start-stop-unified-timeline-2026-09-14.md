## 1. 必须区分三层位置

| 数据层 | 本轮 +x 2 mm 结果 |
| --- | --- |
| 本程序发送的笛卡尔目标（pvat_sent.target_tcp） | 19 个 x 从 0.023866511 m 单调增加到 0.025826511 m，没有反向发送目标 |
| 控制盒反馈的规划位置（robot_kinematics.target_tcp） | 首个 MOVING 样本 x=0.023977725 m，起步 600 ms 窗口内最低 0.023921588 m，回退约 0.056137 mm |
| 控制盒反馈的实际位置（actual_tcp） | 首个 MOVING 样本 x=0.023863506 m，同窗口最低 0.023801897 m，回退约 0.061609 mm |

首个发送目标比控制盒原先的规划 x 低约 0.111213 mm，但比当时实际 x 高约 0.003005 mm。因此，发送序列“相对实际位置向前”与“相对旧规划位置向后重新接续”可以同时成立。

这把起步排查具体缩小到：旧规划状态、反馈实际状态与新 PVAT 边界条件的衔接。不能据此认定是 VR 输入反向，也不能直接认定控制盒抱闸释放造成抖动。pvat_sent.target_tcp 是送入 IK/限幅流程的笛卡尔目标，真正发送给 SDK 的是 p/v/a 关节参数；还不能由它的单调性保证控制盒内插轨迹单调。

## 2. prepare 的不同之处

prepare 使用控制盒 movej。首个 MOVING 样本实际 x=0.008838236 m，600 ms 窗口内最低 x=0.007926659 m，反向变化约 0.911577 mm；同窗口规划 x 最低值仍为转换时的 0.008877815 m。

这构成“实际 x 与规划 x 在起步阶段存在差异”的证据，但关节空间运动不能只凭 TCP 单轴曲线判定全部轨迹异常。还需比较六轴规划/反馈轨迹和时间对齐，才能区分跟踪滞后、关节不同步、采样时序与机械响应。现有数据不能证明每次 IDLE→MOVING 都重新使能或释放抱闸。

## 3. 停止后异常没有被启动分析替代

完整纳入 287 条停止观察后，仍复现首尾 x 变化 −16.284020 mm，且控制盒反馈 target_q 在整个观察段只有一个不同值。

停止流程仍是两轮 stop_move/stop_sys，共四次停止调用等待超时。最后一条 PVAT 返回在首次停止请求前 31 ms；本进程没有停止后新增 PVAT 的记录。远端轨迹是否执行完毕与 RPC 是否返回须分开判断。

所以必须并行保留两个待解释现象：

1. 起步段的较小反向位置变化及目标衔接。
2. 停止调用失败后厘米级的实际位置变化。

目前既不能用第一项解释第二项，也不能证明两项的物理原因相互独立。实验室报告“抖动只在起步、不在停止”的总体结论超出了该报告仅检查运动学事件的覆盖范围。

## 4. 源码对应与下一步优先级

- `backend/app/robots/lebai_adapter.py`：prepare 使用 movej；平移候选进入 build_pvat_point，PVAT 连续时复用先前发送速度，间隔超过轨迹时长时改用反馈速度。
- `backend/app/robots/lebai_pvat.py`：由 IK 解与实际关节差构造目标速度，再按速度/加速度上限缩放，得到关节 p/v/a。它不是直接把 VR 位姿原样传给控制盒。
- 当前没有证据支持直接清零所有速度、取消加速度、删除 stop_sys 或放宽超时作为根因修复。

优先级仍然是停止链路：离线验证单次停止事务、未决 RPC 迟到结果、shutdown 不重复启动停止事务、以及停止期间持续证据记录。起步问题随后使用本次完整时间线核对首帧关节边界条件，不能以换一个初始位形或更大速度掩盖。

本轮只完成分析与可复跑产物；没有修改生产控制逻辑，没有进行真机验证，也未推送 GitHub。实验室不需要新增动作或恢复 IDLE，继续保持既定停测边界。
