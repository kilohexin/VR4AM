# 夹爪异步 SDK 入口检查修复

日期：2026-10-12，Asia/Shanghai。基线：`79037a86aa0122cc724f4302a88729081dd2f707`。

## 问题与复现

`RealLebaiAdapter.set_gripper` 在获取 SDK 锁后检查停止锁、夹爪撤销代次、pump 代次、连接、preflight、故障证据和完整状态样本。随后 `asyncio.wait_for` 创建另一任务；该任务原来只再次检查 VR 权限。

因此，锁内检查完成后到 SDK 任务执行前仍有一次调度机会。离线测试分别在此处令样本过期、pump 代次改变、preflight 失效、客户端变化，或启动真实 adapter 的停止流程。未绑定 VR 权限和绑定允许回调各测一次，共 **10 项失败**，均复现了原代码继续进入假客户端 `set_claw` 的行为。

这是代码与假 SDK 的可复现缺口。没有真实机器人操作记录支持将其认定为现场已经发生的问题，也没有将停止迟到归因于此。

## 修复

将原锁内检查提取为本次调用的同步 `require_dispatch`，在取得锁后及 SDK 任务实际入口前均执行。第二次检查与 `set_claw` 入口之间没有额外 await；完整复用原状态寿命、几何约束及故障记录规则。

调整异常处理范围：本地检查拒绝保留原错误原因；只有实际调用客户端后的异常归为 `sdk_call_failed:set_claw`。原超时继续报 `sdk_timeout:set_claw`，取消传播不变。

没有新增读取、重试或停止指令，没有改动 200 ms 夹爪期限、200 ms 停止期限、100 ms VR TTL，或 `stop_unverified` / `stop_incomplete` 锁存。软件无法撤回已经进入 SDK 的夹爪指令。
