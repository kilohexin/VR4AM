# 观察等待窗口的离线负载比较

2026-10-09，Asia/Shanghai。接续 [可选观察窗口](bounded-observer-window-2026-10-09.md)。本轮完成比较工具、36 组本机实验和定向回归；没有真机连接或动作，暂不推送。

## 决定

**维持 `observer_wait_s=0.0`，不增加真机启用入口。** 当前人工模型未证明 5 ms 或 20 ms 等待窗口能稳定改善发点连续性，也没有证明故障观察延后可接受。不能据此认定真机没有收益；这批数据不足以支持开启候选。

运动中 `stop_move` 约 613 ms 回复的问题仍未解决，200 ms 规则和 `stop_unverified` 保留。连续 VR 控制和真实 Trigger 抓取尚未验收。

## 方法与边界

新增 `backend/tests/robots/pvat_observer_load_probe.py`，固定使用已有 `FakeLebaiClient` 和假的 client factory，没有地址参数或真实 SDK 工厂入口。控制时钟使用本机 `perf_counter_ns`，安全超时随实际时间推进，没有冻结控制时钟掩盖延迟。

比较 4 种负载 × 3 个窗口预算 × 3 次重复。每组 2 个预热发点、12 个测量发点，以 40 ms 目标周期顺序调用真实 adapter 的 `_send_target`。这涵盖完整运动快照、候选/IK 和 SDK 调用锁，但**没有经过 VR 输入、RobotControl 主循环、pump 的生产者/最新值覆盖队列或真实通信**。固定 IK 返回合法不变的关节位置，不模拟实际关节运动或动力学。

| 模型 | 每次六项状态 RPC 的请求延迟 | IK 请求延迟 | PVAT 请求延迟 |
|---|---:|---:|---:|
| baseline | 0 ms | 0 ms | 0 ms |
| moderate | 3 ms | 6 ms | 2 ms |
| read_heavy | 7 ms | 3 ms | 2 ms |
| ik_heavy | 1 ms | 25 ms | 2 ms |

延迟通过 `asyncio.sleep` 注入，包含本机事件循环及 Windows 定时偏差，**不是控制器延迟的拟合**。记录回调只将事件追加到内存，不加入磁盘延迟；真实日志后台写入成本不在此模型内。

观察任务执行完整 `get_state`，每次完成后再等待 40 ms，属于随完成时间变化的负载，并非固定 25 Hz 的观察请求。因此同时报告观察次数。统计只选请求开始于测量阶段的观察，允许该读取在阶段结束后完成；预热阶段发点和观察不计入，尾段没有新观察请求计入。

发点间隔为假 SDK `move_pvat` 的相邻**进入**时刻，不是返回时刻、TCP 发包或控制器接收时刻。SDK 异常可能已有一次进入，只有无采样/观察/收尾错误、完整采样且存在间隔和观察样本的组才能参与比较；失败不重试。窗口耗时为独立 QPC 诊断，缺失值保留 null。

预算顺序按重复轮次轮换，减少固定顺序影响。没有隔离整台电脑的其它工作；实验期间有终端读取和短回归运行。3 次重复是探索性样本，不提供因果效果或置信区间，也不能建立现场故障观察期限。

## 结果

36 组均完整，采样/观察/收尾错误均为空。每行合并 3 组：36 个测量 SDK 进入、33 个相邻间隔。p95 使用 nearest-rank；`>80 ms` 严格不含等于 80 ms。80 ms 是现有 PVAT 时域的风险比较线，在假 SDK 中并不触发真实自动减速。

| 模型 | 窗口预算 | 间隔中位/p95（ms） | >80 ms | 观察次数 | 观察完成 p95（ms） | 窗口实测最大（ms） |
|---|---:|---:|---:|---:|---:|---:|
| baseline | 0 ms | 44.703 / 48.006 | 0/33 | 37 | 1.120 | — |
| baseline | 5 ms | 45.572 / 47.275 | 0/33 | 36 | 1.119 | 0.004 |
| baseline | 20 ms | 32.847 / 48.382 | 0/33 | 36 | 1.283 | 0.004 |
| moderate | 0 ms | 294.287 / 297.215 | 33/33 | 69 | 157.031 | — |
| moderate | 5 ms | 294.757 / 297.192 | 33/33 | 70 | 157.276 | 16.577 |
| moderate | 20 ms | 294.267 / 297.285 | 33/33 | 71 | 157.190 | 19.202 |
| read_heavy | 0 ms | 293.957 / 296.968 | 33/33 | 71 | 157.197 | — |
| read_heavy | 5 ms | 293.976 / 296.727 | 33/33 | 69 | 156.842 | 19.469 |
| read_heavy | 20 ms | 294.524 / 298.557 | 33/33 | 71 | 157.306 | 30.365 |
| ik_heavy | 0 ms | 310.295 / 314.827 | 33/33 | 72 | 157.330 | — |
| ik_heavy | 5 ms | 310.263 / 312.071 | 33/33 | 72 | 156.795 | 19.591 |
| ik_heavy | 20 ms | 309.170 / 312.935 | 33/33 | 72 | 157.245 | 29.204 |

非零负载的所有预算均为 33/33 间隔超过 80 ms；窗口未消除这项风险。baseline 中位数变化同时伴随 p95/最大值波动，不能仅选中位数宣称收益。实际观察次数不完全相同，观察 p95 接近也不能证明相同故障发现延迟。

### 定时偏差的独立校准

比较结束后，另做每种时长 12 次纯 `asyncio.sleep` 测量，不与 benchmark 同时运行：

| 请求等待（ms） | 本机实测中位（ms） |
|---:|---:|
| 1 | 15.665 |
| 2 | 15.579 |
| 3 | 15.650 |
| 6 | 15.381 |
| 7 | 15.533 |
| 25 | 31.232 |
| 40 | 46.871 |

因此请求 1～7 ms 在本次环境里近似同一档，`moderate` 与 `read_heavy` 不能被当成精确不同的真实 RPC 负载。294～310 ms 的人工间隔不能外推成机器人运行速度。

5 ms 窗口实际等待可到约 19.6 ms，20 ms 可到约 30.4 ms，再次说明预算不是实时上界。没有修改系统定时设置或用忙等待绕过事件循环。

## 验证与审查

最终 7 个定向文件 **157 passed，6.94 秒，退出 0**：load probe、窗口单元与 adapter 集成、PVAT 生命周期、延迟注入、adapter control 和停止事务。没有后端全集。

新增用例覆盖空统计/严格 >80 ms、完整假 SDK 采样、观察失败拒绝比较、只有一次发点没有间隔、SDK 发送失败只执行一次，以及无效参数在 client 创建前拒绝。独立静态审查指出单发点准入的 P2，先用回归复现 `comparison_eligible=True`，再要求非空间隔修正。首次 SDK 失败测试错误地期待原始异常文本，已改为 adapter 既有的 `sdk_call_failed:move_pvat` 错误，不改生产异常处理。

36 组测量发生在单发点准入修正前；每组 12 个发点均有 11 个间隔，因此该边界修正不改变本批组的准入或计时数据。

修正后的独立复核未发现新增 P0–P2，并用 JSON 重新计算确认各组汇总一致；审查未运行 SDK、probe 或测试。
