## 11月3日：PVT与PVAT同条件对照及执行器分工

按用户提出的网页/VR分工，选定开发方向为：网页准备位及关节目标用movej，XYZ直线按钮/摇杆仍用movel；VR连续输入优先接控制器侧PVT候选。PVT仍接收关节位置、速度、时长，由控制器估算加速度，VR笛卡尔输入仍需逆解和连续轨迹生成；不能仅改函数名称就完成接线。两种入口共用控制权，切换须结束原执行器。当前产品VR尚未切换。

独立探针新增`--pvt --phase-clock`，只调用Lua SDK `lebai:move_pvt`，与PVAT使用相同40ms连续参考区间和名义120ms提前量；保留单关节0.01rad/2秒界限、异常收尾。补充实际采样时刻、加速度、中段近零速计数，并要求完整参考终点误差≤0.0002rad。12项探针定向回归通过。

官方Docker记录`.tmp/pvt-comparison-20261103/`：PVT完整50点、0.01rad、结束到连续静止确认509ms；主动断流27点、最终0.005746806rad、确认481ms，均无异常stop_move。匹配采样的PVAT完整50点、0.01rad、确认519ms。PVT/PVAT中段各30组样本均无速度小于0.0001rad/s；最大采样加速度分别约0.01421/0.03414rad/s²，但小幅单轴个例不足以证明PVT普遍更平滑。调用最大10～11ms，发送最大40～41ms，静止确认包含200ms连续观察；名义目标与稍后采样的位置差约0.00181rad，不应解释成精确时延或同一时刻的跟踪误差。没有真人VR或真机验收。

结论：PVT在本次条件下可作为VR更简单的轨迹接口，未显示数量级的速度优势。下一项仍是最新VR输入传递、连续多关节轨迹、松手/断流与网页切换接线，现有体验保留已验证路径。原厂依据：https://help.lebai.ltd/sdk/motion.html 。
