# Quest 3 开发与安全操作指南

## 适用范围

本指南适用于 Milestone 1 的纯 VR LM3 仿真。浏览器页面只连接本机 FastAPI 仿真后端，从不连接 LM3 IP，不导入 Lebai SDK，也不产生真实机械臂动作。

Milestone 1 不是 MR/passthrough 应用，不采集相机画面，不录制数据集，不包含 Cannon-es 或物体抓取物理。相机和时间同步消息接口仍作为后续扩展点保留，但本阶段没有主动相机采集或数据集写入。

## 准备条件

- Quest Browser 使用 WebXR 本身**不需要**开启 Quest Developer Mode。
- PC 与 Quest 使用同一 WLAN；路由器必须关闭客户端隔离、AP isolation 或访客网络设备隔离。
- 仅可选的 USB ADB 反向转发流程需要 Developer Mode、ADB 和已授权的 USB 调试。
- 后端必须保持 `127.0.0.1:8000` 回环监听；局域网只开放 Vite 的 5173。

## 同一 WLAN 启动

### 1. 获取 PC 的局域网 IPv4

在 PowerShell 中运行：

```powershell
ipconfig
```

找到与 Quest 位于同一 WLAN 的活动网卡，记录其 IPv4 地址。不要使用 `127.0.0.1`、VPN 地址或已断开网卡的地址。下文以 `<PC-LAN-IP>` 表示该地址。

### 2. 启动回环后端

首次安装步骤见仓库根目录的 [README](../README.md)。安装后，从仓库根目录运行：

```powershell
.\.venv\Scripts\Activate.ps1
Set-Location .\backend
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

在 PC 上打开 `http://127.0.0.1:8000/health`，确认响应报告 `SIMULATOR` 且 `real_robot_enabled` 为 `false`。

### 3. 启动 Vite HTTPS

在另一个仓库根目录终端中运行：

```powershell
Set-Location .\web
npm.cmd run dev
```

Vite 监听 `0.0.0.0:5173`。如果 Windows 防火墙询问，只允许 TCP 5173 用于受信任的专用网络；不要放开后端 8000。

### 4. 在 Quest Browser 打开页面

1. 打开 `https://<PC-LAN-IP>:5173`。
2. 首次访问时，Vite `basicSsl` 自签名证书会触发浏览器警告；核对地址确为自己的开发 PC 后，选择继续访问。
3. 等待页面显示连接成功和 `SIMULATOR`。
4. 选择“进入 VR”，同意浏览器所需的沉浸式 VR 权限。

HTTPS 页面会建立同源 `wss://<PC-LAN-IP>:5173/ws/v1/teleop`。Vite 再把 `/ws` 代理至 PC 回环的 `ws://127.0.0.1:8000`；Quest 不直接连接 8000。

## 可选：USB ADB 反向转发

此流程不是 WebXR 或日常同 WLAN 开发的前置条件。仅在已启用 Developer Mode、Quest 已通过 USB 连接并在头显内授权“USB 调试”时使用。

在安装了 Android platform-tools 的 PC 上运行：

```powershell
adb devices
adb reverse tcp:5173 tcp:5173
adb reverse --list
```

设备状态必须是 `device`，不能是 `unauthorized`。后端和 Vite 仍按本指南启动，然后在 Quest Browser 尝试打开：

```text
https://127.0.0.1:5173
```

仍需处理 `basicSsl` 的证书警告。只反向转发 5173；同源 WSS/Vite 代理会继续把 8000 保留在 PC 回环。USB 连接必须保持，且 Quest OS/Browser 对本地证书和 WebXR 安全上下文的处理可能随版本变化；若此路径不可用，应回到上述同一 WLAN 流程，不要改为暴露明文 8000。

测试结束后移除转发：

```powershell
adb reverse --remove tcp:5173
```

## 右手柄映射

仅使用原厂 Meta Quest 3 Touch Plus **右手柄**发送机械臂遥操作命令。左手柄只调整 VR 中工作台的观察位置，不向后端发送机械臂目标。

> **仅限模拟器：**以下 `1:1` 映射、速度限制和 Home 行为不会启用 Lebai SDK、连接真机 IP 或向真实 LM3 发出命令。

| 输入 | 行为 |
| --- | --- |
| A | 显式发送一次解锁/使能请求 |
| B | 运动或已解锁时立即停止；停止且 Grip 松开后再次按下则返回 Home；可恢复故障时复位并返回 Home。停止优先于同一帧 A |
| Grip | 运动离合；按下时从当前实际手柄/TCP 位姿建立相对锚点，松开时停止运动；重新按下不会跳变 |
| Trigger | 归一化 `0..1` 夹爪闭合量 |

系统只对识别到的 `meta-quest-touch*` 或 `oculus-touch*` profile 使用 A=`buttons[4]`、B=`buttons[5]`。如果 profile 未识别、按钮数量不足、右手柄或 gamepad 数据缺失，系统保持锁定，并在 VR 中显示“手柄不受支持 / 当前配置不支持 A/B 安全控制”；它不会猜测其他按钮映射。

### 跟手映射与模拟器限制

按下 Grip 的瞬间，系统同时记录当前实际手柄位姿和实际 TCP 位姿。持续按住时，手柄相对锚点的世界空间平移默认按 `1:1` 映射到 TCP，手柄的 roll、pitch、yaw 固定按 `1:1` 映射到夹爪姿态。因此手柄移动约 `10 cm`，TCP 目标也移动约 `10 cm`。松开 Grip 会停止运动；将手臂移回舒适位置后重新按住，即可无跳变地从当前实际 TCP 重新锚定并继续覆盖工作空间。平移比例可在启动前设为另一个固定正数，但运行中不切换，姿态始终为 `1:1`，也不使用非线性比例。

当前控制/仿真频率和状态回传频率均为 `50 Hz`。模拟器限制如下：

| 参数 | 数值 |
| --- | ---: |
| TCP 最大线速度 | `0.30 m/s` |
| TCP 最大线加速度 | `1.2 m/s²` |
| TCP 最大角速度 | `1.5 rad/s` |
| TCP 最大角加速度 | `4.0 rad/s²` |
| 关节最大速度 | `1.5 rad/s` |
| 关节最大加速度 | `4.0 rad/s²` |
| Home 关节速度 | `0.5 rad/s` |

这些参数只为当前浏览器模拟器的跟手体验服务；未来真机接入必须重新评估并使用独立的保守限制。

## 安全操作顺序

1. 确认页面已连接 `SIMULATOR` 后进入 VR。进入 VR 会立即走本地停止路径并自动回到锁定状态。
2. 完全松开 Grip、A 和 B，让系统先观察到各按钮的松开状态。
3. 保持 Grip 松开，短按一次 A。
4. 等待世界空间中文状态牌从“解锁中”变为后端确认的“已解锁”。没有确认时不得移动。
5. 按住 Grip 建立当前手柄与仿真 TCP 的相对锚点，然后缓慢移动或转动右手柄。
6. 松开 Grip；运动必须停止。再次按住 Grip 会在当前位姿建立新锚点，不应跳变。
7. 在运动或已解锁状态按一次 B，立即停止并解除使能。
8. 保持 Grip 松开，再按一次 B，请求低速返回标准 Home。Home 完成后仍保持锁定；再次移动前必须重新松开 Grip/A/B、按 A，并等待“已解锁”确认。

### 首次松开门闩

A 和 B 都使用“先观察到松开、再接受按下上升沿”的门闩。新 XR 会话、追踪丢失或恢复边界会重置门闩；恢复时持续按住的 A/B 不会触发命令，必须先松开再按。系统没有自动解锁或恢复后自动使能路径。

### 世界空间状态牌

VR 中的中文状态牌位于视野左上方，显示未解锁、解锁中、已解锁、运动中、已停止、Home 中、故障/失联或手柄不受支持，并固定提示 `A 解锁 · B 停止/回 Home · Grip 移动 · Trigger 夹爪`。状态判断同时依赖后端确认，不应仅凭手柄按键推测已解锁。进入 Quest 后应确认 HUD 足够高且不遮挡夹爪、方块或主要操作区域。

### 标准 Home 与 B 键顺序

标准 Home 姿态为两个夹爪左右排列、双目摄像头位于夹爪上方。B 的第一次操作在所有运动或已解锁状态都只负责立即停止，不能直接启动 Home；停止并确认 Grip 松开后，后续一次 B 才请求 Home。Home 执行“确认停止—返回 Home—确认稳定”，完成后保持 `DISARMED`，绝不会自动解锁。

可恢复硬故障时，先松开 Grip，再按 B 执行故障复位并返回 Home。Home 或故障复位进行中会忽略重复请求；若 Home 失败，系统继续停止和锁定，不得继续移动。

## 中断与恢复

以下任一事件都必须立即触发本地停止/解除使能并锁定：

- Quest XR 会话的可见性进入 `hidden` 或 `visible-blurred`；
- 右手柄/位姿追踪丢失；
- WebSocket 关闭、断开或重连；
- 页面刷新、关闭或卸载；
- XR 会话结束、退出 VR 或清理。

恢复连接、追踪或可见性后，不会恢复先前的使能状态。先确认 Grip、A、B 全部松开，再按一次 A，并等待状态牌重新确认“已解锁”；随后才能按 Grip 移动。若状态牌仍显示故障/失联或不支持，保持 Grip 松开并停止操作。

桌面模式另有 `window blur` 输入复位，用于清除桌面 Grip/Trigger；它不是一项独立的 Quest XR 真机事件。Quest 真机验收以 XR 会话报告的 `hidden` / `visible-blurred` 为准。

## Quest 人工验收流程

1. 关闭 PC 端控制页面，只保留 Quest 控制连接，刷新 Quest 页面并进入 VR。
2. 解锁后按住 Grip；手柄前后、左右、上下各移动约 `10 cm`，确认 TCP 同方向移动约 `10 cm`，没有慢动作式累积。
3. 保持 Grip 按住，分别做 roll、pitch、yaw，确认夹爪姿态按 `1:1` 跟随；松开并重新按住 Grip，确认目标无跳变。
4. 在运动或已解锁状态按一次 B，确认机械臂只停止；Grip 松开后再按一次 B，确认机械臂返回 Home。
5. 确认 Home 为左右夹爪、双目摄像头在上，并且 Home 完成后仍需重新按 A 解锁。
6. 确认 HUD 位于视野左上方、不遮挡主要操作区域，并完整显示 A、B、Grip、Trigger 的用途。

### 方块抓取、堆叠与自碰撞验收

- 五个彩色方块均应可抓取；Trigger 闭合时只选择夹爪中心捕获范围内最近的方块。
- 方块被抓取后应保持 `60 mm` 尺寸，不得缩小、消失或跟随错误的夹爪节点。
- 松开 Trigger 后，方块可放回桌面或另一个方块顶部；静止方块不得互相穿透，也不得穿入桌面。
- 将机械臂折向自身时，应在模型发生可见穿模前停止，并以琥珀色显示“机械臂接近自碰撞边界，请将手柄退回”；手柄退回安全方向后应自动恢复，无需复位。

上述方块交互采用确定性运动学放置，不模拟重力、摩擦、碰撞反弹或携带过程中的连续物理。当前自碰撞限制也只用于浏览器模拟器，不能视为真机碰撞保护。
