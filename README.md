最新操纵目标是[相对位姿跟随](docs/vr-pose-follow-direction-2026-11-03.md)：Grip对齐后，手柄朝向目标1:1、平移2:1，手停则目标固定。完整手柄位姿→邮箱→原厂IK/PVAT已接入可选`--pose-follow-vr`模式；独立实例上的产品WebSocket合成输入通过超过40秒持Grip、三轴、两种朝向、并行X/Y渐进夹爪、松手/重握、固定边界及运动中直接断连，共631点。它仍是有界候选，尚无真人头显舒适度、大幅70°运动或真机验收。默认启动器继续使用下面的速度杆模式，不自动切换。

位姿候选已扩展为每次最多300秒/3750点、相对最初Grip零点各轴±100mm的固定目标框，关节使用固定绝对软限位，不再被旧20mm/0.07rad诊断范围截断。初版参考速度为0.06rad/s、加速度0.15rad/s²、jerk 0.5rad/s³，本轮更快参数见顶部。原厂Docker内合成44秒/551点与主机WebSocket长运行均覆盖约30mm实际往返及序号回绕；最大发送间隔仍有91ms，未满足严格小于80ms，不能宣称已无卡顿。修复了旧段完成但结束记录尚未写完时，新Grip误用已撤销零点的问题；只在原运动和清理已知完成后交接，不清除未知锁存。尚需新版真人头显体验；旧扩展记录位于`codex/vr-pose-continuation`分支。

位姿模式到本次平移框边缘会限幅，真正输入过期或故障则退出跟随，需松开按钮后重新按下Grip。新鲜手柄目标逐段求IK，每段最多4mm/0.02rad；计算段仍使用原始输入时间戳，不冒充最终手柄端点的解。新解未就绪时最多400ms保持当前P/V/A参考，过期/未知不会靠迟到输入恢复。这些是计算与控制限制，不是机械精度或物理停止保证。开发预览：`.venv/Scripts/python.exe scripts/run_lmaster_docker.py --pose-follow-vr`；执行需另带`--run`，并先正常关闭已有开发后端，保持单一控制入口。

执行器分工：网页准备位/关节目标用`movej`，网页XYZ直线操作用`movel`；VR使用`--pvat-vr`开启控制器侧PVAT候选，支持三轴组合、名义参考速度10mm/s，手势灵敏度2倍（约4mm偏移启动）。它是持续方向速度杆，不追赶手柄终点。十秒窗口及局部参考段结束后，只有已知完成且Grip输入仍新鲜有效才续接；真实工作区/关节边界、输入过期或故障仍暂停，交接可能短暂停顿。左手X长按打开夹爪、Y长按闭合，松开保持、同时按下保持；右Trigger不再控制夹爪。Docker网页/VR夹爪目标速率1.2行程/秒（约0.83秒目标全行程，非端到端延迟保证），PVAT模式的本地虚拟夹爪可与机械臂并行；真机并行未开放。仍需真人头显确认长期稳定性。

独立PVAT工具`scripts/docker_pvat_live.py`仍默认预览，执行需先关闭8773/8774。产品候选启动：`.venv/Scripts/python.exe scripts/run_lmaster_docker.py --run --pvat-vr`；定向合成验证：在`web`运行`node scripts/checkDockerPvat.mjs 8773 --disconnect-active`。详见`docs/project-status.md`。本机Windows当前保留5173端口，临时VR HTTPS入口以`--port 8443`启动，旧5173链接不可用。

## 原方向模式启动

前提：本机官方 L Master Docker 容器运行，模拟 SDK 端口3030、管理端口3020已映射。启动器核对本机 Docker、官方镜像和端口，不重建容器，不连接真实机器人。

依赖与网页构建已就绪时，Windows可运行`./scripts/start_docker_web.ps1 -Run`，独立后台启动8773后端（PVAT VR候选）与8443 HTTPS代理。省略`-Run`仅预览。重复执行复用健康服务，不自动清除故障或重启已有服务；日志和进程信息在`.tmp/docker-web-services/`。Docker Desktop和官方容器需先运行。头显使用电脑局域网IP的HTTPS8443地址，电脑使用HTTP8773。

从仓库根目录执行（Python 3.11+、Node.js 22+ / npm）：

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -e "./backend[dev,real]"
Set-Location web
npm ci
npm run build
Set-Location ..
.venv/Scripts/python.exe scripts/run_lmaster_docker.py
.venv/Scripts/python.exe scripts/run_lmaster_docker.py --run
```

第一条启动器命令只预览，带 `--run` 才启动。打开 [Docker 控制台](http://127.0.0.1:8773/)。仅保留一个控制页面，PC 与头显轮流使用。

连续平移候选可加 `--blended-translation` 启动，默认关闭。它将网页和VR平移接入4mm直线续接、发送时最多8mm计算前瞻，松手不追加、反向先收尾；俯仰/自转仍为原分步模式。11月2日两轮合成XR整链通过，覆盖XY双向、升降、俯仰、自转、虚拟夹爪、跟踪丢失、重新准备和断连；第二轮另通过约16.8秒/12步长按。此前输入过期未复现但根因尚未确认，仍需操作者体验。不要将此选项用于真机，也不要把计算前瞻当成物理停止距离保证。

另加 `--blended-rotation` 开启统一平移/俯仰/自转续接（自动包含连续平移）。11月2日更新后，混合动作也使用同一个有界 movel 执行器，不再退回逐步停稳的 movej。按位置和角度共同归一化，每段平移不超过4mm、旋转不超过1°，计算前瞻不超过8mm/2°、同时最多两个目标；混合时各分量小于纯轴步长。方向明显变化仍先收尾，松手完成已发送短段。Docker中输入中断100ms会停止追加、自然收尾并提示松开后重新按住，迟到的持按不会自行恢复；反馈/未知结果故障仍锁存。已通过混合续接、输入中断、Grip中Trigger及完整合成XR链，真人流畅度仍需体验；不承诺恒速、即时停止或真实制动效果。

Docker PVAT VR候选支持**平移＋俯仰＋工具自转**。Grip捕获手柄位置与姿态中心；约4mm偏移开始持续平移，回中心约2mm内停止续发。手腕相对中心约3°开始俯仰/自转，回到约1.5°内停止，允许与平移组合；松Grip清除中心。俯仰抬头方向沿用网页负工具局部X，自转绕工具局部Z，名义角速度0.04rad/s并受关节速度缩放。左X/Y长按渐进夹爪，Trigger不再映射。当前转腕已通过合成Docker验证，真人方向与舒适度仍需确认。未加`--pvat-vr`时保留原平移候选。官方仿真内部服务出现过atomic_log 64项数组越界panic，长期稳定性未解决，不能直接迁移到真机；见`docs/real-control-readiness-2026-11-03.md`。

启动时还会将已核对的本机模拟器速度倍率设为100%并读回确认，避免原厂界面留下10%倍率导致动作超时。不要同时在原厂界面发控制指令或改速度倍率。

已核对的本机原厂模拟器处于 `STOP` 或冷启动 `ROBOT_ON` 时，入口调用一次 `start_sys` 并等待 `IDLE`。`PAUSED`、`MOVING`、故障等状态不会自动恢复或复位；这条启动规则只适用于 Docker。

`real` 是原厂 SDK 依赖组的历史名称；安装库本身不连接设备，Docker入口始终使用模拟端口。

1. 确认页面显示 **原厂 Docker 仿真 · LEBAI_DOCKER**、连接正常。
2. 点击“解锁仿真”，再独立点击“进入准备姿态”；解锁本身不运动。
3. 到位后持按摇杆、升降或俯仰。平移每步8 mm，俯仰/自转每步1.5°。松开不追加目标，已发送的当前小步自然完成；规划期间松手可能取消尚未发出的目标。
4. 长按夹爪打开/闭合，松开保持目标开口。Docker夹爪为本地虚拟实现，无接触物理。
5. 停止或跟踪丢失撤销控制。可恢复且无未知结果时重新解锁、准备；故障/未知结果保留，不自动重连清除。

Docker关节速度上限 **0.6 rad/s**、TCP平移上限 **150 mm/s**，实际每步由路径计算选择速度，短距离也可能达不到上限。速度上限不是机械臂分辨率。指令关节加速度仍为0.2 rad/s²，工具角度相对准备位限制为90°，工作区和有限目标规则仍生效；真机默认2mm/0.5°及速度参数未修改。

## 头显控制 Docker

后端保持运行，在另一个终端执行：

```powershell
Set-Location web
npm run docker:vr -- --port 8443
```

头显与电脑处于同一可信局域网，打开 `https://<电脑当前局域网IP>:8443/`。此专用HTTPS入口将页面和WebSocket固定代理到 **8773**；不要用旧版 `npm run dev` 的8000后端替代。

首次自签名证书提示需使用者处理，头显须支持WebXR、连接手柄。按需允许专用网络TCP8443，不暴露公网；Python后端仍只监听回环。先关闭PC控制页，再在头显进入VR。

- A第一次按下解锁；松开并收到确认后，再按A准备。
- 右Grip控制平移、工具俯仰及局部轴自转；松开停止续发。
- 左X长按打开、Y长按闭合夹爪，松开保持；右Trigger不控制夹爪。
- B停止；有限位置入口不开放Home。

合成XR验证只能覆盖软件路径；真实佩戴、按键、方向和舒适度需用户体验。Docker模式已开放工具自转。

## 操作者体验清单

先完成网页，再关闭网页控制标签、切换到头显。检查以下四组操作即可，不必逐个按钮向开发者确认：

1. **解锁与准备**：第一次解锁后显示“已解锁，等待准备”，机械臂不移动；独立准备完成后操纵可用。
2. **移动与夹爪**：摇杆前后左右、上升下降、抬头低头及自转；长按和松开后不应反复要求解锁。夹爪长按渐变、松开保持；鼠标移到3D画面内用滚轮缩放、左键拖动转视角，观察夹指开合。松手时已发送的小步允许完成，规划阶段未发送的目标取消。
3. **连续操作与重握**：网页换方向；VR先松开Grip，移开手，再握住且保持手不动，机械臂不应跳向旧目标。随后移动手或俯仰再继续跟随。
4. **停止与恢复使用**：B/停止撤权；无故障时重新解锁和准备。退出控制页后再打开，仍须重新解锁；跟踪丢失后不能自动恢复旧手势。

反馈只需说明卡在哪一步、页面提示、方向是否符合直觉，以及头显是否感到迟滞或不适。不要把故障通过刷新掩盖。网页/合成XR通过后仍需真人头显体验；真机的夹爪、负载、反馈精度与制动另做现场验收，不承诺一次通过。

开发者可关闭所有控制页，在Docker后端运行时从`web`目录执行`npm run test:docker-xr`：它先检查Docker身份，再通过产品输入模块验证平面连续/反向、升降、俯仰、自转、模拟夹爪、跟踪丢失、重新准备和断连。可用`npm run test:docker-xr -- 8774`指定另一个本机测试端口；不接受远程主机。此命令会驱动虚拟机械臂，并非只读。
